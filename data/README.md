# Каталог и источники данных

Рабочий каталог — **`verified-hotels.json`**, значение `DATA_PATH` по умолчанию. Его политика `evidencePolicy: "verified-only"` отделяет официальные и географические свидетельства от демонстраций. В нём 96 объектов, 38 реальных категорий у 6 отелей, 17 положительных family-фактов. У 90 объектов сохранена запись «Категория номера не подтверждена» с `capacity: null`; это не реальная категория.

Источники категорий: [verified-rooms-research.json](verified-rooms-research.json) и [verified-access-research.json](verified-access-research.json). В них исследованы 8 отелей; для L7 Haeundae и Toyoko Inn Haeundae No.2 достаточных сведений для импорта категорий не найдено. `npm run data:verify` объединяет эти исследования с географией `demo.json`. `npm run data:prepare` последовательно пересобирает географическую основу и проверенный каталог. Повторная сборка не обновляет дату проверки сайтов. [Подробный контракт, покрытие и ограничения](../docs/VERIFIED_DATA.md).

`area-assessments.json` хранит текущие показатели воздуха, почасовой прогноз CAMS и официальные районные сведения для 96 объектов. Прогноз обновляется через `npm run area:assess`; срок свежести — 6 часов. `noise-context.json` строится через `npm run noise:assess` из реальных дорог OSM и отдельных подтверждённых событий `noise-events.json`. Датированных наблюдений движения на выбранные даты нет; исторические профили KTDB сохранены отдельно. Радиусы влияния событий — явно обозначенные допущения, календарь неполон. Методики: [воздух и безопасность](../docs/AREA_ASSESSMENT.md), [внешний шум](../docs/NOISE.md), [историческое движение](../docs/TRAFFIC.md).

`osm-busan-haeundae-snapshot.json` содержит 1 773 объекта ограниченной выгрузки OpenStreetMap для района Хэундэ в Пусане: bbox `[129.145, 35.150, 129.180, 35.175]` (запад, юг, восток, север). `demo.json` сохраняется как географическая основа и архив демонстрационного примера; первый этап `npm run data:prepare` пересобирает этот файл. Он содержит 96 именованных объектов размещения: 42 `hotel`, 42 `motel`, 6 `hostel`, 4 `guest_house`, 2 `apartment`. Тип хранится в `lodgingType`. Значение региона API — `Пусан`.

У 95 объектов есть приближённый маршрут к Haeundae Beach длиной 36–1355 м по графу. У Paradise Hotel Busan (`node-4199814292`) сохранён `route: null`, факта `beach_walk` нет. Неподтверждённые, нулевые или превышающие 2500 м маршруты не превращаются в расстояние до пляжа; сам объект остаётся в каталоге. В архивном `demo.json` сохранены геометрия, факторы шума и явно помеченные демонстрационные категории: 95 географических и 448 демонстрационных фактов. Рабочая сборка забирает только реальные `beach_walk` из этой основы; вымышленные номера и факты не переносятся. В `verified-hotels.json` добавлены 95 частичных `step_free_route` со значением `null`: отсутствие отмеченных лестниц не гарантирует проходимость всего пути.

`traffic-ktdb-2024.json` содержит 10 исторических будничных профилей KTDB с 184 часовыми подсчётами. Исходный ответ охватывает 86 дорожных участков; у 76 подсчёты отсутствуют. Файлы `.raw.geojson` и `.provenance.json` сохраняют исходный ответ, точный запрос, дату получения и хеш. Данные получены без ключа через официальный View-T. `npm run traffic:fetch` проверяет и использует кеш; `npm run traffic:fetch -- --refresh` делает новый запрос. Java читает путь `TRAFFIC_DATA_PATH`, по умолчанию `data/traffic-ktdb-2024.json`. В пределах 300 м от линий с профилями находятся 72 объекта каталога. Это исторический фон, не текущий трафик. Любой исторический уровень сохраняет неизвестность на даты поездки и не подтверждает обязательное условие тишины.

- Данные карты: © OpenStreetMap contributors, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), [атрибуция OSM](https://www.openstreetmap.org/copyright).
- Источник этого snapshot: официальный [OSM API, map.json по bbox](https://wiki.openstreetmap.org/wiki/API_v0.6#Retrieving_map_data_by_bounding_box:_GET_/api/0.6/map), четыре небольших тайла. Публичные Overpass-инстансы отвечали ошибками и таймаутами при загрузке дорог, поэтому использован разовый ограниченный fallback. Запросы, даты и адрес источника сохранены в `osm-busan-haeundae-api-tile-*.json`. Выгрузка получена 24 октября 2026 года; `sourceDate` — самая ранняя дата получения тайла, а не дата натурной проверки. Ненужные метаданные аккаунтов редакторов удалены из кеша.
- `npm run data:fetch` повторно использует сохранённые четыре API-тайла без сетевых запросов. `npm run data:fetch -- --osm-api` явно выбирает этот способ. Без API-кеша и флага скрипт сначала использует публичные [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API). Для обновления следует переместить соответствующие `osm-busan-haeundae-api-tile-*.json` и `osm-busan-haeundae-part-*.json` из папки данных и загрузить заново. Приложение не обращается к публичным серверам при обычном запуске. Кеш разделён по региону; подготовка отклоняет snapshot другого региона.
- Пляж Haeundae подтверждён также [официальной страницей города Пусан](https://www.busan.go.kr/eng/beaches/1325815). Названия отелей и пляжа берутся из OSM, при наличии — из `name:ru` или `name:en`, иначе сохраняется исходное корейское название. Их текущая работа отдельно не проверялась.
- Маршрут начинается с ближайшего узла графа к точке отеля и заканчивается узлом в пределах 35 м от границы нанесённого пляжа. Проходимость этих соединительных участков не проверена, а их длина не включена в длину графового маршрута. Расстояние первой привязки сохраняется отдельно.
- Доступные проходы строятся по общим идентификаторам узлов OSM, а не по визуальным пересечениям линий. Учитываются известные ограничения доступа, закрытые барьеры, ступени и пешеходные односторонние участки. Граф ограничен выгрузкой и может быть неполон.
- Обход исключает отмеченные ступени и ведёт к тому же пляжу. Отсутствие отмеченных ступеней не доказывает доступность с коляской; исходное свидетельство остаётся неизвестным. Бинарная политика отдельно принимает отсутствие отмеченных лестниц или обход как явно обозначенную оценку.
- В текущем наборе кратчайшие маршруты не содержат отмеченных ступеней. Демонстрационные препятствия у входа остаются только в архивном примере и помечены `demo: true`; рабочий каталог их не импортирует. Лестницы в реальную геометрию ради демонстрации не добавлялись.
- Три соседних береговых OSM way объединены в одну линию по совпадающим конечным точкам. Это реальная геометрия побережья; заполнение морской области выполняет интерфейс.
- Расстояния до дороги или железной дороги рассчитываются до сегментов их геометрии. Эти объекты — факторы возможного шума, а не измерения шума внутри номера.
- Названия и расположение отелей реальные, но действующая работа отеля не проверена. Комнаты и ответы с `demo: true` вымышлены и не являются сведениями реальных отельеров; рабочий режим их игнорирует. Официальные категории имеют отдельные ID с `-real-`, источник и дату проверки. Наличие, цены и бронирование не проверяются.
- Повторная подготовка данных не обновляет срок актуальности фактов. Дата базы OSM также не является датой натурной проверки объекта.

Бинарные решения не записываются в исходные снимки: null/unknown/stale и реальные значения сохраняются. Недостаток доказательств не даёт положительного допуска. Вместимость и условия категории не выводятся из типа размещения. [Подробности](../docs/VERIFIED_DATA.md).

## Сочи

`sochi/verified-hotels.json` — 61 именованная OSM-запись центральной прибрежной части Сочи; `sochi/preserved-manifest.json` и `sochi/raw/` сохраняют источник 24 октября 2026 года. `sochi/quality.json` содержит исключения, возможные дубли и неизвестные поля. Сборка: `npm run data:prepare:sochi`. [Описание и ограничения](../docs/SOCHI_DATA.md). `official-review.json` — отдельные заявления 16 гостиниц с собственных сайтов, не подтверждение условий комнаты.

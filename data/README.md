# Данные демонстрации

`osm-busan-haeundae-snapshot.json` содержит реальную ограниченную выгрузку OpenStreetMap для района Хэундэ в Пусане: bbox `[129.145, 35.150, 129.180, 35.175]` (запад, юг, восток, север). `demo.json` строится командой `npm run data:prepare` и содержит 24 отеля, геометрию карты, рассчитанные маршруты к Haeundae Beach, факторы внешнего шума и отдельно помеченные демонстрационные категории номеров. Значение региона API — `Пусан`.

- Данные карты: © OpenStreetMap contributors, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), [атрибуция OSM](https://www.openstreetmap.org/copyright).
- Источник этого snapshot: официальный [OSM API, map.json по bbox](https://wiki.openstreetmap.org/wiki/API_v0.6#Retrieving_map_data_by_bounding_box:_GET_/api/0.6/map), четыре небольших тайла. Публичные Overpass-инстансы отвечали ошибками и таймаутами при загрузке дорог, поэтому использован разовый ограниченный fallback. Запросы, даты и адрес источника сохранены в `osm-busan-haeundae-api-tile-*.json`. Выгрузка получена 24 октября 2026 года; `sourceDate` — самая ранняя дата получения тайла, а не дата натурной проверки. Ненужные метаданные аккаунтов редакторов удалены из кеша.
- `npm run data:fetch` повторно использует сохранённые четыре API-тайла без сетевых запросов. `npm run data:fetch -- --osm-api` явно выбирает этот способ. Без API-кеша и флага скрипт сначала использует публичные [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API). Для обновления следует переместить соответствующие `osm-busan-haeundae-api-tile-*.json` и `osm-busan-haeundae-part-*.json` из папки данных и загрузить заново. Приложение не обращается к публичным серверам при обычном запуске. Кеш разделён по региону; подготовка отклоняет snapshot другого региона.
- Пляж Haeundae подтверждён также [официальной страницей города Пусан](https://www.busan.go.kr/eng/beaches/1325815). Названия отелей и пляжа берутся из OSM, при наличии — из `name:ru` или `name:en`, иначе сохраняется исходное корейское название. Их текущая работа отдельно не проверялась.
- Маршрут начинается с ближайшего узла графа к точке отеля и заканчивается узлом в пределах 35 м от границы нанесённого пляжа. Проходимость этих соединительных участков не проверена, а их длина не включена в длину графового маршрута. Расстояние первой привязки сохраняется отдельно.
- Доступные проходы строятся по общим идентификаторам узлов OSM, а не по визуальным пересечениям линий. Учитываются известные ограничения доступа, закрытые барьеры, ступени и пешеходные односторонние участки. Граф ограничен выгрузкой и может быть неполон.
- Обход исключает отмеченные ступени и ведёт к тому же пляжу. Отсутствие отмеченных ступеней не доказывает доступность с коляской; этот пользовательский критерий остаётся неизвестным.
- В текущем наборе кратчайшие маршруты не содержат отмеченных ступеней. Демонстрационные препятствия у входа в номера по-прежнему помечены `demo: true`. Лестницы в реальную геометрию ради демонстрации не добавлялись.
- Три соседних береговых OSM way объединены в одну линию по совпадающим конечным точкам. Это реальная геометрия побережья; заполнение морской области выполняет интерфейс.
- Расстояния до дороги или железной дороги рассчитываются до сегментов их геометрии. Эти объекты — факторы возможного шума, а не измерения шума внутри номера.
- Названия и расположение отелей реальные, но действующая работа отеля не проверена. Все комнаты и ответы с `demo: true` вымышлены для демонстрации алгоритма и не являются сведениями реальных отельеров. Наличие, цены и бронирование не проверяются.
- Повторная подготовка данных не обновляет срок актуальности фактов. Дата базы OSM также не является датой натурной проверки объекта.

# Эталоны совместимости с main

85 ответов в `snapshots/` получены 26.10.2026 от отдельной копии действующего
main `e4faa2dbc006a1a785e43059c83d10a5c239f084` с новой пустой SQLite,
актуальными файлами `data/` и отключёнными внешними моделями.

SHA-256 проверенного исходного JAR:
`b04b8752c9745a985ae8847bad6961ddd72f0be692ea1b811b0e83faf19a1c4e`.

Эталоны сняты с прежнего приложения до сравнения со Spring. Обновление отражает
изменения main после начала spring-migration: режим допуска, личные пожелания,
сведения о категориях и новые открытые источники. Ответы Spring не использовались
для генерации эталонов.

```powershell
npm run contract:verify
node scripts/contract.mjs diff --base http://127.0.0.1:8088 --against http://127.0.0.1:8090
```

Для прямого сравнения обе копии должны использовать отдельные тестовые хранилища:
сценарий создаёт вымышленные аккаунты, объявления, фотографии и заявки.
Не направляйте его на пользовательскую или рабочую копию сайта.

`requests.json` задаёт запросы и точечные допустимые отличия. `allowValueChanges`
разрешает только переход строки `SQLite 3` в `PostgreSQL 16` в `health` по пути
`$.database` и в `PostgreSQL` в девяти ответах поиска по пути `$.trace[2].tool`.
После объединения с диалоговым подбором также разрешены девять точных переходов
`$.trace[1].detail`: пояснение теперь содержит число категорий, удовлетворяющих
всем выбранным условиям. Для фиксированных запросов закреплены значения 20, 0
или 1; другой текст или число остаются ошибкой.
Другой движок, перестановка шагов, удаление поля и изменения остальных полей
`trace` остаются ошибками. Эталоны SQLite при этом не переписываются.
Изменчивые UUID и времена нормализуются; добавление новых полей разрешено,
удаление существующих и изменение значений фиксируются. Статические эталоны
зависят от сохранённых источников и их сроков; это проверка API, а не условий в отеле.

`contract:verify` проверяет свободность порта 8089, создаёт уникальную схему
`contract_*` и отдельную папку загрузок, явно включает кабинеты и отключает
лабораторный режим и модели. Файлы каталога и оценок берутся из `data/`, независимо
от пользовательских настроек этих путей в `.env`. После проверки процесс
останавливается; схема и файлы запуска сохраняются для разбора ошибок.
Для отдельного сервера PostgreSQL задайте `DATABASE_URL`, `DATABASE_USER` и
`DATABASE_PASSWORD`; без них используется Compose. Не запускайте параллельно
другие изменяющие данные проверки против той же копии приложения.

новых доказательств и PostgreSQL описаны в [отчёте переноса](../docs/SPRING_MIGRATION_QUALITY.md).

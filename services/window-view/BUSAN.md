# Пусан: пилот Хэундэ

Сцена `busan-haeundae` покрывает круг радиусом 2000 м вокруг Shilla Stay Haeundae
(35.15983896, 129.1586863). Внутри находятся все 24 идентификатора отелей из
каталога основного приложения. Это прибрежная часть Хэундэ, не весь город;
Кваналли и Сондо в эту поставку не входят.

## Использование

Из `services/window-view`:

```powershell
python -m window_view serve
# В другом терминале:
curl.exe http://127.0.0.1:8011/v1/regions
curl.exe -X POST http://127.0.0.1:8011/v1/views/estimate -H "Content-Type: application/json" --data-binary @examples/real-hotel.json
```

При запущенном Java API тот же запрос принимает
`http://127.0.0.1:8080/api/views/estimate`. Сервис Python запускается отдельно;
его адрес задаёт `WINDOW_VIEW_URL` в окружении Java.

Пример использует Shilla Stay, **входной этаж 5**, дату 24 октября 2026 года и
смещение `utc_offset_minutes: 540` (UTC+9). Для другого отеля возьмите `hotel`
из `data/regions.json`, задайте свой этаж и дату. Номер комнаты сам по себе не
задаёт этаж или направление. Без геометрии окна возвращаются восемь условных
направлений на введённом этаже. Это не восемь существующих номеров.

`radius_m` ограничивает поиск относительно отеля, а сохранённая сцена — доступную
территорию. В ответе `room_resolution.evaluated_radius_m` показывает фактический
радиус расчёта. Мост или гора за пределами сцены не считаются отсутствующими:
неисследованные виды остаются неизвестными.

## Состав и происхождение

Снимок получен 24 октября 2026 года через Overpass: **2342 здания/части здания**,
103 точки-цели, включая 48 морских образцов. У 150 зданий есть тег высоты,
у 396 — только интервальная оценка по этажности, у 1796 высота неизвестна.
GLO-90 через Open-Meteo дал 600 образцов поверхности. Это модель с разрешением
около 90 м, не геодезическая съёмка земли и фасадов.

- OSM: [правила высоты](https://wiki.openstreetmap.org/wiki/Key:height),
  [этажность](https://wiki.openstreetmap.org/wiki/Key:building:levels),
  [отметка основания](https://wiki.openstreetmap.org/wiki/Key:ele).
- [Open-Meteo Elevation API](https://open-meteo.com/en/docs/elevation-api):
  Copernicus DEM GLO-90, пакеты до 100 координат.
- [Shilla Stay Standard](https://www.shillahotels.com/en/shillastay/haeundae/accommodation/standard.do):
  варианты категории с городским или морским видом, этажи 3–8. Хранятся как
  `reported` и не превращаются в координаты или вид конкретной комнаты.
- [Официальный план этажей Shilla](https://www.shillahotels.com/en/shillastay/haeundae/introduction/about.do):
  Rooftop Pool & Bar на 18-м этаже. Это `scope: facility`. OSM содержит
  `building:levels=17`; номер террасы на крыше не приравнивается автоматически
  к числу этажей фасада и не подтверждает существование гостевого номера на 18-м.

У каждого источника есть URL, дата получения, доступная дата исходных данных и
метод. Картографический запрос, версии OSM и SHA-256 сохранены в сцене; SHA-256
самого gzip находится в `data/scenes.json`. Тексты и фотографии отелей целиком
не копировались. Каталог экспортирует только реальные OSM ID, имена и координаты;
демонстрационные категории и ответы отельеров из приложения не используются.

## Обнаруженные ограничения

Выгрузка содержит неполные контуры: `geometry_complete=false`. Поэтому она не
подтверждает свободный обзор. Около 77% зданий не имеют ни высоты, ни этажности.
Сведения о расположении окон физических комнат отсутствуют.

При проверке башен обнаружены существенные расхождения OSM `ele` и DSM:
отметка, похожая на высоту самой башни, могла ошибочно становиться её основанием.
Обе версии сохраняются. `ground_elevation_conflict` запрещает уверенный вывод на
основе спорной отметки; отметка не заменяется молча нулём или ближайшим DSM.
Порог расхождения 100 м — консервативный сигнал для уточнения, не оценка точности.
Небольшое расхождение или отсутствие флага не подтверждает правильность данных.

## Воспроизводимость и качество

```powershell
python -m unittest discover -s tests
python verify_busan.py
```

Расширенная проверка выполняет 72 офлайн-запроса: для каждого из 24 отелей пары
`этаж 3 / 20 марта`, `этаж 8 / 21 июня`, `этаж 17 / 21 декабря 2026`.
Проверяются входной этаж, область результата, ссылки на источники, согласованность
статусов и локальная дата солнечных событий UTC+9. Это три пары, не полное
перебирание этажей и дат. Высокие тестовые этажи могут отсутствовать у отеля:
расхождение с картой должно быть явно отражено, а не скрыто.

Машинный отчёт — `data/busan-quality.json`; общие проверки — [QUALITY.md](QUALITY.md).
Число проверенных на месте окон остаётся **0**. Прохождение тестов проверяет
программу и честность обработки пропусков, но не доказывает реальную видимость.

Для явного обновления источников:

```powershell
python -m window_view collect examples/collect-busan.json --output data/open/busan-haeundae.scene.json
python build_examples.py
python verify_busan.py
```

Повторный сбор использует кеш. Чтобы действительно обновить определённый источник,
нужно явно обновить его кеш; перепаковка сама по себе не меняет дату наблюдения.

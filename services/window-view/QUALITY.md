# Проверка качества window-view

Этот отчёт отделяет проверку программы от проверки того, что действительно видно
из конкретного окна. Проверка на месте и сверка с геопривязанными фотографиями
окон не проводились. `clear_in_model` означает отсутствие препятствия в заданной
модели; это не независимое подтверждение реального вида.

## Обязательные границы вывода

- Сведения о категории номера не наследуются физическим номером без доказательства.
  Заявление отеля о виде сохраняется отдельно от геометрического расчёта.
- Неизвестные координаты окна, направление или этаж не восстанавливаются из номера
  комнаты. В таком случае ответ относится к условным сценариям отеля, а не к комнате.
- Высота над землёй не равна абсолютной отметке. Для линии визирования требуется
  согласованная вертикальная система отсчёта; отсутствие данных не считается нулём.
- Неизвестная высота пересечённого здания не считается отсутствием препятствия.
  Если диапазон возможных высот пересекает луч, результат должен остаться неизвестным.
- Одна видимая или скрытая точка не описывает целиком море, парк, фасад или гору.
  Доли относятся только к перечисленным образцам, а не к площади окна.
- Восход и закат рассчитываются для даты и явного смещения UTC. Стандартный
  астрономический момент не совпадает с первым или последним появлением Солнца
  над соседним зданием или горой. Облачность и реальная атмосферная видимость
  не проверяются.

## Независимый численный ориентир

Опубликованный пример [NREL SPA, приложение A.5](https://www.nlr.gov/docs/fy08osti/34302.pdf)
для 17 октября 2003 года, 19:30:30 UTC, широты 39.742476 и долготы −105.1786:
азимут 194.340241°, видимая высота 39.888378°; восход 13:12:43.46 UTC,
закат 18 октября 00:20:19.19 UTC. Для используемого упрощённого расчёта тест
задаёт допуск 0.1° по положению и 3 минуты по событиям. Параметры эталона
включают давление 820 мбар, температуру 11 °C и высоту 1830.14 м; различие
геометрической и преломлённой высоты учитывается допуском. Численный пример
используется для сверки, исходный код SPA в проект не переносился.

Фактические отклонения локального расчёта от этого примера: 0.00235° по азимуту,
0.01631° по высоте, 0.46 секунды по восходу и 89.19 секунды по закату.
Это результат одной контрольной точки, а не общая оценка погрешности.

[NOAA описывает](https://gml.noaa.gov/grad/solcalc/calcdetails.html) зависимость
наблюдаемых событий от атмосферы; текущая страница также предупреждает,
что калькулятор больше не поддерживается. Эти источники задают внешний
ориентир, а не подтверждают точность локальной модели зданий.

## Протокол проверки

1. Сначала модульные примеры геометрии, солнечных событий и нормализации источников.
2. Затем независимые расширенные примеры: углы около севера, границы поля зрения,
   высота и основание препятствия, отверстия в полигонах, разные абсолютные отметки,
   полярные даты, локальная дата при ненулевом UTC-смещении.
3. Затем API: полный номер, неполный номер, отсутствие номера, отдельная категория
   из официального источника, ошибки ввода и недоступность источника.
4. В конце — сохранённый реальный снимок: число объектов и доля известных высот,
   источники, пределы покрытия и отсутствие необоснованных фактов о комнате.

## Результаты

Независимый запуск 24 октября 2026 года:

```powershell
python -X utf8 -m unittest discover -s tests
python -X utf8 -m unittest discover -s tests -p test_expanded.py
```

Полный набор: **151 тестовый метод, 151 прошёл**. В том числе независимый
расширенный набор: **44 метода, 44 прошли**. Внутри методов есть дополнительные
табличные случаи (`subTest`); они не прибавлены к указанному знаменателю.
Сеть и API-ключи для этих запусков не использовались. Реальные снимки были
получены отдельно и сохранены; повторный расчёт работает без сети.

Снимок Батуми вокруг Radisson Blu содержит 2244 контура зданий: высота указана
в OSM у **109/2244** (4.86%), у **1149/2244** используются интервальные оценки
по этажности, у **986/2244** высота неизвестна. В снимке 168 точек-целей и
600 образцов высоты GLO-90. Наличие 600 образцов не означает непрерывную
проверку всего рельефа: разрешение модели около 90 м, а неполнота контуров
обнаружена и отмечена в `completeness.geometry_complete=false`.

Сохранённый запрос для 5-го этажа отеля оценивает 8 условных направлений,
по 39 выбранных точек в каждом. После пересборки нормализатором `osm-normalizer/1.1`
в 312 оценках: 273 точки вне выбранного сектора, 39 результатов `unknown`,
0 результатов `clear_in_model`. Эти числа относятся
к образцам и секторам, не к 312 реальным окнам. Высота этажа в этом запросе
оценочная; геометрия конкретной комнаты не известна. Подтверждённых на месте
комнат: **0**. Непроверенный вид не заменён вымышленным положительным ответом.

## Найденные ошибки и регрессии

Независимая расширенная проверка обнаружила следующие ошибки на искусственных
геометрических примерах; каждый пример сохранён в `tests/test_expanded.py`.
Все пять перечисленных регрессий проходят после исправлений.

| Ошибка | Требуемое поведение |
|---|---|
| Номинальная высота здания перекрывала заданный диапазон высот | Диапазон имеет приоритет; пересечение возможных высот с лучом даёт `unknown` |
| Крыша соседнего здания с известной отметкой земли рассчитывалась на уровне земли | Абсолютная отметка крыши равна отметке основания плюс высота здания |
| Крыша с неизвестной высотой превращалась в известную точку на земле | Высота точки крыши остаётся неизвестной |
| Три проверки высоты окна пропускали тонкое препятствие на промежуточной высоте | Оценочная высота не превращается в подтверждённую видимость всего интервала |
| Три проверки высоты окна могли пропустить узкое вертикальное поле зрения | Вертикальное исключение по трём образцам не доказывает исключения всего интервала |

Также добавлены регрессии для расхождения запрошенного этажа с этажностью на карте,
ограничения солнечного горизонта реальным радиусом сцены, отсутствия строительных
контуров в реальной выгрузке и различия между геометрической высотой центра Солнца
и приближённым лучом для верхнего края диска в момент стандартного восхода.

Внешний численный ориентир проверяет один опубликованный астрономический пример.
Сетка из дат и координат проверяет конечность и диапазон чисел, а не фактическую
точность во всех географических условиях. Все комнаты и здания модульных примеров
имеют искусственные идентификаторы; они не добавляют сведения к реальным отелям.

## Интеграция и ограничения проверки запуска

- 23 существующих теста приложения, проверка TypeScript и Vite production build прошли.
- TypeScript-клиент вызвал Python API по настоящему HTTP: для синтетического западного
  окна на 4-м этаже морская точка `blocked`, на 14-м — `clear_in_model`.
- OpenAPI-документ, CLI-примеры и контрольные суммы упакованных сцен проверены локально.
- Реальный снимок упакован в gzip; контрольные суммы не зависят от преобразования
  окончаний строк Git между Windows и Linux. Добавлены три проверки упаковки.
- Dockerfile подготовлен, но сборка контейнера не запускалась: Docker daemon в этой
  среде недоступен. Проверенный запуск — обычный Python-процесс.
- Основной интерфейс приложения не менялся; для сервера добавлен отдельный клиент.
- Сохранены три коротких опубликованных описания категорий Radisson со статусом
  `reported`. Они не изменяют геометрические ответы и не подтверждают вид номера.

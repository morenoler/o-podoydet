# Вид из окна

Отдельный JSON-микросервис для «О!Подойдёт». Python 3.11+, стандартная библиотека,
без API-ключей и зависимости от основного приложения. **Этаж передаёт вызывающий код.**

Сервис оценивает морские точки, соседние здания, достопримечательности, парки,
водоёмы, вершины и направления восхода/заката. Учитывает азимут окна, горизонтальный
и вертикальный сектор обзора, высоту наблюдателя, контуры/высоты зданий, поднятые
части зданий, отверстия в полигонах, поверхность местности и кривизну Земли.

Это расчёт по ограниченной модели. `clear_in_model` означает свободный луч к
выбранной точке при перечисленных допущениях. Фотографию и подтверждённый вид
из физического номера сервис не обещает: `actual_visibility_confirmed` всегда `false`.

## Запуск

Из этой папки:

```bash
python -m window_view serve
# http://127.0.0.1:8011/health
# http://127.0.0.1:8011/openapi.json
# http://127.0.0.1:8011/v1/scenes
```

API:

```bash
curl -X POST http://127.0.0.1:8011/v1/views/estimate \
  -H "Content-Type: application/json" --data-binary @examples/room.json
```

В PowerShell используйте `curl.exe`. CLI работает без HTTP-сервера:

```bash
python -m window_view evaluate examples/room.json
python -m window_view evaluate examples/room-high-floor.json
python -m window_view evaluate examples/real-hotel.json
```

Первые два примера полностью вымышленные: на низком этаже морская точка закрыта
зданием, на высоком расчётный луч проходит над ним. Третий использует сохранённые
открытые данные Пусана (Хэундэ) и сохраняет неизвестность при неполных источниках.

Пилот покрывает **24 отеля** текущего каталога в Хэундэ, а не весь Пусан.
`GET /v1/regions` возвращает их OSM ID, координаты и настройки `Asia/Seoul` / UTC+9.
Этаж и дату задаёт вызывающий код. Подробности источников и покрытия — в [BUSAN.md](BUSAN.md).

## Запрос

```json
{
  "hotel": {
    "id": "osm:way:627150752",
    "name": "Shilla Stay Haeundae",
    "lat": 35.15983896,
    "lon": 129.1586863
  },
  "floor": 5,
  "date": "2026-10-24",
  "utc_offset_minutes": 540,
  "data_mode": "cached",
  "scene_id": "busan-haeundae"
}
```

- `floor` обязателен. По умолчанию первый этаж — уровень земли. Для нумерации с нуля
  передайте `ground_floor_number: 0`. Номер комнаты никогда не разбирается как этаж.
- Высота глаза: `(floor - ground_floor_number) × floor_height_m + eye_height_m`.
  Высота глаза над полом по умолчанию 1,6 м. Это явное допущение, не замер окна.
- Если высота этажа не передана, используются пригодные `height / building:levels`
  или явно объявленное предположение 3 м. Возвращается диапазон; видимость при
  неопределённой высоте остаётся `unknown`, рядом есть `nominal_status`.
- Для конкретного окна дополнительно передайте `room.id` и `room.window` с
  `lat`, `lon`, `bearing_deg`. Азимут: 0 — север, 90 — восток, 180 — юг, 270 — запад.
  Поля `horizontal_fov_deg`, `vertical_fov_deg`, `pitch_deg` задают сектор и наклон.
  `room.source` хранит URL, короткую цитату и дату получения исходных сведений.
- Присланная геометрия помечается как входные сведения, независимо не проверенные.
  URL источника сохраняется как ссылка; сервис не скачивает произвольные URL.
- Если окно неизвестно, ответ имеет `scope: hotel_floor_scenarios`: восемь направлений
  **на том же входном этаже** от представительной точки отеля. Это сценарии, а не окна
  существующих номеров. Координаты и ID отеля передаёт каталог основного приложения.
- Дата и фиксированный UTC offset относятся к месту поездки на эту дату. Сервис
  не угадывает часовой пояс или переход на летнее время.

Публичные сведения о конкретных комнатах можно добавить в
`data/open/published_views.json`. Нужны точный hotel ID, физический room ID, этаж,
геометрия окна и источник. Сейчас таких проверенных записей нет. Описания категорий
выдаются отдельно в `published_claims` со статусом `reported`; они не задают геометрию.

## Ответ

`assessments[]` содержит наблюдателя, категории вида, отдельные точки и Солнце.
У каждой точки есть расстояние, азимут, угол возвышения, препятствия, неопределённости
и ссылки на `sources[]`.

| Статус точки | Значение |
|---|---|
| `clear_in_model` | Луч свободен в имеющейся модели |
| `blocked` | Луч пересекает моделируемое препятствие |
| `outside_fov` | Точка вне заданного сектора окна |
| `unknown` | Нужных данных недостаточно или есть конфликт |

`categories.sea.visible_in_model: true` означает хотя бы одну свободную морскую
точку в модели. Если все выбранные точки закрыты, вся категория всё равно остаётся
неизвестной: ограниченная выборка не доказывает, что море совсем не видно.
Аналогично крыша соседнего здания представлена отдельной точкой, а не всем фасадом.

Для Солнца возвращаются UTC-время и азимут стандартного восхода/заката. Проверка
препятствий использует приближённый луч верхнего края диска у горизонта с явно
записанным допущением о рефракции. Время первого появления Солнца над соседним
зданием отдельно не вычисляется. Полярный день/ночь возвращают отсутствие событий.

## Открытые источники и сбор

- [OpenStreetMap / Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API): контуры,
  здания и их части, высоты, этажность, береговая линия, точки интереса. ODbL,
  © OpenStreetMap contributors. По [правилам OSM](https://wiki.openstreetmap.org/wiki/Key:height)
  `height` уже включает крышу; добавлять её повторно нельзя. Высоты из этажности —
  диапазон предположений, а не измерение.
- [Береговая линия OSM](https://wiki.openstreetmap.org/wiki/Tag:natural%3Dcoastline): море
  справа по направлению линии. Пляж сам по себе не считается морской поверхностью.
- [Open-Meteo / Copernicus GLO-90](https://open-meteo.com/en/docs/elevation-api): глобальная
  модель поверхности с шагом около 90 м. Это DSM: растительность и застройка могут
  влиять на высоту. Узкие препятствия рельефа не гарантированно обнаруживаются.
  Сохраняется атрибуция; условия использования публичного API отличаются от лицензии данных.
- [NOAA](https://gml.noaa.gov/grad/solcalc/calcdetails.html): опубликованные формулы
  солнечного положения. Погода и реальное наблюдение ими не подтверждаются.

Обычный запуск не обращается к сети. Для нового района:

```bash
python -m window_view collect examples/collect-busan.json --output data/open/busan-haeundae.scene.json
# Или явно разрешить API собирать источники для data_mode=live:
python -m window_view serve --allow-network
```

`collect` — явная сетевая команда. География запроса ограничена радиусом 200–2000 м;
Overpass вызывается последовательно, есть таймауты и ограничения объёма.
Высоты запрашиваются пакетами до 100 точек, максимум 600 точек за оценку.
Неудача источника не заменяется пустой картой. При недоступности высот сохраняется
неизвестность. Кэш `.cache/` хранит исходные ответы, запросы, время и SHA-256;
повторный расчёт не обновляет дату исходных данных. Удалять выбранную запись кэша
для пересбора нужно явно. В репозитории сохранён готовый реальный снимок `.scene.json.gz`
с контрольной суммой; API распаковывает его автоматически. `build_examples.py`
упаковывает `data/open/busan-haeundae.scene.json`, обновляет индекс сцен и переносит
только идентификаторы/координаты отелей из каталога приложения. Батуми сохранён
отдельной регрессионной сценой; основной реальный пример теперь использует Пусан.

Неизвестные высоты и пропущенные контуры препятствуют подтверждению свободного вида.
Существенное расхождение отметки основания OSM и ближайшего DSM сохраняется как
конфликт с обеими версиями; спорная отметка не становится уверенным препятствием.
Собственное здание исключается только при согласованном положении наблюдателя;
его выступы, балконы и другие крылья отдельно не моделируются.
Высота здания применяется к вертикальному объёму его контура; сложная форма крыши
без отдельных размеченных частей не восстанавливается.
За границей района, за стеклом, в облаках или тумане видимость может отличаться. Нет гарантии наличия
номера, возможности размещения на этаже или работы отеля на дату поездки.

## Подключение и проверки

Java-клиент: `backend/src/main/java/ru/opodoydet/WindowViewClient.java`.
Основное приложение принимает `POST /api/views/estimate` с тем же телом запроса
и передаёт его Python-сервису; адрес задаётся `WINDOW_VIEW_URL` (по умолчанию
`http://127.0.0.1:8011`). Python запускается отдельным процессом.
Клиент сохраняет JSON и статусы неизвестности, ограничивает тело и время ответа.
Интерфейс приложения не менялся. ID каталога `way-123` соответствует `osm:way:123`;
готовое сопоставление для 24 отелей есть в `GET /v1/regions`.

```bash
python -m unittest discover -s tests -v
python build_openapi.py
python build_examples.py
python verify_busan.py
docker build -t o-podoydet-window-view .
docker run --rm -p 127.0.0.1:8011:8011 o-podoydet-window-view
```

Контейнер по умолчанию работает офлайн от непривилегированного пользователя.
HTTP-сервер рассчитан на локальный прототип: одна тяжёлая оценка одновременно,
остальные получают `429`. Для общего внешнего доступа нужен шлюз с авторизацией
и ограничениями нагрузки. Результаты проверок и известные ограничения — в `QUALITY.md`.

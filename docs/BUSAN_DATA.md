# Пусан: городской каталог и места рядом

Новый набор `data/busan/verified-hotels.json` содержит **876 объектов размещения**, включая все прежние 96 и 780 новых: 205 отелей, 598 мотелей, 27 гостевых домов, 20 хостелов и 26 апартаментов. Это отмеченные в OpenStreetMap объекты в административной границе Пусана, а не реестр всех действующих гостиниц и не предложение бронирования. Подробные знаменатели и покрытие находятся в `data/busan/quality.json`.

## Источники и география

Граница найдена запросом по `boundary=administrative`, `ISO3166-2=KR-26` и проверена как единственная relation с `admin_level=4`: [Busan, relation 2396450](https://www.openstreetmap.org/relation/2396450). По её Overpass area собраны `tourism=hotel|motel|guest_house|hostel|apartment`. Запрос охватывает административную территорию, включая прибрежные острова; прямоугольник границы нужен только для отображения карты.

Кафе, рестораны, супермаркеты, магазины у дома, аптеки, парки, метро, музеи, торговые центры, пляжи и железнодорожные станции задаются в `data/busan/place-categories.json`. Там же находятся русские/английские выражения и радиусы по умолчанию. Радиусы — продуктовая настройка, а не научная граница понятия «рядом». Точные сочетания тегов применяются при офлайн-подготовке. Например, все станции собираются один раз, затем разделяются на метро и железнодорожные станции.

Городские запросы Overpass для POI завершались ошибками; окончательный слой из **6 527 мест** получен из [датированного регионального PBF Geofabrik](https://download.geofabrik.de/asia/south-korea-261026.osm.pbf). Дата базы в его заголовке: **26 октября 2026, 21:24:46 UTC**; получение завершено 27 октября. SHA-256 и опубликованный поставщиком MD5 проверены. Извлечение охватывает прямоугольник административной границы и может включать места соседних муниципалитетов. Все `bbox` в итоговом наборе и манифестах производного слоя имеют порядок `[west, south, east, north]`; строка запроса Overpass использует свой порядок south/west/north/east. Находящиеся за муниципальной границей кафе тоже могут быть близки к гостинице в Пусане. Сырые гостиничные записи по-прежнему отобраны по точной административной области.

«Центр» означает выбранную ориентирную точку [станции Сомён, node 5782717000](https://www.openstreetmap.org/node/5782717000), а не единственный или геометрический центр Пусана. [Официальный туристический портал Visit Busan описывает Сомён как центральный район](https://visitbusan.net/en/index.do?menuCd=DOM_000000303011001000&uc_seq=394&lang_cd=en). Определение, OSM-идентификатор, координаты и небольшая цитата сохранены в `data/busan/city-center.json`. Это явное допущение интерфейса; Нампхо и другие центры городской жизни не заменяются утверждением о единственном центре.

## Воспроизводимость

Обычная подготовка и тесты не обращаются в сеть:

```powershell
npx tsx scripts/prepare-busan.ts
npx tsx --test tests/busan-data.test.ts
```

Первичный сетевой сбор запускается отдельно:

```powershell
npx tsx scripts/fetch-busan.ts --fetch
```

При недоступности сервера можно явно выбрать публичное зеркало, перечисленное в [документации OpenStreetMap](https://wiki.openstreetmap.org/wiki/Overpass_API):

```powershell
npx tsx scripts/fetch-busan.ts --fetch --endpoint=https://maps.mail.ru/osm/tools/overpass/api/interpreter
```

Коллектор работает строго последовательно, ограничивает каждый ответ 20 МиБ и 120 секундами, не повторяет запросы автоматически и не обходит ограничения сервера. HTTP-ошибка останавливает сбор. HTTP 200 тоже недостаточно: проверяются JSON, отсутствие `remark`, конечный `out count`, количество каждого типа объектов, уникальные OSM-идентификаторы. При подготовке повторно проверяются SHA-256 сохранённых байтов. [Язык Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL) описывает эти выходные форматы и ограничения времени.

Для повторного извлечения POI есть отдельный необязательный шаг: явно скачайте [датированный PBF, 290 178 112 байт](https://download.geofabrik.de/asia/south-korea-261026.osm.pbf) в `.local/busan-extract/south-korea-261026.osm.pbf`. CLI проверяет его по сохранённому SHA-256 перед обработкой. Извлечение использует закреплённую `pyosmium 4.3.2`; каталог зависимости и национальный PBF остаются в игнорируемой `.local/`. Обычная подготовка из включённого JSON, приложение и тесты данных этой зависимости не требуют:

```powershell
python -X utf8 scripts/extract-busan-pois.py --input .local/busan-extract/south-korea-261026.osm.pbf --source-manifest data/busan/regional-extract-audit.json --boundary-manifest data/busan/manifest.json --config data/busan/place-categories.json --output .local/busan-extract/rebuilt-pois.json --report .local/busan-extract/rebuilt-manifest.json --python-libs .local/busan-extract/python-libs
```

Если отдельная зависимость ещё не установлена, её установка выполняется явно: `python -X utf8 -m pip install --target .local/busan-extract/python-libs osmium==4.3.2`.

`regional-extract-manifest.json` связывает производный JSON с URL/SHA-256/размером PBF, датой базы, версией метода, конфигурацией и SHA-256 результата. Подробный аудит повторного извлечения готовым CLI сохранён в `regional-extract-audit.json`, первоначальный аудит — отдельно в `regional-extract-initial-audit.json`. Повторный прогон дал **побайтно идентичный JSON** всех 6 527 POI. Производный JSON в `raw/` не называется точным HTTP-ответом: это фильтрация первичных OSM-примитивов из PBF. Двум национальным relation с вложенными relation не удалось рассчитать геометрию; они исключены и учтены, их принадлежность Пусану неизвестна. Среди включённых 6 527 POI есть 1 369 без собственного имени; вместо вымышленного названия показываются тип и OSM ID.

`manifest.json` хранит исходный запрос, полный URL, время получения, HTTP-статус, тип ответа, размер, SHA-256 и временные отметки базы OSM/площадей. Ответы Overpass в `raw/` сохранены точно, без перезаписи или удаления полей. Дополнительные успешные ответы Сомён (68 кафе и 122 ресторана) оставлены для сверки с региональным извлечением. При действительном расхождении тегов или координат объект исключается до рассмотрения, обе версии сохраняются. У двух way обнаружилось только различие округления центра: Overpass выводит семь десятичных разрядов, а среднее границ с точностью 1e-7 может иметь дополнительный половинный разряд. Это различие менее сантиметра учтено отдельным тестом и аудитом; оно не объявляется фактическим конфликтом. Кэш не обновляется молча; `--refresh` запрещён, новая версия снимка требует отдельного каталога и рассмотрения изменений.

## Что подтверждено и что неизвестно

Для `nearbyPlaces` статус `supported` относится только к расчёту по сохранённым точкам OpenStreetMap: конкретная точка указанного типа лежит не дальше порога по прямой. `scope=hotel_surroundings`, `method=haversine-osm-v1`, OSM ID, URL, координаты, время получения и срок перепроверки позволяют воспроизвести расчёт. Используется формула гаверсинусов, радиус Земли 6 371 008,8 м, округление расстояния вверх. Геометрия здания/парка/пляжа представлена центром его ограничивающего прямоугольника из Overpass, узлы — своей точкой. Это не вход, не ближайший край территории и не пешеходный маршрут. Дороги, стены, море, перепады высот, доступность входов и часы работы расчёт не проверяет.

`sourceEvidence.status=reported` означает сообщение OSM о размещении объекта. Дата снимка базы (`osmBaseDate`) не является датой изменения конкретного объекта или проверки на месте. Если дата объекта неизвестна, `sourceDate` отсутствует. Срок перепроверки равен 30 дням после получения конкретного ответа и не делает исходный объект более свежим. Явно неработающие объекты и недоступные публике POI отфильтровываются по доступным тегам; отсутствие такого тега не доказывает фактическую работу.

Существующие 96 объектов объединяются только по точному OSM ID. Их официальные категории, факты, даты, маршруты, шумовые наблюдения и координаты сохранены. Одинаковые имена и близкие координаты не служат основанием переносить сведения между объектами. Аудит нашёл **13 пар кандидатов в дубли** с одинаковым нормализованным именем в пределах 100 м; они не слиты автоматически. Переводы имён аудит не сопоставляет. Поэтому число строк не равно проверенному числу уникальных предприятий.

Новые объекты имеют `rooms: []`, `route: null`, неизвестные цену, вместимость и доступность на даты. Никакие номера, ответы отельеров, цены или маршруты для них не придуманы. Старое поле `fetchedAt` и `sourceDate` набора относится к исходному снимку Хэундэ; отдельная `coverage` описывает новые даты и территорию. Исходный пешеходный граф и шумовые наблюдения остаются ограничены старым районом и не распространены автоматически на город.

Неизвестный тип пожелания не должен становиться подтверждённым условием. Для новых типов мест расширяют конфигурацию, явно собирают новый снимок и проверяют его, затем добавляют обработку пользовательского выражения. Признак близости не подтверждает свойства вроде «веганский ресторан», «круглосуточная аптека» или «парк без лестниц».

## Проверка качества

Сначала проверены небольшие синтетические сцены: повреждённые/неполные ответы, совпадение счётчика, повтор OSM ID, координаты, гаверсинусы, выбор ближайшего публичного работающего POI, граница округления, отсутствие вымышленных комнат и неизменность старых сведений. Эти тестовые сцены находятся только в тестах.

Затем выполнена проверка полного набора: все исходные SHA-256/счётчики, воспроизводимая сборка, уникальность OSM ID, сохранение каждого старого поля и отсутствие новых комнат/цен/маршрутов без источника. **9/9 тестов данных прошли**, включая полный корпус; это не оценка фактической точности карты. Все 876 точек размещения находятся внутри итогового map bbox. Только **6/876 объектов** имеют собранные официальные категории: **46 категорий**; для **870/876 объектов** сведения о категориях не подтверждены. У 54 новых OSM-записей нет названия, и это показано явно.

По сохранённым геометрическим данным в пределах настроенного радиуса находятся: 71/876 объекта от ориентира центра (1 500 м), 684/876 от кафе (500 м), 837/876 от ресторана (500 м). Остальные знаменатели есть в `quality.json`. Проверок гостиниц и мест на местности: **0**. Полнота OSM относительно действующих предприятий неизвестна; полнота выполнения запроса не заменяет полноту карты.

При сборе основной Overpass вернул 502, первое зеркало — 504 на запросе размещения, второе зеркало предоставило размещение, но составные запросы POI завершались 504. Эти ответы не сохранены как успешные снимки и не использованы для утверждения отсутствия мест. Кэширование успешных частей позволило продолжить без повторной загрузки гостиниц.

## Что проверено в сквозном сценарии

AI_PROVIDER=deepseek имеет приоритет над намеренно неработающими LLM_* и
ADVISOR_LOCAL_*. Проверены Java-разбор пожеланий, расположения, чата и публичного
ответа отельера, в том числе Spring LlmAnswerExtractor. API конфигурации возвращает
DeepSeek как режим по умолчанию без ключа. API запуска возвращает 202, запускает
настоящий Python-worker и сохраняет завершённый отчёт с execution=deepseek,
двумя вызовами, 40 входными и 10 выходными тестовыми токенами в PostgreSQL.

История сохраняет владельца; другой cookie-клиент не получает снимок и отчёт.
При HTTP 429 выполняется один вызов и rules_fallback без повторов. Явный запуск
rules не обращается к стенду. Контексты синтетические; ответ модели задан тестом.
Это проверка маршрутизации и протокола, а не оценка качества DeepSeek.

Отдельные проверки покрывают запрет редиректов, HTTP 401/402/429/5xx, размер
запроса/ответа, пустой, обрезанный и неверный JSON, дубли ключей, trailing tokens,
неверную схему, неизвестные ID, keep-alive и зависшее тело ответа. Проверяются
обязательные предупреждения и отказ от придуманной принадлежности доказательств.
Ключ и необработанные тела ошибочных ответов не выводятся в сообщения ошибок.

## Существенные найденные проблемы и исправления

1. В main выбор модели был раздельным: Agents, планировщик расположения,
   Spring LlmClient и Python могли использовать разные настройки. Введён общий
   AI_PROVIDER; один DeepSeek-ключ заменяет локальную модель во всех этих путях.
2. PythonWorker не передавал DeepSeek-настройки, а режимы и диагностика принимали
   только rules/local. Добавлены явный режим, ограниченная передача ключа только
   его процессу и проверка соответствия запрошенного и выполненного режима.
3. Основной интерфейс всегда запускал rules, лаборатория считала модель локальной
   и показывала отсутствие платного API. Добавлены серверный defaultMode, подписи
   DeepSeek, отметка платных запросов и корректное сравнение с правилами.
4. Сквозной запуск из Maven обнаружил зависимость Python-worker от текущей папки.
   Добавлен ADVISOR_ROOT для запуска Java вне корня; тест использует настоящий
   worker с явно заданным корнем, а не подменяет его ответ.
5. Старый LlmClient мог логировать тело ошибки провайдера. Теперь в журнале только
   код HTTP либо общее сообщение, без сырых ответов и ключей.
6. Тестовые запускатели отключали лишь прежние ключи. В Java-фикстурах исключено
   наследование DeepSeek, в HTTP/contract-проверках явно задан AI_PROVIDER=rules.

## Ограничения

Реальных запросов к DeepSeek: 0. Ключ, баланс, доступность конкретной модели,
реальный TLS/сеть и смысловое качество ответов не проверены. Настоящую модель
нужно отдельно проверить после настройки серверного ключа. Имя модели
настраивается через DEEPSEEK_MODEL; текущий пример взят из официальной документации.

Завершённый JSON по схеме не доказывает истинность сведений. Сохранены прежние
проверки цитат, обязательных условий, одной категории/комнаты и неизвестности.
Внешних сообщений отельерам и проверки условий на месте не было.

Java пока не выводит токены отдельных разборов в UI; общего финансового лимита
нет. До двух вызовов ограничено на один запуск Python-помощника, не на весь
диалог сайта. Резервный ответ по правилам не отменяет стоимость уже отправленного
API-запроса. Отдельной ручной проверки интерфейса в браузере не проводилось;
проверены типы, сборки и серверный рендер соответствующих компонентов.

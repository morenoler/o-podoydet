# Проверка переноса main в Spring

Дата: 26.10.2026. Основа: `main` e4faa2d и `spring-migration` fd09ba5.
Первый этап был опубликован в `spring-migration` без изменения main. Последующее
объединение с диалоговым подбором описано в конце документа.

## Состав

Java API работает из `server/` на Java 21, Spring Boot **3.5.6**, PostgreSQL 16.
Стиль исходной Spring-ветки сохранён: контроллеры MVC, конструкторные зависимости,
доменная логика в существующих пакетах, JdbcClient/JPA и транзакции Spring.
Python-агенты и отдельный сервис вида из окна сохранены. `src/`, `shared/`, `agents/`
и `services/window-view/` совпадают с актуальным main.

Перенесены режимы допуска поиска, личные пожелания и их объяснения, кабинеты,
фотографии, частные уточнения, история ответов, согласованные снимки помощника,
принадлежность истории, оценка района и API вида из окна. Все 24 Java-файла тестов
main восстановлены под `server/src/test`.

V1–V3 исходной Spring-ветки не переписаны. V4 добавляет частные уточнения,
V5 — владельцев запусков помощника, V6 — активный регион и изоляцию истории.
SQLite используется только по явному `LEGACY_DB_PATH`, в режиме чтения;
действующие записи PostgreSQL не заменяются импортом.

## Найденные ошибки и исправления

- Пересчёт доказательств выполнялся после сохранения снимка помощника. Теперь
  поиск, карточка и помощник используют окончательную согласованную проекцию;
  последующий ответ отельера не меняет уже сохранённый снимок.
- Исходный overlay не учитывал explore/verified и мог смешивать условия категорий.
  Применяется общая политика допуска и проверка одного номера.
- Имитации отельера были привязаны к реальным гостиницам и могли подтверждать
  реальные факты. Введены demo/simulated, защита экспериментальных диалогов и
  отдельные вымышленные `data/demo/spring-host-dialog.json`. Отсутствие авторизации
  больше не позволяет изменять знания реального каталога через v2.
- Независимые ответы одного предмета автоматически заменяли друг друга.
  Замена разрешена только внутри того же диалога и канала; другие версии
  сохраняют противоречие. Политика demo определяется регионом конкретного отеля.
- SQLite-сериализация не переносится на многопоточный PostgreSQL автоматически.
  Добавлены транзакции, блокировки объявления, защита повторных запросов и версий,
  согласованные снимки чтения и конкурентные проверки подтверждения заявок.
- Импорт мог переносить факт или исторический вопрос между регионами при
  совпадении ID и переписывать существующие исправления PostgreSQL. Проверяются
  регион и предмет; столкновение отменяет транзакцию. Цепочки замены применяются
  только к действительно вставленным строкам того же предмета.
- Восстановление оборванных запусков помощника происходило до импорта SQLite.
  Теперь оно повторяется после импорта до открытия HTTP: перенесённые queued/running
  переходят в failed, завершённые ответы и их владельцы сохраняются.
- Часть вычислений использовала системные часы вместо общего Clock. Время
  выдачи, свежести источников и восстановления истории согласовано и проверяется
  фиксированными датами, отличающимися от времени компьютера.
- Необязательный confidence=null приводил к исключению. Добавлена регрессия.
- Исходный Spring-тест ожидал старые 304 факта. Текущий main содержит 328;
  проверка теперь сопоставляет полный набор ID и область каждого свидетельства
  с исходным файлом, сохраняя проверку уникальности.
- Tomcat отклоняет некорректный путь с `..` до контроллера кодом 400.
  Проверка сохраняет запрет раскрытия файла и учитывает этот транспортный ответ.
- Testcontainers 1.21.3 не подключался к Docker Engine 29. Зависимость тестов
  закреплена на [1.21.4](https://github.com/testcontainers/testcontainers-java/releases/tag/1.21.4),
  исправляющей совместимость с новым движком. Версии Java и Spring Boot сохранены.

Все перечисленные финальные проверки завершились успешно. Полный Java-прогон
предшествовал двум последним регрессиям импорта; затронутые импорт и запуск после
этих изменений проверены повторно набором 9/9. Повторная проверка неизменённых
частей не выдаётся за отдельное покрытие.

85 эталонов API заново сняты с отдельной проверенной сборки текущего main,
а не с переносимого сервера. Происхождение и SHA-256 указаны в
[contract/README.md](../contract/README.md).

Первое сравнение дало 76/85: все девять отличий были в диагностическом имени
базы (`trace[2].tool`, SQLite 3 → PostgreSQL). Остальные поля этих ответов совпали.
Разрешены только эти точные переходы значений и имя базы в health
(SQLite 3 → PostgreSQL 16); содержимое trace целиком не исключается.
Проверка состава каталога была запущена одновременно со сценарием, создающим
объявление; обнаружено загрязнение тестовой схемы. Повторные проверки используют
отдельные чистые схемы и выполняются последовательно для общих данных.

Локальные подробные журналы находятся в игнорируемой `.local/spring-migration/`:
`http.json`, `accounts.json`, `clarifications.json`, `search-modes.json`,
`personal-wishes.json`, `busan-expanded.json`, `contract-fresh-schema-final.log`.
Java: `.local/spring-verify-final.log`, `.local/spring-importer-startup-final.log`
и `.local/spring-testcontainers-fixed.log`. Пользовательские данные в отчёт не включены.

## Границы результата

- Это проверка кода, API и сохранённых данных. Проверок реальных номеров на месте: **0**.
  288 случаев вида — три пары этаж/дата на объект, не все сочетания и не точность
  по фотографиям. Неполная геометрия сохраняет unknown.
- Объекты каталога и категории при частичном импорте сохраняются, даже если
  отсутствуют в очередном файле: это сохранённый контракт main. Межрегиональные
  совпадения глобальных ID отклоняются; для таких наборов нужны отдельные схемы.
- Диалог v2 пока предназначен для вымышленной лаборатории. Реальные владельцы
  работают через авторизованные кабинеты и частные уточнения; регистрация
  не даёт прав на произвольную гостиницу открытого каталога.
- Свободный текст обрабатывается ограниченными правилами, а слова владельца
  сохраняют происхождение reported. Достоверность на месте, доступность на даты,
  оплата и бронирование внешнего поставщика этим переносом не подтверждены.
- Первый запуск требует получения Maven-зависимостей и образа PostgreSQL;
  затем проверки используют локальные снимки без ключей внешних API.

## Объединение с диалоговым подбором, 26.10.2026

Объединены `spring-migration` 5c39f76 и `codex/spring-boot-backend` 45b5b9b.
Каноническим сервером остаётся `server/`, Java 21 / Spring Boot 3.5.6 / PostgreSQL 16.
В него перенесены последовательный чат, явные изменения пожеланий и рекомендации
конкретных категорий. Сброс удаляет изменения из чата и сохраняет ручные условия.

Подтверждённые совпадения всех критериев находятся в `roomRecommendations`;
допущенные режимом поиска варианты с оговорками — в `roomAlternatives`.
Сохранены explore/verified, Leaflet и сохранённая карта, личные пожелания,
приватные уточнения, владельцы снимков/запусков, ядро знаний и сервис вида из окна.
Миграции Flyway не изменялись. Указанная вместимость учитывает подтверждённое
правило размещения выбранной категории. Проверка Origin использует декодированный
маршрут, включая запросы вида `/%61pi/search`.

Проверки объединённой версии:

- TypeScript: 187/187; Python-помощник: 32/32.
- Java: 237/237 на настоящем PostgreSQL 16.15, ошибок и пропусков нет.
  Прогон был прерван после 225 завершённых тестов; оставшиеся 12 проверены отдельно.
- Сервис вида: 182/182; расширенная матрица: 288/288 запросов по 96 объектам.
- Парсер шумового отчёта: 5/5; генератор демо: 4/4; проверки запуска: 2/2.
- Сборки приложения и лаборатории успешны.
- Контракт актуального main: 85/85. Старые эталоны сохранены; явно разрешены
  девять точных изменений текста `trace[1].detail` с числом подходящих категорий.
- Браузер: последовательные пожелания, удаление условий, сброс и поздний ответ,

фотографии пользователя не участвовали в проверках. Логи и снимки экрана остаются
в игнорируемой `.local/`.

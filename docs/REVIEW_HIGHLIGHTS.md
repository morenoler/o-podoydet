# За что хвалят в отзывах

Как путешественник, я хочу видеть, что гости особенно ценят в жилье, чтобы быстро сравнить варианты и понять, какие детали стоит изучить перед поездкой.

В карточках объявлений `/stays` и объявлений отельеров в поиске показываются три темы. Ссылка «Все темы отзывов» открывает блок на странице объявления. Там каждой теме соответствует короткое пояснение. Например: чистота, удобные кровати, гостеприимство, заселение или оснащение кухни. Эти темы дополняют сведения о размещении; они не подтверждают обязательные пожелания и не меняют ранжирование.

## Текущий прототип

Данные сгенерированы только для семи опубликованных вымышленных объявлений из `data/demo/fixtures.json`. Они хранятся отдельно в `data/demo/review-highlights.json`, с `is_demo=true` и `status=demo`. В интерфейсе всегда видны пометка «Демо» и пояснение, что отзывы вымышленные. Тексты реальных отзывов, авторы, оценки, проценты и число упоминаний не выдумываются.

Показ требует одновременно точного ID демообъявления и серверного `demo=true`. Совпадения по названию, городу или похожему ID недостаточно. Для остальных объявлений краткий блок отсутствует; на странице жилья написано, что отзывы пока не загружены. Публичная форма владельца не может назначить себе статус демо.

## Следующий этап: отдельный скрипт

Сбор и разбор отзывов сейчас **не реализованы**. В дальнейшем отдельный явно запускаемый скрипт будет получать доступные отзывы, сохранять источники и выделять ключевые параметры похвалы. Приложение будет читать подготовленный результат. Владельцу не потребуется вводить похвалу вручную.

Контракт результата описан в `shared/reviewHighlights.ts`: субъект и область действия, список тем с ключом, названием и пояснением, источник, дата получения, известная дата источника, метод, срок перепроверки, статус и признак демо. Неизвестная дата источника и размер корпуса остаются `null`. `obtainedAt` демопримеров обозначает дату подготовки примера, а не дату получения настоящих отзывов. Для реальных данных понадобится отдельный проверяемый импорт/API; демонстрационный загрузчик намеренно принимает только демопримеры.

Перед подключением реальных результатов необходимо добавить ссылки на исходные отзывы и идентификаторы подтверждающих фрагментов, количество обработанных отзывов, период и полноту выборки. Нельзя выводить «чаще всего» без подсчёта; положительные и отрицательные упоминания одной темы нужно сохранять вместе. Похвала отелю не подтверждает характеристику каждой комнаты, доступность или тишину на даты поездки.

## Проверка и запуск

```powershell
npm test
npm run backend:test
npm run build:all
npm run demo:setup
npm run demo:start
```

Демоверсия: `http://127.0.0.1:8082/stays`. Если `.local/demo.sqlite3` уже существует, команда setup сохраняет её. Для расширенного набора из восьми объявлений создайте новую копию: `npm run demo:setup -- --output .local/demo-reviews.sqlite3`, затем задайте `DEMO_DB_PATH=.local/demo-reviews.sqlite3` и отдельную `DEMO_DB_SCHEMA=demo_reviews` перед запуском. Подробности в [DEMO.md](DEMO.md). Переимпорт не должен перезаписывать пользовательские данные.

Целевые проверки: `npx tsx --test tests/review-highlights.test.ts tests/listing-beds.test.ts tests/comparison.test.ts tests/sochi-account-ui.test.ts`. Они проверяют отделение демо, пустые состояния, переход к подробностям, совместимость кроватей и валют. Реальные отзывы и состояние объектов на месте не проверялись.

# Рабочий спутниковый слой и проверка регрессий

Проверка выполнена 29 октября 2026 года на исходной `main` `eb65e16`.
Дата проверки приложения не является датой съёмки или обследования отеля.

## Найденные ошибки

1. Без `VITE_ARCGIS_API_KEY` кнопка «Спутник» оставляла OpenStreetMap. Ошибка
   воспроизведена в браузере на пользовательской сборке, порт 8080.
2. Пояснение результатов продолжало называть EOX 2016 даже при включённом ArcGIS.
3. Любая ошибка одного тайла немедленно убирала всю карту, включая успешно
   загруженные участки. Теперь неполная карта остаётся с предупреждением;
   полностью неудачная загрузка или отсутствие результатов по тайм-ауту
   переключают на запасной слой. Успешная следующая область снимает предупреждение.
4. Блок «О карте и данных» перекрывал атрибуцию поставщика. Он вынесен в поток
   под картой; пересечение проверено по геометрии DOM на двух ширинах.
5. Подпись выбора расположения объявления называла Пусан при выборе Сочи.
   Подпись теперь не зависит от региона.

## Источник снимков

Без ключа кнопка «Спутник» использует **ESA WorldCover Sentinel-2 annual true-colour
composite 2021**, слой `esa-worldcover-s2rgbnir-10m-2021-v2_tcc`, через Terrascope WMTS.
Слой отражает годовую мозаику с разрешением около 10 м, а не текущую съёмку.
Собственные тайлы доступны до z14. После уточнения пользователя приближение карты
доступно до z19: снимок увеличивается без появления новых деталей, а маркеры,
маршруты и управление продолжают работать в обычном масштабе. Поля `maxNativeZoom`
и `maxZoom` разделены; переключение слоя больше не отдаляет выбранный отель.
Для подробных улиц остаётся OSM (z8–19), для авторизованных подробных снимков
сохраняется настройка `VITE_ARCGIS_API_KEY` и проверка атрибуции Esri.

На первом визуальном проходе открытый EOX 2016 показал облачную область над
Хэундэ, поэтому в итоговой реализации выбран ESA WorldCover 2021.
REST-шаблон Terrascope из `ResourceURL` вернул HTTP 400; используется объявленный
в `OperationsMetadata/GetTile` адрес KVP `https://wmts.terrascope.be/wmts`.
Параметры слоя, времени, матрицы, строки и столбца проверяются отдельным тестом.

| Поле | Значение |
| --- | --- |
| Субъект и область | Спутниковый фон, без изменения гостиничных фактов, маршрутов и OSM-набора |
| Источник и лицензия | [ESA WorldCover data access](https://esa-worldcover.org/en/data-access), CC BY 4.0 |
| Получено | 2026-10-29, HTTPS GET официальной документации, WMTS capabilities и двух тайлов |
| Дата источника | Год композиции 2021; точные даты отдельных пикселей не установлены |
| Статус | Свойства слоя заявлены поставщиком; загрузка проверена на двух областях |
| Перепроверка | До 2026-11-29 или при ошибке загрузки/изменении сервиса |

Официальный [WMTS GetCapabilities](https://wmts.terrascope.be/?request=GetCapabilities&service=WMTS)
объявляет EPSG:3857, уровни 8–14, PNG и время `2021-01-01`.
SHA-256 сохранённого локального ответа:
`792046b76b0e0134c3fe7c3a33841cc72c1da2fb2c140ac7fa7b1af41886fdbe`.

Пилот: по одному тайлу на z14 для Пусана и Сочи; оба HTTP 200, image/png,
98 261 и 44 120 байт соответственно. Затем выполнена проверка видимых областей
в браузере: Пусан — 12/12 тайлов, Сочи — 8/8 тайлов. Это проверка загрузки,
не оценка географической точности или актуальности всех объектов.
Снимки не выгружаются массово, не используются как доказательства условий номера
и не добавляются в исследовательские наборы. Сохраняются атрибуции ESA,
Copernicus, Terrascope и OpenStreetMap; действует обычный HTTP-кэш браузера.

## Ограничения

- Настоящий ArcGIS API key отсутствует: авторизованные запросы Esri в браузере
  не проверены; кодирование ключа и обработка недостоверной атрибуции проверены тестами.
- Отказы тайлов и тайм-ауты проверены детерминированными тестами монитора;
  сетевые ошибки поставщика не создавались в живом браузере.
- Мобильная проверка выполнена на ширине 390 px во встроенном Chromium,
  а не на физическом телефоне. Safari, Firefox и другие сети не проверены.
- Обзорный слой не позволяет рассмотреть окна или подтвердить вид из комнаты.
  Полевая проверка и свежесть снимков по каждому отелю не выполнены.

## Уточнение поведения приближения

Пользовательская проверка выявила, что жёсткий предел z14 мешал приближать отели.
Ограничение ошибочно связывало возможности управления с разрешением источника.
Исправление разрешает z19 для обоих видов карты и сохраняет ограничение запросов
к ESA на z14. Это исправление взаимодействия, а не повышение разрешения снимков.

Проверка уточнения: 362/362 TypeScript-теста, typecheck, основная и лабораторная
сборки. В браузере пройдены семь шагов приближения от шкалы 2 км до 20 м (z19).
На z19 загружен тайл ESA z14 и увеличен Leaflet; запросов несуществующих уровней
ESA z15–19 нет. Переключения спутник → улицы → спутник сохранили шкалу 20 м,
ошибок в консоли не было. Серверные и Python-наборы из таблицы выше относятся
к предыдущему исправлению и для этого изменения управления не запускались повторно.

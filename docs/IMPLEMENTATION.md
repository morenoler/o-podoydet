# Реализация MVP: Пусан / Java 21 / SQLite 3

Состояние на 24 октября 2026 года, версия 0.2.0. Реализованное поведение и проверки перечислены отдельно от возможностей полной концепции.

## Что изменилось

- Добавлена лабораторная копия на порту 8081 с отдельной базой и шестью учебными объявлениями. Страница `/lab` показывает реальный выбор локального ИИ, проверку критиком, решения Java и исправления программной защиты. Доступны два изолированных тестовых опыта, сравнение с правилами на одном снимке и инструкции проверки каждого агента. Скрипты устанавливают Ollama и готовят небольшую локальную модель без платного API. [Запуск, ограничения и результаты проверок](LOCAL_AI_LAB.md).

- В выдачу встроен помощник выбора на Python с Java 21 API: анализ пожеланий, короткий список, критика оснований и предварительные сценарии при отсутствии совпадений. Использует точный снимок текущего поиска; обязательные условия самостоятельно не меняет. По умолчанию работает без модели, опционально поддерживает только локальную модель, до двух вызовов за запуск. История хранится в `advisor_runs`. [Устройство и проверка](ADVISOR.md).

- Добавлена отдельная BinaryDecisionPolicy: критерии возвращают match/mismatch, варианты fits/excluded. Исходные unknown/stale/conflict сохраняются в evidenceStatus; эвристики помечены assumed и объясняются отдельно. Неизвестная вместимость оценивается по типу размещения.
- Интерфейс разделён на app/pages/features/shared. Java разделена на web/application/domain/persistence/shared; SearchService объединяет поиск и расчёт карточки. Сервер остаётся источником окончательных решений. [ARCHITECTURE.md](ARCHITECTURE.md).

- Рабочий каталог переведён на `data/verified-hotels.json`, политика по умолчанию `verified-only`. Добавлены 38 официальных категорий у 6 отелей и 17 подтверждений семейного назначения; у 90 объектов категория и вместимость остаются неизвестными. Старые демонстрационные факты и сохранённые ответы кабинета не используются как реальные доказательства.

- Демонстрационная территория перенесена в Пусан, район пляжа Хэундэ. Исходные снимки Адлера заменены данными Пусана; старая пользовательская SQLite-база остаётся нетронутой.
- Бэкенд работает на Spring Boot 4.1.2 / Java 21: Spring MVC, Tomcat, Jackson 3 и sqlite-jdbc. Spring управляет сервисами и ресурсами, Maven собирает исполняемый Boot JAR. Все API и готовый интерфейс обслуживаются Spring Boot. [Архитектура и проверка](BACKEND.md).
- SQLite 3 создаётся по `backend/src/main/resources/schema.sql`. Таблицы: metadata, hotels, rooms, facts, questions, drafts. Каталог после импорта читается из базы; JSON-поля сохраняют сложную геометрию и историю доказательств.
- Сохранены подбор внутри одной категории, обязательные условия, неизвестные/устаревшие/конфликтующие сведения, сравнение, кабинет отельера, предварительный разбор и атомарное подтверждение ответа.
- Сохранены ограниченные правила разбора и опциональный адаптер Responses API с проверкой цитаты и fallback. Новые параметры браузера изолированы от старой версии.
- Добавлен `scripts/assess-area.ts` с пакетным и одиночным вводом координат, кешем, тайм-аутами, проверкой единиц/времени/географии, offline-режимом и импортом официальной районной статистики.
- В карточках появился блок района. `GET /api/areas/:hotelId` читает отчёт при запросе, проверяет координаты отеля и свежесть данных воздуха. Пересборка Java для обновления отчёта не нужна.
- Безопасность, воздух и внешний шум добавлены в пожелания, ранжирование и сравнение. `POST /api/hotels/:id/evaluate` оценивает все восемь условий на даты поездки; карточка использует тот же Java-расчёт, что и выдача.
- Воздух проверяется по почасовому прогнозу с полным покрытием поездки в Asia/Seoul. Шум учитывает геометрию дорог, датированные наблюдения движения и локальные мероприятия; подробности и источники доступны в интерфейсе.
- Каталог расширен до 96 именованных объектов пяти типов в прежних границах Хэундэ. `lodgingType` отделяет отели, мотели, хостелы, гостевые дома и апартаменты. Отсутствие маршрута больше не удаляет объект из каталога.
- Добавлен отдельный исторический фон KTDB за 2024 год. Он сохраняет исходную неизвестность на даты поездки, но бинарная политика принимает исторический low и отклоняет moderate/high как явно помеченную оценку. Это действует и на обязательное условие.
- При запуске Java синхронизирует исходный каталог с SQLite транзакционно. Новые объекты добавляются без удаления базы; вопросы, черновики, подтверждённые ответы и история сохраняются. Исчезнувшие из снимка исходные факты перестают быть активными.

## Данные

В снимке Хэундэ 1 773 объекта OSM. Каталог содержит 96 именованных объектов размещения: 42 отеля, 42 мотеля, 6 хостелов, 4 гостевых дома и 2 объекта апартаментов. У 95 есть приближённые маршруты к Haeundae Beach длиной 36–1355 м; у Paradise Hotel Busan (`node-4199814292`) маршрут неизвестен и геофакт расстояния отсутствует. Исследованы официальные источники восьми отелей: у шести найдены 38 категорий, для двух достаточных данных нет. 17 категорий имеют family=true; courtyard и полный step_free_access не подтверждены. У Paradise подтверждено название Deluxe City, но максимальная вместимость неизвестна. Источники и ограничения находятся в двух research-файлах. Старые 448 демонстрационных фактов остаются только в географической основе/архиве `demo.json`. Подробнее: [VERIFIED_DATA.md](VERIFIED_DATA.md).

`npm run data:verify` собирает рабочий каталог из основы и исследований без сетевых запросов. `npm run data:prepare` пересобирает оба каталога последовательно. Для официальных категорий и фактов действует срок перепроверки 30 дней; пересборка не продлевает исходные даты. Частичные сведения сохраняют value=null, включая 95 step_free_route. Отдельная политика может принять маршрут без отмеченных лестниц либо с обходом как оценку, не изменяя геофакт. SQLite сохраняет историю кабинета, но real-подбор отбрасывает demo/host-свидетельства.

География получена из ограниченных запросов Overpass и четырёх небольших тайлов официального OSM API. Кеш региона и снимок включены в репозиторий. Маршруты идут по связанным рёбрам с учётом известных ограничений доступа. Отсутствие отмеченных ступеней не становится доказательством полной доступности. Соединительные участки от отеля до сети и от сети к точному входу на пляж не обследованы.

Отчёт `area-assessments.json` обновлён для всех 96 объектов: получены текущие PM2.5, PM10, NO₂ и US AQI из Open-Meteo/CAMS Global и почасовые прогнозы. Это модель с сеткой около 45 км, а не измерение конкретной улицы. Значения старше 6 часов становятся устаревшими при чтении. Текущий снимок показан отдельно; за фактическим горизонтом прогноза исходная оценка остаётся unknown. Бинарная политика может применить отдельно проверенный текущий снимок не старше 24 часов как предположение с порогом US AQI ≤ 50. Даты и покрытие нужно читать из текущего отчёта, поскольку следующая загрузка их изменит.

Официальный CSV полиции содержит две используемые категории за 2025 год по всему Хэундэ-гу: кражи и разбойные нападения. Географическая привязка выполнена по полигону OSM relation 4062934; все 96 точек внутри. Период, территория, названия категорий, исходная строка/столбец, хеш CSV, методика и ограничения сохранены. Историческая граница именно за 2025 год отдельно не проверена. Из районных чисел не вычисляется личный риск или общий балл безопасности.

Официальный публичный слой KTDB/View-T без ключа вернул 86 дорожных участков. У 10 есть исторические будничные подсчёты 2024 года: 184 часовых значения, три полных суточных профиля и семь профилей 06:00–22:00. Остальные 76 участков не получили вымышленных нулей. У 72 объектов каталога есть линия с историческим профилем в пределах 300 м; это не полное покрытие дат поездки. Источник, геометрии, исходный ответ и хеш сохранены. `npm run traffic:fetch` использует проверенный кеш; `--refresh` повторяет запрос. Java читает `TRAFFIC_DATA_PATH`, по умолчанию `data/traffic-ktdb-2024.json`.

Исторический фон применяется к поездкам с будними днями, если год профиля не старше трёх лет относительно года заезда. Расстояние считается до собственных линий KTDB; подсчёты не приписываются OSM way и не пересчитываются на полосу без числа полос. Исторический фон сохраняет исходные unknown и assessmentBasis=historical. Финальная политика принимает low, отклоняет moderate/high и помечает решение оценкой. Обязательное несовпадение исключает вариант, желательное меняет порядок. Датированные события и наблюдения имеют приоритет. Подробности: [TRAFFIC.md](TRAFFIC.md), [NOISE.md](NOISE.md).

## Проверки

Результаты ранних браузерных проходов ниже относятся к прежнему демонстрационному режиму. Они не доказывают изменение реального подбора ответом кабинета: в текущем `verified-only` такой ответ должен сохраняться только в истории. Проверки нового режима перечислены в [ACCEPTANCE.md](ACCEPTANCE.md); исторические API-примеры с итоговым unknown ниже также предшествуют бинарной политике.

- TypeScript-набор проверяет географию, валидацию восьми пожеланий, источники воздуха и прогноз, официальный импорт, трафик, события, покрытие и offline CLI. После расширения каталога отдельно пройдены 10 тестов географии и подготовки данных, проверка типов и точное совпадение повторной подготовки с сохранённым JSON.
- JUnit-набор проверяет HTTP-контракты, обязательные условия, область действия фактов, транзакции, сохранность SQLite, прогноз на даты поездки, сопоставимость безопасности, шум и защиту от ложных подтверждений. При прочих равных умеренный риск шума ранжируется выше высокого. Текущие команды полного прогона: `npm test` и `npm run backend:test`; число тестов меняется с развитием набора.
- TypeScript и Vite проходят сборку. Maven компилирует Java с release 21 и собирает исполняемый JAR.
- На прежнем каталоге из 24 объектов в браузере пройдено: Пусан → 5–12 ноября 2026 года → двое взрослых и ребёнок → обязательное удобство с коляской → 16 кандидатов. Это исторический результат проверки, не ожидаемое число для расширенного каталога.
- В том проходе для Geullori Condominium создан вопрос, разобран и подтверждён ответ «Перед входом три ступени, пандуса нет.». Новый подбор показал 15 кандидатов: неподходящая категория исключена. Ответ сохранён в локальной SQLite.
- В карточке проверены карта, маршрут, показатели воздуха и официальные районные сведения с источниками. Карточка и оба блока района визуально проверены в браузерном viewport 390 × 844; горизонтального переполнения не обнаружено. Это не тест на физическом устройстве.
- Независимый просмотр Java-кода проверил API, области действия, транзакции и свежесть источников. Найденный случай отсутствующего времени модели исправлен и покрыт тестом.
- Дополнительно проверены в браузере новые пожелания, выдача, сравнение Sunset и Westin, источники расчёта и карточка района на ширине 390 px. Горизонтального переполнения и ошибок консоли не обнаружено. [Превью сравнения](environment-comparison.png).
- Через рабочий API: у Westin на 7–8 ноября 2026 событие даёт высокий риск шума и исключение при обязательной тишине; на 8–9 ноября это событие не учитывается, результат unknown из-за неполноты данных. Прогноз на 25–26 октября покрывает 24 часа, максимум US AQI 33, результат match; ноябрьские даты за горизонтом дают unknown.

Во время разработки параллельная пересборка JAR нарушила загрузку классов уже запущенной JVM. Скрипт запуска теперь копирует JAR в отдельный `.local/runtime/` перед запуском. Maven принудительно пересоздаёт исходный JAR перед упаковкой зависимостей; после изменений сервер перезапущен.

## Ограничения

- Нет актуальных цен, наличия номеров, бронирования и авторизации реальных отельеров. Сервер слушает только `127.0.0.1`.
- Официальные категории покрывают только 6 из 96 объектов; известная категория также не означает, что все её условия подтверждены. Для 90 объектов неизвестны категория и вместимость.
- Courtyard и полный путь без ступеней до категории не подтверждены. Нет обследования маршрутов и измерения шума внутри номера; вид на город, парк или сад не подменяет внутренний двор.
- Нет текущего потока дорожных счётчиков и прогноза движения на даты поездки. KTDB — частичный исторический фон 2024 года; отсутствующие ночные часы, выходные и режим праздников им не восстановлены.
- Скрипт оценивает загрязнение воздуха; вода, почва и санитарное состояние не измеряются.
- Нет общего рейтинга безопасности или вероятности происшествия для гостя. Для проверки пожелания поддержан строгий импорт сопоставимых официальных показателей на 100 тысяч жителей. Реальные абсолютные числа в поставке не удовлетворяют этому условию.
- Реальный LLM-провайдер с ключом не проверен; тесты используют контролируемые ответы/ошибки.
- Грубые оценки семьи, вместимости, маршрута, текущего воздуха и внешнего шума могут ошибаться; они видны отдельно от доказательств и не подтверждают свободный номер.
- Полная ручная приёмка всех сценариев не заявляется. Дальнейшие проверки перечислены в [ACCEPTANCE.md](ACCEPTANCE.md).

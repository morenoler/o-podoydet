## Существенные найденные ошибки

1. **Отрицательное условие терялось при частичном пересечении поездки.** В обоих Java путях оценки и TypeScript требовалось покрытие всей поездки независимо от значения. Пример: общий положительный факт о доступе и закрытие прохода 2 ноября при поездке 1–4 ноября давали подтверждение. Теперь положительный факт должен покрывать всю поездку, отрицательный применяется при любом пересечении, включая выезд. Конфликт не затирается.
2. **Погрешность числового источника могла скрыть несовпадение порогу.** Значения 900 и 1100 м считались согласованными, хотя порог равен 1000 м. Теперь допуск погрешности применяется только по одну сторону порога; иначе сохраняется конфликт.
3. **Простые запросы вызывали модель при наличии конфигурации.** Обычный поиск и чат теперь используют детерминированный разбор. Тест с локальным HTTP-счётчиком проверяет ноль обращений даже при заданных ключе и модели. Дополнительный разбор на странице также запускается по правилам; эксперименты с моделью остаются в лаборатории.
4. **Тишина автоматически подменялась окнами во двор.** Теперь это независимые условия. Отрицания, числовые требования и неизвестные части запроса не должны превращаться в приблизительно похожий готовый фильтр.
5. **Дата могла сдвинуться на предыдущий день.** `dateFull` интерпретировал календарную дату как UTC-момент. Регрессия проверяет четыре часовых пояса; даты поездки сохраняют день календаря.
6. **Подпись маршрута выглядела как полная дорога от входа.** Карточка, сравнение и карта теперь говорят о пешеходной сети; непроверенные подходы отделены от её длины.
7. **Пустой ответ недоступного API показывал технический JSON error.** Теперь есть понятное сообщение с повтором; устаревший поисковый запрос отменяется при изменении условий.
8. **Дополнение в чате могло затереть название отеля.** «Нужен балкон» теперь дополняет `Signiel` до `Signiel балкон`; явная команда «Найди Hilton» заменяет запрос. Повторы не добавляются, превышение 240 символов отклоняется с пояснением без потери исходного запроса.
9. **Отмена смешанного запроса сохраняла часть изменений.** В сообщении «Нужно тихо и гамак» распознанное условие применялось, но пустой контекст следующего сообщения мешал его отмене. Журнал теперь сравнивает все изменённые критерии независимо от контекста; последующие ручные правки сохраняются.
10. **Пустой набор пожеланий выглядел как проверка всех удобств.** Карточка без выбранных условий теперь сообщает о вместимости и происхождении категории; заголовок подробностей также не обещает совпадение отсутствующих условий.
11. **Vite мог завершиться на заблокированном JAR в Windows.** При параллельной проверке серверной сборки наблюдение `.local/runtime` завершилось с `EBUSY`. Временные сборки и `server/target` исключены из наблюдения; production-сборки проходят.

## Изменения

В `Trip.hotelFilters` добавлены `query`, `lodgingTypes`, `maxPricePerNight`, `maxBeachMeters`. Один серверный фильтр применяется после проекций источников и личных уточнений, перед формированием рекомендаций, альтернатив, деталей и повторных подборов помощника. Неизвестное значение не проходит числовой фильтр; цена сравнивается только в KRW. Слова должны находиться в области одного отеля и одной категории, а не собираться из разных комнат.

Текстовый поиск использует Unicode-нормализацию, ограниченный словарь русско-английских соответствий и совпадение префиксов длиной от трёх символов. TypeScript-предпросмотр и Java используют общий синтетический набор тестовых запросов. Найденные фрагменты сохраняют ссылку, область категории и известные даты. Отсутствующая дата источника остаётся неизвестной. Сырые личные переписки не индексируются.

Чат поддерживает цену, расстояние, тип жилья, поиск имени/упоминания, этаж и направление окон. Даты и гостей он не меняет. Условия из чата можно отменить отдельно; последующая ручная правка сохраняется. Изменения открытого окна фильтров накладываются на актуальное состояние по отдельным полям, чтобы не потерять ответ чата.

Из интерфейса убраны дубли быстрых кнопок и подробного переключателя допуска, повтор категории внутри карточки, повтор рекомендации внутри чата и инструкции установки моделей. Фильтры и режим допуска находятся в одном окне, активные ограничения можно снять отдельно. На телефоне карта/чат раскрываются по кнопке и не отодвигают выдачу на целый экран.

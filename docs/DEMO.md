# Локальная демонстрация кабинетов

Учебные кабинеты создаются напрямую в PostgreSQL из **JSON**, без SQLite-драйвера в обычном приложении. Исходник `data/demo/fixtures.json` содержит только вымышленные аккаунты, адреса, объявления, координаты, цены, поездки и вопросы. Учебные пароли публичны.

Нужны Node.js 24+, JDK 21, Maven 3.9+ и PostgreSQL 16 (Docker или собственный `DATABASE_URL`). Python 3.11+ нужен для помощника. Из корня:

```sh
npm ci
npm run build:all
npm run demo:setup
npm run demo:start
```

Откройте http://127.0.0.1:8082.

| Роль | Почта | Пароль |
|---|---|---|
| Путешественник | user@demo.test | UserDemo2026! |
| Отельер | host@demo.test | HostDemo2026! |

Используйте этот экземпляр только локально: эти пароли опубликованы в репозитории.

## Подготовка и сохранение изменений

`demo:setup` создаёт `.local/demo-seed.json` с явными `kind` / `is_demo`, базовой датой и SHA-256 синтетических fixtures. Источник не меняется; существующий целевой файл не перезаписывается. Будущие и прошедшие поездки рассчитываются относительно дня подготовки по часовому поясу Пусана. `--date` позволяет зафиксировать дату.

`demo:start` включает кабинеты на порту 8082, задаёт `DEMO_MODE=true`, `DEMO_SEED_PATH` и отдельную схему `demo`. Новый `DemoSeedImporter` после Flyway загружает аккаунты, объявления, поездки и вопросы через PostgreSQL в одной транзакции. Пароли хешируются Java `Passwords`: PBKDF2-HMAC-SHA256, 600000 итераций, случайная соль. Сессии, загрузки и история ИИ не копируются.

Импорт разрешён только в явно выбранной отдельной схеме, только при `DEMO_MODE=true`. При первом импорте таблицы кабинетов должны быть пустыми. После успешного импорта маркер запрещает повторную перезапись: сохраняются изменения отельера, пароли, заявки и история. Ошибка откатывает всю транзакцию. Одновременные импорты сериализуются блокировкой PostgreSQL.

`demo:start` использует `dist/`, `ACCOUNT_MODE=true`, `LAB_MODE=false`, `AI_PROVIDER=rules`, каталог `data/verified-hotels.json` и `.local/demo-uploads/`. Порт задаётся `DEMO_PORT`, схема — `DEMO_DB_SCHEMA`. Публичные реальные данные и явно учебные объявления сохраняют разные признаки происхождения. Цена учебного объявления не является ценой реального отеля.

## Новый независимый показ

```powershell
npm run demo:setup -- --date 2026-10-29 --output .local/demo-next.json
$env:DEMO_SEED_PATH = '.local/demo-next.json'
$env:DEMO_DB_SCHEMA = 'demo_next'
npm run demo:start
```

Не подставляйте основную схему и не заменяйте существующие данные. Для резервного копирования нужны схема PostgreSQL и `.local/demo-uploads/`: JSON содержит только исходные учебные данные.

`demo:seed` также создаёт новый JSON-образец, по умолчанию `.local/demo-seed.json`. Обе команды отказываются перезаписывать файл. Для повторного запуска уже подготовленного экземпляра нужна только `npm run demo:start`.

## Состав

- Два аккаунта с адресами `.test`, пустыми телефонами и опубликованными учебными паролями.
- Восемь объявлений: семь опубликованных и один черновик, все с `demo=true`; фотографии отсутствуют. Координаты учебные, у одного опубликованного варианта расположение неизвестно.
- Разные кровати, диваны, спальни и футоны; детская кроватка не добавляет основных спальных мест. У черновика расстановка может отсутствовать.
- Шесть заявок: две ожидающие, одна подтверждённая, одна отменённая, две завершённые. Историческая цена завершённой поездки сохраняется отдельно.
- Шесть вопросов: три без ответа и три с ответом.
- Ноль исходных сессий, загруженных фотографий и запусков помощника.

В кабинете отельера можно изменить расположение и кровати, сохранить объявление, открыть его повторно и сравнить варианты. Неизвестные значения не становятся подтверждениями. Публикация требует заполненной расстановки и достаточного количества основных спальных мест.

## Проверки

```sh
npm run demo:test
npm run backend:test
```

Node-проверки проверяют JSON, SHA-256, даты, отказ от перезаписи и прежний SQLite-образец совместимости. `DemoSeedImporterTest` работает на настоящем PostgreSQL и проверяет атомарность, пароли, защиту схемы, восстановление после перезапуска и сохранение правок. Тесты переноса SQLite сохранены отдельно.

## Перенос старой SQLite

`data/demo/preview.sqlite3` и `scripts/demo-data.mjs` оставлены как **эталон совместимости старого импорта**. Штатные `demo:setup` и `demo:start` их не используют.

SQLite JDBC отсутствует в обычном runtime JAR. Для явно нужного переноса прежней базы соберите специальный вариант:

```sh
mvn -B -f server/pom.xml -Plegacy-import package -DskipTests
```

Затем задайте `LEGACY_DB_PATH` и отдельную PostgreSQL-схему, передайте окружение процессу и запустите сервер. Источник открывается только на чтение; существующие строки PostgreSQL не перезаписываются. Не задавайте одновременно `LEGACY_DB_PATH` и `DEMO_SEED_PATH`. Без профиля явный legacy-импорт останавливает запуск с понятным сообщением. `DEMO_DB_PATH` в новом скрипте отклоняется, чтобы старый путь не был случайно принят за JSON.

# Экологические и общественные условия района

Отдельный скрипт `scripts/assess-area.ts` собирает датированный снимок для координат объекта. Он не формирует общий балл «качества района», не использует демографические характеристики и не подменяет статистику преступности количеством камер или полицейских участков.

## Источники

**Воздух — Open-Meteo Air Quality API, модель CAMS Global.** Используются PM2.5, PM10 и NO₂ в мкг/м³ и готовый US AQI провайдера. Глобальная модель имеет пространственное разрешение 0,4° (около 45 км), исходный временной шаг 3 часа. API возвращает интерполированное текущее значение с собственным временем. Это не показания ближайшей станции и не измерение конкретной улицы; близкие отели могут получить одинаковые данные. [Документация провайдера](https://open-meteo.com/en/docs/air-quality-api).

Сохраняются текущие значения и отдельный почасовой прогноз: время в UTC, время получения, координаты модельной ячейки, исходный URL и единицы. Текущий снимок не заменяет прогноз на даты поездки. US AQI не пересчитывается из одного мгновенного значения PM2.5 и не смешивается с европейским индексом.

Атрибуция: Open-Meteo и Copernicus Atmosphere Monitoring Service (CAMS), данные [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Бесплатный API предназначен для некоммерческого использования; для коммерческого размещения нужно проверить подходящий тариф. [Условия Open-Meteo](https://open-meteo.com/en/terms).

**Преступность — исторические районные сведения полиции и отдельно проверенная граница.** Каталог [data.go.kr](https://www.data.go.kr/data/15101812/openapi.do) также описывает тематический слой SafeMap о плотности зарегистрированных происшествий. [SafeMap API](https://www.safemap.go.kr/dvct/data/selectDataAPIDetail.do?dataApiId=11) указывает ключ и WMS-слой. [Министерство внутренних дел Кореи](https://mois.go.kr/frt/sub/a06/b10/safemap/screen.do) описывает процедуру получения ключа; этот WMS-источник не используется для вычисления рейтинга.

WMS-цвета не превращаются автоматически в вероятность преступления. Если для точки нет проверенного импорта с точной географией, `safety.status = "unknown"`: «Недостаточно проверенных районных данных о преступности. Безопасность не оценена». Это не положительная и не отрицательная оценка района.

Фактически скачан без ключа официальный [CSV полиции по районам за 2025 год](https://www.data.go.kr/data/3074462/fileData.do), включая столбец `부산 해운대구` (Хэундэ). Прямая [ссылка на CSV](https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000007729840&fileDetailSn=1&insertDataPrcus=N) вернула HTTP 200. Сохранён оригинал `data/korea-crime-2025.csv` (кодировка EUC-KR) и SHA-256 в нормализованных записях. Публикация датирована 16 октября 2026 года. Без пересчёта извлечены две исторические величины за весь 2025 год: 1 635 зарегистрированных краж и 2 разбойных нападения во всём Хэундэ-гу. Это отдельные категории, а не общее число преступлений и не личный риск.

Граница получена из [OSM relation 4062934](https://www.openstreetmap.org/relation/4062934): `name=해운대구`, административный код `2635000000`, уровень 6, версия 20 от 28 июня 2026 года. Точный полигон собран из связанных outer ways по идентификаторам узлов, имеет 171 точку и сохранён в `data/haeundae-boundary.geojson`. Подмена прямоугольником не используется. ## Запуск

Требуются установленные зависимости проекта. Дополнительные пакеты не нужны.

Все отели из текущего `data/demo.json`:

```powershell
node --import tsx scripts/assess-area.ts --source-archive .local/air-source-responses.json.gz
```

Результат: `data/area-assessments.json` с `assessments[]`, `generatedAt`, регионом и списком пропущенных объектов `skipped`. Каждая запись содержит `hotelId`, название, `[longitude, latitude]`, `assessedAt`, `airQuality` и `safety`. Серверный контракт: `GET /api/areas/:hotelId` → `{ "assessment": объект_или_null }`.

Одна точка в Пусане, отдельно от основной базы:

```powershell
node --import tsx scripts/assess-area.ts --lat 35.16 --lon 129.16 --id busan-point --name "Точка в Пусане"
```

Результат по умолчанию: `.local/area-single.json`. Координаты в этом примере иллюстративны и не обозначают выбранный отель. Для объявления следует передать его проверенные координаты.

Доступные параметры:

- `--input path.json` — другой файл с массивом `hotels` и полями `id`, `name`, `coordinates`.
- `--output path.json` — отдельный путь результата.
- `--refresh` — повторный запрос воздуха, минуя свежий кеш.
- `--safety path.json` — нормализованные официальные исторические данные, проверенные оператором. По умолчанию при наличии читается `data/official-safety-evidence.json`; он содержит две записи по Хэундэ за 2025 год.
- `--offline path.json` — ответы API из файла, без сети.
- `--now ISO_TIMESTAMP` — фиксированное время только для offline-тестов.
- `--source-archive path.json.gz` — сохраняет точные тела использованных ответов, URL, время получения и SHA-256 каждого ответа; SHA-256 самого архива добавляется в итоговый отчёт. Offline-архив имеет `synthetic: true`.

Запросы выполняются последовательно с паузой 200 мс, тайм-аутом 20 секунд и пределом тела 1 МиБ. Проверяются HTTP-статус, JSON Content-Type, корректность JSON и структуры данных; перенаправления не допускаются. Ответы кешируются по точному URL в `.local/area-cache`; свежий кеш используется 3 часа. При чтении проверяются сохранённый URL, SHA-256 точного тела и время получения. Повреждённый или старый кеш без этих реквизитов отклоняется с сообщением и требует повторного сетевого получения; он не используется как резервный источник.

Ответы старше 6 часов получают статус `stale`; `refreshAreaFreshness` повторяет эту проверку при чтении сохранённого снимка, отдельно для текущих значений и прогноза, и отклоняет некорректное будущее время. При сетевой ошибке предыдущий проверенный кеш остаётся датированным и также помечается `stale`; без него возвращается `unknown`. Частичные данные получают `partial`, отсутствующие значения сохраняются как `null`, а не нули. Неверные единицы и модельная ячейка дальше 80 км от запроса не считаются доказательством. Порог защищает от ответа для другого города; он не увеличивает детализацию модели.

## Прогноз на даты поездки

Запрос содержит `current` и `hourly` для PM2.5, PM10, NO₂ и US AQI, `forecast_days=5`, `domains=cams_global`, `timezone=Asia/Seoul`, `timeformat=unixtime`. Часы нормализуются в ISO UTC. API допускает разные горизонты, но нельзя предполагать наличие прогноза за пределами фактически полученных часов. [Параметры Air Quality API](https://open-meteo.com/en/docs/air-quality-api).

В `airQuality.forecast` сохраняются:

- `status`, `fetchedAt`, `sourceUrl`, `requestUrl`, `modelCoordinates`, `model`, `resolutionKm`;
- `issuedAt: null`: API не сообщил время выпуска модельного прогона; время скачивания не выдаётся за время выпуска;
- `timezone: "UTC"`, `tripTimezone: "Asia/Seoul"`, `intervalSeconds: 3600`;
- `units`: `pm25`, `pm10`, `no2` — `µg/m³`, `usAqi` — `USAQI`;
- `coverageStart` (включительно), `coverageEnd` (исключительно);
- `hourly[]`: отдельные `{time, pm25, pm10, no2, usAqi}`, максимум 168 записей;
- ограничения и ошибка, если данные не прошли проверку.

Нормализация проверяет координаты, время получения, ожидаемые единицы, равенство длин массивов и порядок времён. Дубли, перестановка, нецелый час, более 168 записей или времена за пределами допустимого горизонта приводят к `unknown`. Пробелы в последовательности и пропущенные показатели остаются явными, со статусом `partial`; они не заполняются соседним значением. Если длина одного массива не соответствует временам, вся эта метрика становится `null`, чтобы не сдвинуть значения относительно часов.

Для подбора сервер должен преобразовать даты поездки в интервал **[заезд 00:00 Asia/Seoul, выезд 00:00 Asia/Seoul)** и найти каждую ожидаемую часовую запись с числовым US AQI. Например, 25–27 октября в Пусане соответствуют интервалу `[24 октября 15:00 UTC, 26 октября 15:00 UTC)` и 48 часам. Конечный час выезда не входит в поездку.

Сравнение с порогом требует полного покрытия US AQI и свежести не более 6 часов. Пропуск или выход за горизонт сохраняет unknown; текущий снимок не подставляется в прогноз. Границы coverageStart/coverageEnd не доказывают полноту. Partial из-за NO₂ не отменяет отдельно проверенное полное покрытие US AQI. Скрипт готовит доказательства, Java применяет критерий.

Один неудачный запрос не отменяет остальные. Объекты с некорректными координатами и дубликаты идентификаторов попадают в `skipped`. Полный результат собирается перед записью файла; не запускайте два процесса, пишущих в один и тот же путь. Java API читает отчёт при каждом запросе: после обновления достаточно перезагрузить карточку.

## Импорт официальных свидетельств

Формат — `{ "version": 1, "records": [...] }`. Схема строго проверяется в `shared/area.ts`. Каждая запись должна включать:

- `id`, `sourcePublisher`, официальный HTTPS `sourceUrl` на домене `.go.kr`;
- `publishedAt` в формате `YYYY-MM-DD`, `retrievedAt` как ISO UTC;
- `period.from` и `period.to` — период исторических сведений;
- `geography.name`, `geography.code`, `geography.sourceUrl`, `geography.type` (`Polygon` или `MultiPolygon`), `geography.coordinates` — точная геометрия в GeoJSON-порядке `[lon, lat]`, внешние кольца и при необходимости внутренние отверстия, все кольца замкнуты; источник границы — официальный корейский домен или конкретная relation OSM;
- `metric`: `reported_incidents`, `crime_density_grade` или `crime_rate_per_100000`;
- `metricLabel`, `sourceRecord` с точной строкой/столбцом, числовое `value`, `unit`, описание `methodology`, массив `limitations`; опционально SHA-256 исходного файла `sourceFileSha256`;
- `verification = "operator-checked-official-source"` — оператор проверил оригинальную публикацию, период, легенду и соответствие границы показателю.

В поставляемом импорте используются реальные значения из сохранённого официального CSV; синтетические значения находятся только в тестах. Домен источника и флаг оператора не доказывают подлинность сами по себе: приложение проверяет структуру и попадание точки в географию. Подлинность и смысл новых публикаций нужно проверять при подготовке очередного импорта, а не присваивать им этот статус автоматически.

Запись применяется только внутри полигона и вне его отверстий; точки на границе остаются без этого свидетельства. Подмена сложной административной границы прямоугольником недопустима. Нельзя присвоить всему району показатель отдельного дорожного сегмента WMS. Для слоя без точной геометрии и документированной метрики запись не импортируется.

Применимое свидетельство меняет статус на `evidence`, но не на «безопасно». Период остаётся видимым; приложение не пересчитывает историческое число в вероятность происшествия или индивидуальный риск. Несколько публикаций сохраняются отдельно, без суммирования несопоставимых данных. Демографические признаки, количество полиции, камер и ресторанов не входят в допустимые метрики.

### Необязательное сопоставимое значение для относительного показателя

Существующие районные абсолютные числа краж и разбойных нападений **не подтверждают относительную безопасность**, в том числе на будущие даты. В поставляемых реальных данных нет искусственно рассчитанного comparator или балла.

Для будущего импорта официального нормированного показателя предусмотрены `rateDefinition` и `comparator`. Это контракт данных, а не автоматически найденная статистика:

- Исходная запись обязана иметь `metric = "crime_rate_per_100000"` и `unit = "incidents_per_100000_residents"`.
- `rateDefinition` содержит `categoryCode`, `denominatorBasis = "annual_average_resident_population"`, `methodologyId`.
- `comparator` содержит те же `metric`, `categoryCode`, `period`, `unit`, `denominatorBasis`, `methodologyId`, а также `value` и `baselineRegion: {name, code}`. Код базы сравнения должен отличаться от кода самого района.
- Происхождение базы сравнения задаётся независимо: `sourcePublisher`, официальный `sourceUrl`, точный `sourceRecord`, `publishedAt`, `retrievedAt`, `verification = "operator-checked-official-source"`.

Схема отклоняет сравнение абсолютного количества с частотой, разных категорий преступлений, периодов, единиц, знаменателей или методик. Число происшествий должно быть целым. Дата публикации сравнивается с датой получения в календаре `Asia/Seoul`, одинаково в TypeScript и Java; публикация после получения недопустима. При дате публикации/получения comparator в будущем он исключается из применимого свидетельства. Период должен закончиться раньше дня заезда и не более чем за два года до него. Сравнение частот, когда оно обосновано, описывает только конкретный зарегистрированный тип происшествий и не означает «район безопасен» или прогноз личного риска.

## Детерминированный offline-ввод

В файле требуется объект `responses`, ключи — идентификаторы отелей. Каждое значение содержит `fetchedAt` и `response` с оригинальной структурой Open-Meteo: координаты, `current_units`, `current`. Для отсутствующего идентификатора создаётся `unknown`, данные другой точки не переиспользуются.

```powershell
node --import tsx scripts/assess-area.ts --input .local/test-hotels.json --offline .local/test-air.json --now 2026-10-24T09:00:00Z --output .local/test-assessments.json
node --import tsx --test tests/area.test.ts tests/air-source.test.ts
```

Тестовые концентрации и полигоны находятся только в `tests/area.test.ts`. Проверяются даты, единицы, пропуски, устаревание, несоответствие координат, категории US AQI, неизвестная безопасность, строгий импорт, границы и отверстия полигонов и полный offline-проход CLI.

## Реальная проверка подключения

В первом проходе 24 октября 2026 года выполнены настоящий HTTP-запрос Open-Meteo для точки Пусана 35.16° N, 129.16° E и пакетный проход по 24 отелям. Для всех 24 получены текущие PM2.5, PM10, NO₂, US AQI и прогноз по 120 часам; пропусков и недоступных ответов не было. Снимок сохранён в `data/area-assessments.json`. После импорта CSV и проверки полигона все 24 точки сохраняют статус безопасности `evidence` с двумя историческими районными свидетельствами без comparator. Общая безопасность по-прежнему не оценивается баллом и не гарантируется.

25 октября 2026 года выполнено последовательное обновление для **96 из 96** объектов текущего каталога, без пропущенных объектов и сетевых ошибок. Итоговый отчёт создан в 09:05:13 UTC. Сырые ответы сохранены в `data/air-source-responses-2026-10-25.json.gz`; точные URL, время и хеши доступны для воспроизведения. Проверка повторно нормализует каждый из 96 исходных ответов и сравнивает результат с отчётом.

На момент обновления текущие четыре показателя доступны у 96/96 объектов. У всех 96 прогноз имеет статус **partial**: по 120 часовых строк, но последние два часа не содержат концентраций, последний час также не содержит US AQI. Это 11 424 заполненных значения US AQI из 11 520 ожидаемых, а не полное покрытие. Общий временной интервал `[2026-10-24T15:00Z, 2026-10-29T15:00Z)` соответствует 25–30 октября по Пусану. Наличие границ этого интервала не подтверждает каждый час поездки. В ответах две пары координат модели; различия координат API не повышают заявленное разрешение CAMS Global до точности улицы.

96/96 объектов имеют два районных исторических свидетельства о преступности; **0/96** имеют сопоставимые нормированные частоты. Поэтому безопасность для фильтра остаётся неподтверждённой. Сверка с CSV и тесты логики не являются проверкой района на месте, текущего личного риска или воздуха у окна.

Исправлены найденные ошибки: сравнение корейской даты публикации с UTC-сутками, допустимость будущего времени при повторном чтении, отсутствие проверки целостности кеша, неограниченное чтение HTTP-тела, округление дробного шага времени Java до целого и применение статистики, чей период ещё не завершился к дню заезда. Проверки включают 21 тест TypeScript (в том числе воспроизведение всех 96 ответов) и 4 отдельных Java-регрессии; общий набор выполняется при интеграции.

## Итог фильтра при неполных данных

Нормализация сохраняет исходные available/partial/stale/unknown и не заполняет пропуски. Java сначала строит строгую оценку на даты поездки, затем отдельная BinaryDecisionPolicy возвращает только match/mismatch. Исходные статус и объяснение доступны через evidenceStatus и sourceExplanation; предположение помечается assumed=true и decisionBasis="estimate".

Для воздуха фильтр проходит только при полном пригодном прогнозе на даты поездки. Текущий US AQI может сохраняться в диагностике, но не подтверждает будущее пребывание и не превращает `unknown` в `match`. При недостатке данных бинарный итог — `mismatch` с исходным `evidenceStatus: "unknown"` и объяснением нехватки данных. Это не утверждение, что воздух плохой. Обычная отметка свежести отчёта использует 6 часов; возраст снимка и основание решения остаются видимыми.

Для безопасности отсутствие сопоставимых частот сохраняет исходную неизвестность, а итог фильтра — mismatch с пояснением недостаточности данных. Это не вывод об опасности района. Обязательный mismatch исключает вариант, желательный влияет только на порядок. Полная политика: [VERIFIED_DATA.md](VERIFIED_DATA.md).

# Шум на даты поездки

Модель оценивает риск внешнего шума в конкретном месте и в даты поездки. Она не рассчитывает децибелы и не подтверждает звукоизоляцию номера. Java вычисляет результат при поиске; `shared/noise.ts` содержит проверяемую TypeScript-реализацию тех же правил.

## Что сохранено

`data/noise-context.json` содержит реальные геометрии 865 автомобильных дорог OSM в демонстрационном районе Хэундэ, три официальных мероприятия и **ноль измерений трафика**. `data/noise-events.json` — небольшой воспроизводимый список событий с источниками. Национальный выходной без локальной программы не считается событием, вызывающим шум.

- [21-й Busan Fireworks Festival](https://www.busan.go.kr/eng/bsevents/1752782): 7 ноября 2026, основное шоу 19:00–20:00 по Корее. [Организатор](https://www.busanfireworks.com/en/) называет Dongbaekseom среди площадок. Используется реальная [OSM-точка острова](https://www.openstreetmap.org/node/7866912597), **не подтверждённая точка запуска**. Потенциал high основан на типе программы. Радиус 1500 м — открыто указанное, акустически не проверенное допущение. Подготовительная программа 14:00–19:00 не подменяется основным шоу.
- [Haeundae Sand Festival 2026](https://www.busan.go.kr/eng/bsevents/1725994): 15–18 мая 2026. Используется реальный полигон [Haeundae Beach](https://www.openstreetmap.org/way/107531972). Потенциал moderate, радиус 300 м — допущения для фестивальной программы. Даты выставки скульптур до 14 июня не продлевают активный фестивальный риск. Время задано с точностью до дня; это не утверждение о круглосуточных выступлениях. Отдельная площадка на Gunam-ro не локализована этим полигоном.
- [12-й Haeundae Light Festival](https://www.busan.go.kr/eng/bsevents/1705138): 29 ноября 2025 — 18 января 2026, освещение 18:00–23:00. Исторические даты сохранены. Световая инсталляция имеет потенциал low и условный радиус 200 м. Она не приравнивается к фейерверку и не подтверждает общий низкий риск. Сохранён общий интервал фестиваля; повторяющееся расписание по часам пока не моделируется.

Календарь частичный: отсутствие совпадений означает отсутствие подходящей записи, а не доказанное отсутствие мероприятий. Никакие даты 2025 года не перенесены автоматически в 2026 год.

## Откуда брать движение

[Busan Traffic Information Center](https://its.busan.go.kr/) публикует транспортную информацию. [Городские обследования](https://www.busan.go.kr/depart/trafficcensus0101) содержат счёт автомобилей по направлениям на отдельных участках и в отдельные исторические дни; они не являются прогнозом на будущую поездку.

[UTIC](https://www.utic.go.kr/guide/utisRefTraffic.do) требует ключ и авторизацию IP и прямо указывает, что API не предоставляет объём движения. Скорость или цвет дорожного затора нельзя выдавать за число автомобилей. [Официальный ITS Open Data](https://www.its.go.kr/opendata/intro) требует регистрацию ключа; сопоставление детекторов и стандартных дорожных link ID с OSM геометрией должно проверяться при импорте. В проекте не настроен рабочий доступ к счётчикам, поэтому загрузка дорог неизвестна.

Разрешён импорт проверенных наблюдений. Каждый `roadId` должен точно совпадать с геометрией из `roads`. Импорт не выполняет приблизительное сопоставление по похожему названию. Нельзя импортировать ежедневную среднюю скорость как почасовой счёт или старое наблюдение как будущий прогноз.

## Контракт

Корневой объект: `schemaVersion: 1`, `region: "Пусан"`, `timeZone: "Asia/Seoul"`, `generatedAt`, `bbox`, `roads`, `trafficObservations`, `events`, `coverage`, `assumptions`. Полная строгая схема — `noiseContextSchema` в `shared/noise.ts`.

`source` всегда содержит HTTP(S) `url`, `publisher`, `retrievedAt` с часовым поясом и необязательное `description`. Координаты — `[longitude, latitude]`.

Дорога: `id`, `name`, `roadClass`, `geometry` из двух или более точек, `oneWay`, `source`. Класс дороги и близость — отдельный базовый фактор, не измеренная загрузка.

Наблюдение: `id`, `roadId`, `startsAt`, `endsAt`, необязательные `vehicleCount`, `speedKph`, `lanes`, обязательное `direction` (`one_direction`, `both_directions`, `unknown`), `source`, `limitations`. Интервал от минуты до 24 часов. Нужен хотя бы счёт или скорость. `lanes` — число полос именно в области счёта, включая оба направления при `both_directions`. Без известного направления и числа полос нагрузка остаётся unknown. Конец измерения не может быть после получения источника. Будущие наблюдения не поддерживаются.

Событие: `id`, `name`, `eventType`, `startsAt`, `endsAt`, `timePrecision`, `geometry` (`Point` или закрытый `Polygon` с возможными отверстиями), `influenceRadiusMeters`, `noisePotential`, `influenceBasis`, `source`, `geometrySource`, `limitations`, `status`. Источники расписания и геометрии независимы. `influenceBasis` явно объясняет допущение о радиусе и потенциале.

`coverage.traffic.status`: unavailable, partial или complete. `coverage.events.status`: partial или complete. Для обоих есть `reason`, `sourceUrls`; для complete обязательны `verifiedAt`, `startsAt`, `endsAt`, `geometry: Polygon`, `verificationSource`. Доказательство должно охватывать весь срок поездки и территорию, а отметка проверки и источник проверки должны быть не старше 6 часов и не из будущего. Точка на границе полигона не подтверждает полноту. Полнота трафика означает проверенную полноту перечня всех дорог, способных влиять на эту территорию; полнота событий — всех влияющих событий, включая площадки за её пределами. Простое обведение имеющихся данных полигоном не доказывает полноту.

Текущий импорт не имеет таких доказательств: traffic unavailable, events partial. Даже полный интервал измерений одной известной дороги не позволяет объявить общий low при неизвестной полноте дорожного перечня. Дополнительно полигон проверки трафика должен покрывать окружение отеля с запасом более 300 м до любой границы; недостоверная или будущая запись дороги блокирует вывод о полноте всего перечня.

## Прозрачные допущения модели

- Даты задают полуоткрытый интервал `[заезд 00:00, выезд 00:00)` в Asia/Seoul. Мероприятие в момент начала дня выезда уже не пересекает поездку.
- Расстояние до дороги считается до ближайшей точки реального сегмента, не только до его вершин. Близкие дороги: до 300 м. Базовая близость high до 50 м, moderate до 150 м, low до 300 м. Этот фактор сам по себе не даёт итоговый риск.
- Счёт нормализуется: `vehicleCount / intervalHours / lanes`. До 300 автомобилей на полосу в час — low, до 700 — moderate, выше — high. Это эвристические пороги, не санитарные нормативы и не оценка дБ. Скорость сохраняется как контекст и не заменяет счёт.
- При high-нагрузке риск high до 75 м, moderate до 150 м, далее low. При moderate-нагрузке риск moderate до 150 м, далее low. Эти расстояния — модельные допущения; ветер, рельеф, фасад и экранирование не учтены.
- Наблюдения учитываются только при пересечении с реальными датами измерения. Историческое движение не переносится на будущую неделю. Для подтверждения low нужны интервалы без пробелов для каждой близкой дороги на весь срок поездки и оба направления, кроме односторонней дороги.
- Событие учитывается при одновременном пересечении времени и модельной зоны. Внутри полигона расстояние равно нулю. High-потенциал даёт high во внутренней половине радиуса и moderate во внешней. Moderate и low сохраняют свой уровень. Cancelled, tentative и holiday не создают вклад.
- Итог high при любом high-вкладе; иначе moderate при любом moderate. Low возможен только при полном проверенном покрытии движения и событий. Иначе unknown. Для пожелания `low_noise`: high/moderate означает несовпадение по оценочному риску, low — совпадение в рамках модели, unknown — недостаток сведений.
- При выбранном пожелании тишины Java учитывает градацию в ранжировании: moderate получает штраф 2 балла, high — 3. При обязательном пожелании оба уровня исключают вариант. Для остальных условий сохраняются +3 за совпадение, −2 за несовпадение и −1 за неизвестность; это веса подбора, а не шкала здоровья или безопасности.

## Запуск и импорт

```powershell
npm run noise:assess
npm run noise:assess -- --validate data/noise-context.json
npm run noise:assess -- --hotel node-368952148 --check-in 2026-11-07 --check-out 2026-11-08
npm run noise:assess -- --traffic .local/verified-traffic.json --events data/noise-events.json
npm run noise:assess -- --traffic .local/verified-traffic.json --traffic-coverage .local/traffic-coverage.json --event-coverage .local/event-coverage.json
node --import tsx --test tests/noise.test.ts
```

Файл traffic имеет корень `{ "trafficObservations": [...] }`, файл events — `{ "events": [...] }`. Каждый coverage-файл содержит сам объект покрытия. Команда полностью проверяет вход перед заменой публичного `data/noise-context.json`; секретные ключи и неочищенные ответы API в него не записываются. Команда `--validate` только проверяет файл. Синтетические наблюдения находятся исключительно в тестах.

Для проверки UI: Westin (`node-368952148`), 7–8 ноября 2026, пожелание тихого отдыха. Официальное событие попадает в даты и место; интерфейс должен показывать источник, оценочный характер риска и условный радиус. В обычный день без совпавшего события отсутствие трафика должно оставаться неизвестностью.

# Проверка уточнений и повторного подбора

Дата: 25 октября 2026 года. Регион приложения — Пусан. Проверки кода и HTTP выполнены на сохранённых данных, без обращения к реальным отельерам. Аккаунты, объявления и ответы в новых сценариях вымышленные.

## Что реализовано

Проверка выбранных условий внутри одного объявления, личный вопрос о решающем неизвестном условии, структурированный ответ владельца, история исправлений и повторный поиск с исходными датами и гостями. Доступны три условия: семейное размещение, окна во двор, путь до номера без ступеней. Для исследовательского каталога без подключённого владельца создаётся только черновик вопроса.

Ответ остаётся заявлением владельца. Поиск использует обезличенные сведения об условии; личное дополнение путешественника и текст переписки не включаются в публичный результат или контекст помощника.

## Найденные ошибки и исправления

- Положительный ответ на часть поездки больше не подтверждает всю поездку. Отрицательное условие блокирует вариант при пересечении хотя бы одного дня, включая выезд.
- Противоположные ответы с пересекающимися периодами сохраняют конфликт. Истечение срока одного ответа его не разрешает. Разные непересекающиеся периоды сами по себе конфликтом не считаются.
- Новое «неизвестно» не восстанавливает старое «да». Применимая неопределённость из другого диалога также сохраняется. Старый ответ из другой области действия или вне дат поездки не портит применимый положительный профиль.
- Изменение материальных параметров объявления инвалидирует прежние ответы. Обратное изменение не возвращает им действительность; косметическая правка названия или фото её сохраняет.
- Карточка учитывает выбранные пожелания так же, как выдача. Неизвестные справочные условия, которые пользователь не выбирал, больше не меняют её итоговую оценку.
- Снимки поиска и история помощника привязаны к аккаунту или анонимной сессии. Чужие идентификаторы не дают доступа; старые записи без владельца не открываются через API.
- Смена аккаунта очищает приватное состояние интерфейса. Возврат фокуса в неизменившуюся сессию сохраняет незавершённую форму.
- Защита от противоречий в ответе различает выбранное условие и оговорки о других удобствах. Нейтральное пояснение допускается: значение явно выбирает владелец. Свободный текст автоматически не считается независимым доказательством.
- Чтение кабинета использует пакетную загрузку историй и повторно использует сведения внутри одного запроса. История и разграничение доступа сохраняются.

## Расширенная выборка

Итоговые модульные наборы прошли: 156 TypeScript, 134 Java, 182 Python сервиса вида, 29 Python помощника, 5 парсера шума и 4 проверки демобазы — **510 тестов**. Проверка типов TypeScript, основная сборка, лабораторная сборка и упаковка Java завершились успешно. Параметризованные случаи ниже входят в эти тесты, а не прибавляются к числу 510.

- Согласованность пояснений владельца: 79 независимо размеченных синтетических формулировок и 237 вариантов регистра, пробелов и переноса строки, всего 316 проверок. Это регрессионный корпус, а не оценка точности на случайной выборке реальных ответов.
- Эталон логики периодов сравнивает результат по отдельным дням с рабочим алгоритмом интервалов: 324 одиночных случая, 34 992 пары в обоих порядках, 2 268 добавлений отрицательного условия, 3 888 проверок изоляции признаков и неприменимых ответов.
- Совместимость обязательных условий проверена на 27 синтетических объявлениях: 378 классификаций для сочетаний трёх признаков и двух режимов допуска.
- Пакетное чтение проверено на 411 диалогах одного владельца и 1 233 версиях ответов, плюс отдельном чужом объявлении. Проверяются граница пакета SQL, порядок, полная история, разные даты и смена области действия между запросами.
- HTTP-сценарий уточнений создаёт четыре аккаунта и два объявления. Последний прогон: 10 этапов, 88 HTTP-запросов, успешный перезапуск. Проверяет роли, повторные запросы, конкуренцию редакторов, исправления, неизвестность, сроки, конфликты, приватность и сохранение после перезапуска. Число запросов может меняться из-за опроса состояния помощника.
- Регрессия кабинетов: 8 этапов, 56 HTTP-запросов, две загрузки PNG и семь проверок декодированных пикселей. Проверены сохранение фото после перезапуска, порядок, права доступа, вопросы, заявки и выход из аккаунта.
- Общая HTTP-матрица: 102 поиска и 9 792 классификации отелей. Отдельная матрица режимов: 324 сочетания, 30 924 классификации.
- Сервис вида: 288 запросов по 96 объектам, по три пары «этаж — дата» на объект. Это не полное декартово произведение этажей и дат. Осмотренных на месте номеров — **0**.
- Браузер: вопрос путешественника → отрицательный ответ и конфликт → исправление владельца → история двух ответов → пересчёт с сохранёнными датами, гостями и обязательным условием. Проверены мобильный экран 390 × 844, отсутствие горизонтального переполнения и смена сессии между вкладками.

## Производительность и ограничения

В локальном синтетическом замере на 500 диалогах и 1 500 версиях ответов медиана формирования кабинета владельца снизилась примерно с 707 до 118 мс, путешественника — с 513 до 70 мс. Это замер на одной машине, без сетевой задержки, а не гарантия времени ответа в эксплуатации. Результаты до и после оптимизации побайтно совпали: SHA-256 `ad65288e96199206f9a6e037924395aea13bef1124276c1559fce4b1cd022cf2`. Размер ответа не сокращался; масштабирование на десятки тысяч диалогов отдельно не проверялось.

Проверка формулировок ограничена распознаваемыми конструкциями русского языка. Она не гарантирует понимания произвольного текста, истинности заявления или доступности номера на даты. Источники реального каталога, геометрический расчёт вида, модель воздуха и признаки шума сохраняют прежние ограничения. Качество локальной языковой модели не оценивалось: интеграционные сценарии используют режим правил.

## Как повторить

```powershell
npm test
npm run backend:test
npm run agents:test
npm run demo:test
npm run build:all
npm run lab:build
python -X utf8 scripts/verify-clarifications-integration.py --port 8084
python -X utf8 scripts/verify-accounts-integration.py --port 8083 --report .local/accounts-http-report.json
python -X utf8 scripts/verify-http-integration.py --app-port 8090 --lab-port 8091 --view-port 8092 --keep-running --report .local/http-report.json
python -X utf8 scripts/verify-search-modes.py --app http://127.0.0.1:8090 --lab http://127.0.0.1:8091
```

`--keep-running` оставляет три изолированных сервера для следующей проверки; их PID записаны в `.local/http-smoke/<время>/processes.json`. После проверки остановите именно эти процессы. Для проверки сервиса вида отдельно выполните команды из его README. Если пользовательская версия уже запущена, собирайте кандидат в отдельную папку и передайте её через `--app-dist`; не перезаписывайте работающую сборку и базу.

Скриншоты, подробные локальные отчёты, тестовые базы и инструменты дизайн-аудита находятся в игнорируемой `.local/` и не входят в публикацию.

Финальные HTTP-прогоны уточнений и кабинетов использовали JAR с SHA-256 `bf805a97c7146c1c61bd1d47c3b1257771aa770a7b622b54ab04d662e0c1b246`. При обновлении пользовательской демоверсии проверено побайтное соответствие сериализованных строк восьми прежних таблиц кабинетов; новая схема добавлена без изменения этих записей. Повторный визуальный просмотр после запуска на 8082 был заблокирован политикой URL встроенного браузера; доступность этого экземпляра подтверждена HTTP, визуальные проверки относятся к изолированному запуску того же интерфейса.

## Дополнение: ошибочная подсказка о датах

Пользователь сообщил об ошибке при датах 26.10.2026–10.11.2026, двух взрослых и отсутствии детей. Эти значения проходят схему. Найдены две ошибки интерфейса: общий отказ всей схемы, включая скрытые в этом окне пожелания, всегда отображался как ошибка дат/гостей; сохранённое сообщение не пересчитывалось при редактировании полей. Скрытое состояние исходной пользовательской вкладки по скриншоту неизвестно, поэтому конкретное отклонённое поле не установлено.

Теперь отображается причина по полю, сообщение пересчитывается после изменений, сводка дат не зависит от корректности пожеланий. При отправке берутся текущие значения элементов формы, чтобы незавершённая синхронизация React не отправляла старую дату. Пожелания и их обязательность сохраняются. Добавлены три регрессионных теста с показанными датами, ошибками скрытых полей, исправлением значений и отправкой актуального содержимого формы; полный TypeScript-набор — 159 тестов.

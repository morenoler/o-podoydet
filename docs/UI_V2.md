# Интерфейс FigCraft v2

Реализация основана на локальном `opodoydet-search-v2.figcraft` и двенадцати PNG-макетах `opodoydet-*-v2.png` предоставленных владельцем проекта. Используется Nunito Sans с локальными кириллическими и латинскими файлами шрифта. Цвета: основной синий `#163E8E`, текст `#172C4C`, фон `#F7F9FC`, море `#DCEEF4`.

## Запуск и изоляция

Основной сайт: npm run build:all, затем npm start; адрес http://127.0.0.1:8080/. Кабинеты, объявления, поиск, профиль и редактор используют общий интерфейс. Отдельная [демонстрационная БД](DEMO.md) запускается на порту 8082 с основной сборкой.

Лаборатория: npm run lab:build и npm run lab:start; адрес http://127.0.0.1:8081/. Её база, сборка и папка фотографий отделены от основного сайта.

## Структура

- `shared/ui/design-v2.css`, `Modal`, `AccommodationPhoto` — общие компоненты и базовое оформление.
- `app/layout/SiteHeader` — общая навигация обеих сборок; общая оболочка подключает авторизацию.
- `features/search`, `features/hotels`, `features/map`, `features/advisor` — поиск, карточки, рабочая карта и помощник.
- `features/account` — кабинеты, профиль и редактор из отдельных секций. CSS кабинетов ограничен их контейнером.
- `features/listings` — галерея, заявка и вопросы публичного объявления.
- `features/favorites` — избранное в браузере, отдельно для каждого аккаунта и гостя; синхронизации между устройствами нет.

Начальная страница показывает каталог, если даты ещё не выбраны, и результаты реального API при корректных датах. Старый пошаговый ввод доступен на `/trip` и `/wishes`. Кабинеты, объявления и их API включены также в основной версии. Общие компоненты поиска применяются к обеим сборкам.

## Фотографии и реальные данные

Четыре изображения извлечены без изменений из предоставленного FigCraft-файла. Привязка сделана по точному идентификатору каталога в `shared/lib/hotelPhotos.ts`:

- Shilla Stay Haeundae (`way-627150752`): фасад из [Chudu24](https://khachsan.chudu24.com/hanquoc-busan/ksqt.5622.khach-san-shilla-stay-haeundae-busan.html), номер из [Regent Holidays](https://www.regent-holidays.co.uk/holiday/south-korea/shilla-stay-haeundae/).
- Toyoko Inn Busan Haeundae 2 (`way-627350916`): [официальная страница отеля](https://www.toyoko-inn.com/eng/search/detail/00256/).
- Grand Josun Busan (`way-843161717`): [официальная страница отеля](https://gjb.josunhotel.com/facilities/subMain.do).

Для остальных объектов и вымышленных демонстрационных объявлений показывается заглушка. Название не используется для подбора чужого фото. Отельер может добавить до шести фото с компьютера (JPEG/PNG до 8 МиБ) или по HTTPS-ссылке. Есть превью, прогресс, повтор загрузки, изменение порядка и удаление. Файлы хранятся отдельно от сборки, порядок — в SQLite.

Цены, рейтинги, число вариантов и поездки из макета не перенесены в данные. Каталог без цены не показывает выдуманную стоимость. Заявки сохраняют серверный расчёт в KRW. Этаж и восемь направлений окон доступны гостю как сведения отельера; пустые значения отображаются «Не указано». Свободные заметки для подбора остаются закрытыми. Контракт и миграция описаны в `ACCOUNTS.md`.

Карта использует сохранённую геометрию OpenStreetMap, реальные координаты и рассчитанные маршруты. Масштабирование, перемещение, выбор объекта и мобильное переключение списка/карты работают. У объектов без координат маркер не выдумывается. Фильтры соответствуют поддерживаемым условиям API; неподдерживаемые примеры из макета (завтрак, бесплатная отмена) не выдают фиктивных результатов.

## Проверки интерфейса v2 до добавления загрузок

Автотесты: 83 TypeScript, 69 Java, 28 Python. Отдельный API smoke на порту 8082: 112 проверок ролей, прав доступа, приватности, новых полей, фотографий, вопросов, заявок и исторической стоимости. После остановки QA-сервера SQLite подтвердила сохранение данных. Скрипт проверки находится в игнорируемом `.local/v2-api-smoke.mjs`.

В браузере проверены ширины 375, 390, 768, 1024 и 1440 px: поиск, карточка отеля, публичные объявления, профиль, кабинеты и редактор. Горизонтальное переполнение в проверенных состояниях отсутствует. Измерения сохранены в `.local/ui-v2-layout-checks.json`, скриншоты — в `.local/ui-v2-screenshots/`.

Пройдены первый визит без дат, вход обеими тестовыми ролями, выход, фильтры, сравнение, выбор/масштаб карты, мобильное переключение списка и карты, запуск помощника в режиме правил, избранное после перезагрузки и его разделение между аккаунтами. Проверены Escape, видимый клавиатурный фокус, ошибка пустой даты, несуществующее объявление, пустое избранное и загрузка. Через мобильный редактор сохранены существующие этаж/направления; повторное открытие публичного объявления показало те же значения. Новые заявки для UI-проверки в базе 8081 не создавались; жизненный цикл заявок и ответов проверен отдельно на 8082.

`npm run lab:build` (включает TypeScript), сборка Java, отдельная основная frontend-сборка и `git diff --check` прошли. Основной `dist/index.html` сохранил исходный SHA-256 `F11EF3C57F06898023D9252568138A98F11AD69D3D6225E239D9EF50D8A1710E`. Vite сообщает только о комментариях `@__PURE__` внутри установленного Zod; на успешную сборку это не влияет.

Ограничения: фотографии каталога есть у трёх точно сопоставленных отелей, избранное хранится на устройстве, фото объявления добавляются ссылкой. Цены/наличие внешнего каталога, онлайн-оплата и восстановление пароля не подключены. Локальная LLM сохраняет существующую интеграцию; в этой проверке помощник запускался в режиме правил.

## Основная версия и загрузка фотографий

Кабинеты и объявления перенесены в основную сборку с общими провайдерами и маршрутами. VITE_LAB_MODE управляет только лабораторными инструментами. Добавлены файловая загрузка, локальное превью, прогресс, повтор попытки, изменение порядка и удаление фото из объявления. JPEG с EXIF-ориентацией корректно поворачивается перед сохранением.

Проверены основной сервер 8080 и основная сборка с отдельной демонстрационной БД на 8082. В браузере пройден выбор трёх PNG с компьютера, перестановка обложки, удаление фото, повреждённый файл и повтор попытки, блокировка сохранения до разрешения ошибки, сохранение и перезагрузка. Порядок после перезагрузки совпал; публичная галерея открывается, Escape возвращает фокус. Ширины редактора 375, 390, 768, 1024 и 1440 px без горизонтального переполнения. Проверены вход обеими ролями и история поездок.

Автотесты: 91 TypeScript, 73 Java, 28 Python, 4 проверки генератора демо-БД. Новые серверные тесты включают права, реальные форматы, размеры, EXIF, приватность и сохранение файлов и порядка после перезапуска.

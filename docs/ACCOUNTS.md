# Личные кабинеты, объявления и фотографии

Модуль включён по умолчанию в основной и лабораторной версиях. Его можно явно отключить через ACCOUNT_MODE=false. GET /api/health сообщает accountsEnabled. Лабораторные опыты включаются независимо через LAB_MODE=true.

Основная версия открывается на http://127.0.0.1:8080, лаборатория — на порту 8081. Учётные записи создаются через регистрацию. Отельер видит вопросы и заявки только по своим объявлениям. Отдельная вымышленная БД для проверки кабинетов опубликована вместе с кодом: [инструкция и тестовые пароли](DEMO.md). Она не устанавливается в рабочую базу автоматически.

## Границы модулей

`server/.../accounts/auth` содержит аутентификацию, профили и репозитории пользователей/сессий; `listings`, `questions`, `bookings` — отдельные прикладные сервисы и репозитории. `accounts/web/AccountApi` отвечает за HTTP и передаёт действия сервисам. `accounts/persistence/AccountDatabase` владеет отдельным соединением и границей транзакций. Новая схема находится в `accounts-schema.sql` и применяется только при включении модуля. Новые таблицы `account_*` находятся в SQLite, выбранной через DB_PATH, отдельно от подтверждённого каталога.

Это модульное приложение с одним процессом Java и одной локальной базой. Авторизация, объявления и заявки не смешаны с ИИ-подбором и его `Store`/`SearchService`. Запуск отдельных микросервисов для этих локальных сценариев не требуется.

Созданные объявления не присваивают владельца объектам OpenStreetMap и не становятся подтверждёнными фактами для ИИ. Они показываются в каталоге предложений отельеров и участвуют в подборе через отдельный адаптер `accounts/search/OwnerListingSearchProvider`. Карточки отмечают, что сведения предоставлены владельцем и не прошли независимую проверку. Старые экспериментальные `/api/questions` и `/api/drafts/*` закрыты при включённых кабинетах; лабораторные прогоны ИИ остаются доступны.

## Контракт HTTP

Все адреса ниже имеют префикс `/api`. Изменения, кроме фотографий, отправляются методом POST с `Content-Type: application/json`; ошибки возвращают `{error: string}`. Коллекции возвращаются массивами. Общие TypeScript-типы находятся в `shared/account.ts`.

- `GET /auth/me` → `{user: AccountUser | null}`.
- `POST /auth/register` с `{name,email,password,role}` → `{user}`. Роли: `user`, `host`.
- `POST /auth/login` с `{email,password}` → `{user}`; `POST /auth/logout` с `{}` → `{ok:true}`.
- `POST /account/profile` с `{name,phone,about}` → `{user}`. Почта и роль не меняются через профиль.
- `GET /listings` → опубликованные объявления; `GET /listings/:id` → одно опубликованное объявление.
- `GET /listings/:id/questions` → публичные отвеченные вопросы; скрытые вопросы доступны только автору и владельцу объявления. В публичных ответах удалён идентификатор пользователя, оставлено первое имя.
- `POST /listings/:id/questions` с `{text}` → вопрос; `POST /listings/:id/bookings` с `{checkIn,checkOut,guests,note}` → заявка. Доступно путешественнику.
- `GET /account/bookings`, `GET /account/questions` → только собственные записи путешественника.
- `POST /account/bookings/:id/cancel` с `{}` → отменённая заявка.
- `GET /host/listings`, `GET /host/listings/:id` → собственные объявления отельера вместе с закрытым `searchProfile`.
- `POST /host/listings`, `POST /host/listings/:id` с `HostListingInput` → созданное/обновлённое объявление вместе с закрытым `searchProfile`.
- `POST /host/photos` — бинарное тело JPEG/PNG с соответствующим Content-Type; ответ 201 `{url:string}`. Требуется сессия отельера и допустимый Origin.
- `GET /host/questions`, `GET /host/bookings` → вопросы/заявки только по своим объявлениям.
- `POST /host/questions/:id/answer` с `{answer}` → вопрос с ответом.
- `POST /host/bookings/:id/status` с `{status}` → обновлённая заявка.

`ListingInput`: `title` (3–160), `description` (20–5000), `city` (2–100), `address` (3–250), `roomType` (2–100), `capacity` (целое 1–20), `pricePerNight` (целое 1–100000000 в KRW), `amenities` (до 12 строк по 1–80 символов), `status` (`draft` или `published`). Валюта KRW; сумма рассчитывается на сервере. Поля `hostId`, `userId`, `totalPrice`, `role` не принимаются от клиента как основание полномочий.

## Закрытые сведения для подбора

`HostListingInput` расширяет публичные поля необязательным `searchProfile: {notes}`: свободный текст до 6000 символов, доступный только владельцу объявления. Пустой профиль допустим; обновление без `searchProfile` сохраняет предыдущие закрытые сведения.

В версии интерфейса v2 `floor` (целое от −3 до 200 либо `null`) и `windowDirections` (уникальный набор из восьми значений: `north`, `north_east`, `east`, `south_east`, `south`, `south_west`, `west`, `north_west`) стали публичными полями объявления. Отельер может выбрать несколько направлений, гость видит значения с указанием источника. Отсутствующие сведения отображаются как «Не указано». Аддитивная миграция один раз переносит сохранённые значения из прежнего закрытого профиля; очистка поля не приводит к повторному импорту старого значения. Старый формат входных данных поддерживается, публичные поля имеют приоритет, пропуск значения сохраняет предыдущее.

Публичное поле Фотографии: до шести ссылок HTTPS, локальных путей /images/... или файлов /uploads/listings/<uuid>.jpg|png. Отельер загружает JPEG/PNG с компьютера, видит превью и прогресс, меняет порядок кнопками и удаляет фото из объявления. Первое фото становится обложкой. Загрузка должна завершиться до сохранения формы. Обновление старым клиентом без photos сохраняет имеющиеся ссылки. При отсутствии или ошибке загрузки показывается нейтральная заглушка.

Файлы хранятся в UPLOADS_PATH (по умолчанию .local/uploads), вне dist. Сервер проверяет фактический формат, ограничивает входной файл 8 МиБ, размер изображения 20 млн пикселей и сторону 12000 px, уменьшает до 2400 px и перекодирует без исходных метаданных. Ссылки на загруженные фото разрешены только их владельцу. Публичная раздача возможна, пока фото прикреплено к опубликованному объявлению; неопубликованные фото доступны только владельцу. Удаление из формы применяется при сохранении объявления, порядок сохраняется в SQLite. Неиспользуемые файлы физически остаются в хранилище; автоматическая очистка пока не реализована. Резервируйте DB_PATH и UPLOADS_PATH совместно.

Закрытый профиль хранится в отдельной таблице `account_listing_search_profiles`. Изменение объявления и его профиля происходит в одной транзакции. Публичные ответы `/listings`, история поездок и вопросы не читают эту таблицу.

В текущей версии локальный разбор текста распознаёт сведения о семейном размещении, окнах во двор, пути до номера и до пляжа без ступеней, расстоянии до пляжа пешком. Неоднозначные или противоречивые сведения не считаются подтверждением пожелания. Это ограниченный разбор свободного текста; прочие детали сохраняются, но пока не превращаются в самостоятельные критерии поиска. Этаж и стороны света учитываются по отдельным полям при соответствующем запросе гостя, например «Этаж не выше 3. Окна на юг». Без отметки «желательно» такие явно распознанные условия обязательны.

Поиск и ИИ-помощник получают результат сопоставления с пожеланием и пометку об источнике. Исходные заметки не возвращаются в гостевых ответах, исключённых результатах, контексте ИИ или диагностике. Публичные этаж, направления окон и фото доступны в проекции объявления для поиска. Подбор не публикует географические координаты или маршрут для объявления без этих данных. Снимок поиска сохраняет внутренние разобранные сведения на момент запроса, чтобы последующее редактирование объявления не меняло уже сформированный контекст помощника. Изолированные сценарии `/api/lab/search` продолжают использовать только лабораторные примеры.

## История аренды и ограничения

Заявка создаётся со статусом `pending`. Отельер может подтвердить (`confirmed`) или отклонить (`cancelled`) её. Подтверждённую поездку можно завершить (`completed`) только после даты выезда, либо отменить. Пользователь может отменить ожидающую заявку или подтверждённую поездку до начала проживания. Завершённая или отменённая запись сохраняется в истории и не может снова стать подтверждённой.

Даты трактуются в часовом поясе каталога `Asia/Seoul`. Разрешены будущие поездки от 1 до 90 ночей с заездом не дальше двух лет. Вместимость проверяется сервером. Повторная активная заявка того же пользователя на те же даты отклоняется. На пересекающиеся даты нельзя подтвердить две брони одного объявления; проверка и изменение статуса выполняются в одной транзакции. Каждое объявление трактуется как одна единица размещения, без многономерного складского учёта.

История хранит снимок названия, адреса и цены на момент заявки: последующее редактирование объявления не меняет условия старой поездки. Нет платёжной интеграции, списания денег и связи с внешней системой наличия номеров. Подтверждение отельером относится к заявке платформы.

## Сессии и проверка

Пароли хранятся как PBKDF2-HMAC-SHA256 с 600000 итераций и индивидуальной случайной солью. Пробелы в паролях сохраняются. Случайные 256-битные сессионные токены передаются в `HttpOnly; SameSite=Lax` cookie; в БД сохраняется SHA-256 токена. Сессия действует 30 дней, при повторном входе прежний токен текущего браузера отзывается; выход удаляет сессию. При HTTPS можно задать `SESSION_COOKIE_SECURE=true`. Изменения проверяют Origin и JSON Content-Type; вход и регистрация ограничены 30 попытками на адрес за 5 минут. Неверный пароль и отсутствующий пользователь дают одну ошибку.

`npm run backend:test` проверяет регистрацию, вход, выход, сессионные cookie, роли, изоляцию владельцев, сохранение истории и сессий после перезапуска, проверки форм, снимок цены, запрет двойного подтверждения, невозможность преждевременного завершения, SQL-инъекции в логине, Origin, хеширование и включение в основной копии, явное отключение модуля и загрузку фотографий.

Подтверждение электронной почты, восстановление пароля и внешние уведомления не подключены.

## Проверка интерфейса

1. Соберите основную версию: npm run build:all. Запустите npm start или используйте отдельную [демонстрационную БД](DEMO.md).
2. Войдите отельером, откройте объявление, выберите несколько фотографий с компьютера. Дождитесь загрузки, поменяйте порядок, удалите лишнее и сохраните. Перезагрузите страницу и проверьте галерею.
3. Войдите путешественником, откройте опубликованное объявление, задайте вопрос и отправьте заявку. Проверьте историю, ответ отельера и изменение статуса.
4. Проверьте профиль, клавиатуру и узкий экран. Ошибки загрузки можно повторить или удалить; незавершённая загрузка блокирует сохранение.

Автоматические проверки: npm run check, npm test, npm run backend:test, npm run agents:test. Серверные тесты проверяют права на фото, формат и размеры, сохранение порядка после перезапуска и доступность после публикации/удаления.

проверку каждого поля. Поле категории `evidenceStatus=verified` отражает
сверку с опубликованным источником. Оно не подтверждает наличие на даты,
цену, весь путь без ступеней или вид из окна конкретного номера.

`data/verified-access-research.json`; получены 24–25 октября 2026 года.

No.2 достаточных сведений для категорий нет. Даты получения не являются
датами публикации или проверки на месте. Сроки повторной проверки фактов
хранятся в `expiresAt`; аудит их не продлевает.

## Сбор характеристик

В текущем коде уже есть ограниченный сборщик официальных страниц:
`scripts/import-official-hotel-pages.ts`. Он проверяет принадлежность
страницы отелю и категории, извлекает вместимость и условия, сохраняет
URL, время получения, SHA-256 ответа и контрольную сумму проекции.
`data/official-import-report.json` сообщает 14/14 успешных источников
для двух отелей: 13 страниц категорий и один FAQ.

В `data/official-source-cache/index.json` сохранены проекции версии
`official-html-v3`. Полный HTML не распространяется: офлайн можно проверить
целостность проекции и повторить её импорт, но нельзя повторить извлечение
из исходного HTML или пересчитать SHA-256 исходного ответа. Доступность
страниц сейчас не проверялась. Сохранённые категории Marriott и Lotte не
получили новую дату из-за прежних HTTP 403 и JavaScript-страниц.

При повторной проверке 14/14 контрольных сумм проекций совпали. Все 13/13
категорий уже присутствуют и в исследовании, и в подготовленном каталоге;
их `projectionSha256` сохранены. Повторный `mergeSnapshots` с этими
14 проекциями не меняет исследование, включая правила из FAQ.
Пропущенных категорий в сохранённом кеше не обнаружено; повторный импорт
этого кеша не увеличит покрытие.

`agents/engine.py` занимается подбором и объяснением на уже переданном
контексте. Автономного агента, который собирает недостающие категории
остальных 870 объектов Пусана, в текущем наборе нет. Исправление запуска
или тестов не закрывает этот пробел. Вымышленные категории не добавлялись,
географический объём существующих каталогов не менялся.

## Исправленные ошибки

### Байты корейского CSV

Сохранённые свидетельства ссылаются на SHA-256
`a82e8806bd662594f9172a3c790d33b2fa55de1045a8fc703fc697de0c85789b`.
Ему соответствует исходный EUC-KR файл `data/korea-crime-2025.csv`
размером 29 018 байт с 39 окончаниями CRLF. В прежнем Git blob было
28 979 байт с LF и SHA-256
`8c9705a7e66f6832b855e23882e2d220e8e5398285168cfdf6c02ab2686231bd`.
Windows восстанавливал CRLF при checkout, скрывая проблему.

В `.gitattributes` добавлено `data/*.csv -text`; CSV сохраняется с исходными
CRLF. Хеши доказательств не переписывались под преобразованный файл.
Проверены одинаковые Git blob hashes при `core.autocrlf=true` и `false`,
а также существующая сверка SHA-256 и значений CSV в `tests/area.test.ts`.
Это проверка байтов и сохранённых значений, не повторная проверка статистики
у издателя. Другие исходные снимки не обновлялись.

### Ложные HTTP 429 в window-view

Причиной был порядок освобождения семафора, а не накопление счётчика
rate limiter: сервер отправлял ответ, а затем выполнял `busy.release()`.
Клиент, уже получивший ответ, мог успеть отправить следующий запрос до
освобождения слота. Ошибка затрагивала и настоящие последовательные запросы.

Теперь слот расчёта освобождается перед отправкой ответа, включая ошибки.
Невалидный результат приложения по-прежнему даёт обезличенный HTTP 500.
HTTP-тесты создают отдельное приложение и сервер для каждого случая.
Регрессионный тест удерживает запись завершённого ответа и проверяет,
что следующий расчёт уже разрешён. Отдельный тест сохраняет HTTP 429
для действительно одновременных расчётов.

### Файлы IDE

Удалены пять отслеживаемых файлов `.idea/`; каталог добавлен в `.gitignore`.

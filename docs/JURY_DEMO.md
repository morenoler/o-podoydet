# Показ для жюри: от неизвестного условия к результату

Запуск: `docker compose --profile jury up --build --wait`. Откройте [демонстрацию](http://127.0.0.1:8081/jury-demo.html). Страница не требует регистрации, модели или ключа. Все действия выполняет настоящий Spring API, результаты не подставляются в интерфейсе.

1. Нажмите **«Найти номер во двор»**. Поиск выбирает поездку на три ночи через неделю, двух взрослых и обязательные окна во двор. На новой схеме совпадений нет: в обеих вымышленных категориях это неизвестно.
2. Нажмите **«Ответить за учебного отельера»**. Планировщик формирует открытые вопросы, симулятор «Учебной гавани» отвечает по сохранённому сценарию. Из ответа «Все окна номера выходят во двор» выделяется утверждение о категории. Сохраняются цитата, время, источник, `demo=true` и `simulated=true`.
3. Нажмите **«Проверить результат»**. Повторяется тот же запрос поиска. Теперь подходит одна учебная категория. Раскройте **«Посмотреть ответы API и происхождение сведений»**, чтобы увидеть реальные ответы сервера и цепочку доказательств.

Повторный запуск сохраняет ответы: первый поиск тогда уже покажет один вариант. Страница объясняет это, а не изображает повторный переход с нуля. Для новой схемы без удаления истории используйте отдельное имя проекта Compose из [RUNNING.md](RUNNING.md).

На основном сайте http://127.0.0.1:8080 симуляция недоступна. Защита `DemoHostGuard` требует лабораторный режим, политику `demo` и объект `demo-*` с явной учебной меткой. Учебные ответы не подтверждают реальные гостиницы. Личные уточнения реальных кабинетов имеют отдельную авторизацию и область действия.

Для автоматического прогона того же сценария:

```sh
docker compose --profile jury --profile checks run --rm jury-check
```

При локальном запуске отдельного экземпляра Spring с теми же настройками:

```sh
python -X utf8 scripts/jury-demo.py --base http://127.0.0.1:8081
```

Скрипт сохраняет cookie между запросами, проверяет метки вымышленного происхождения и завершается с ошибкой при неверном результате. Он не очищает БД и не отправляет сообщений внешним отельерам.

# Расположение отелей и городской каталог Пусана

Проверка 27 октября 2026 года. База сравнения: `origin/main` — `92411201a4544ed357b34ff9e0e244f0f46d10b2`; изменения продолжают отдельную ветку `feat/smarter-hotel-search`. Main повторно получен с GitHub перед публикацией.

## Исправления и поведение

- «Хочу отель в центре города» раньше не меняло условия. Теперь это близость к явно названному ориентиру Сомён. Кафе, рестораны и ещё десять типов расположения задаются через чат и ручные фильтры. Общий механизм не вызывает LLM.
- Условия объединяются по типу места: добавление кафе сохраняет метро и центр. Отмена чата и сохранение открытой модалки учитывают ручные изменения отдельно для каждого типа.
- Карточки показывают только точки, которые прошли тот же фильтр расстояния и актуальности, что сервер. Сортировка исправлена: использует отобранные доказательства, а не первую историческую точку из массива.
- Отрицания, альтернативы «или», минуты ходьбы, вид из окна и заведение внутри отеля не превращаются в подтверждённую близость. Неподдержанная часть перечисляется в ответе.
- Новые реальные объекты карты доступны даже без собранной категории номера, в отдельном списке. Вымышленных комнат и вместимости для них нет. Отель с неподходящей или устаревшей собранной категорией не возвращается через этот список. Текст заглушки комнаты не участвует в поиске по объекту.
- Ошибка порядка координат границ нового набора исправлена до подключения: `[west, south, east, north]`, как ожидает карта. Расстояния вычисляет код, округляя вверх до метра.
- Условие не подтверждают неизвестный статус, истёкшие/будущие даты, синтетический объект, некорректные координаты или подменённый URL источника.
- Полный прогон обнаружил ошибку точности времени: PostgreSQL округлял наносекунды вверх до микросекунд, и только что сохранённое противоречащее свидетельство могло временно считаться будущим. Время теперь обрезается до микросекунд до записи в JSON и SQL. Регрессионный тест с фиксированными часами воспроизводит прежний сбой и проверяет конфликт двух источников без ожидания.
- При подготовке коммита обнаружена угроза воспроизводимости на Windows: `core.autocrlf` мог менять байты исходных JSON и нарушать SHA-256. Для сырых снимков отключено преобразование строк, для конфигурации и извлекателя закреплён LF. Проверена отдельная выгрузка из Git index с включённым `core.autocrlf=true`.

В исходном сочетании центр + кафе + ресторан найден 71 объект без собранных категорий. С кафе до 300 м и метро до 800 м — 66. Проверены десктоп 1440×1000, мобильный экран 390×844 и прокрутка модалки с доступной кнопкой применения. Исправлены обрезанная подпись сортировки и повтор единицы измерения в доступном имени поля. Онлайн-подложка карты недоступна в этой среде: проверены сохранённая схема, маркер и ссылка OSM, а не загрузка внешних тайлов.

Логи и снимки приёмки сохранены локально в игнорируемой `.local/busan-nearby-review/`; полный журнал Java — `.local/nearby-backend-full-verify-final.log`. Это проверка логики и согласованности снимков, а не процент фактической точности гостиничных сведений.

Воспроизводимая HTTP-проверка отдельной запущенной копии:

```powershell
python -X utf8 scripts/verify-busan-nearby.py --base http://127.0.0.1:8094 --report .local/busan-nearby-review/http-quality.json
```

Она проходит реальную последовательность чата, все 12 типов, накопление/удаление, неподдержанные альтернативы, отсутствие вымышленных комнат, неизвестную цену и независимо пересчитывает расстояние каждой возвращённой точки. Тест не отправляет сообщений отельерам.

## Границы результата

Состав набора, исходные ответы, хеши и знаменатели находятся в [BUSAN_DATA.md](BUSAN_DATA.md) и `data/busan/quality.json`. В наборе 876 объектов, из них 780 новых; 54 новые записи без названия. Найдены 13 пар возможных дублей, автоматически они не объединены. Число объектов OSM не равно числу всех действующих гостиниц. Официальные категории собраны только у 6/876 объектов (46 категорий), у 870/876 их нет. Категории номеров, прежние маршруты и сведения о шуме сохраняют исходное покрытие Хэундэ. Получение нового снимка карты не продлевает официальные сведения о номерах.

Близость относится к представительным точкам карты. Она не доказывает вход, пешеходный маршрут, доступность для коляски, действующую работу заведения или часы работы. Отсутствие найденной точки означает недостаток подтверждения, а не отсутствие места в действительности. Полевых проверок новых объектов: **0**. Цены, наличие на даты и физические комнаты не проверены. Свободные формулировки за пределами явно поддержанной грамматики требуют уточнения; универсальное понимание любых пожеланий не заявляется.

## Среда запуска

Установленный Docker Desktop не смог запустить движок из-за повреждённого служебного IPC `dockerInference` (ошибка Windows 1920). Точечное удаление не удалось; пользовательские тома, настройки и базы не изменены. Для тестов запущен изолированный PostgreSQL 16.15 из официальной поставки под `.local/`, без установки системной службы, на `127.0.0.1:55441`. Проверки выполнены на PostgreSQL, без SQLite/H2 и пропусков.

Обновлённый сайт работает на `http://127.0.0.1:8094/`, использует отдельную БД `nearby_site`, схему `nearby_site_review` и отдельную папку загрузок. Это новая локальная копия с городским каталогом, без переноса пользовательских аккаунтов из Docker. Ключи LLM для сценария близости не нужны.

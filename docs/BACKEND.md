# Бэкенд Spring Boot

Приложение использует Spring Boot 4.1.2, Java 21, Spring MVC, встроенный Tomcat и Jackson 3. Все HTTP-маршруты обслуживаются Spring; JDK HttpServer в рабочем приложении отсутствует. Доменный расчёт условий остаётся независимым от веб-фреймворка.

## Слои

- `Main` запускает Spring Boot. `BackendConfiguration` создаёт хранилище каталога, разбор пожеланий, оценки района, поиск и помощника. `AccountConfiguration` создаёт хранилище и сервисы кабинетов, объявлений, заявок, вопросов и фотографий.
- `CatalogController`, `SearchController`, `AdvisorController`, `LegacyQuestionsController` и аккаунтный `AccountApi` содержат явные MVC-маршруты. Авторизация и работа с фотографиями отделены от HTTP: cookie и заголовки устанавливает контроллер.
- `application`, `domain` и `advisor` сохраняют правила подбора конкретных категорий номеров, снимки поиска, диалоговые изменения и проверку оснований рекомендаций.
- `Store` и `AccountDatabase` работают с существующей SQLite-схемой и транзакциями через JDBC. Смена фреймворка не требует переноса или пересоздания базы. Spring закрывает оба соединения и останавливает фоновые задания помощника при завершении приложения.
- Python-процесс помощника остаётся вычислительным исполнителем за Java-сервисом `AdvisorService`. Запуск, HTTP API, история и отмена управляются Spring-приложением; Python не поднимает отдельный веб-сервер.

## HTTP и настройки

URL и JSON-контракты интерфейса сохранены. `ApiExceptionHandler` формирует JSON-ошибки; `ApiSecurityFilter` проверяет Origin у изменяющих запросов, включая URL с кодированными символами. JSON-тела ограничены 24 КиБ, фотографии — 8 МиБ. Cookie остаются HttpOnly / SameSite=Lax, с настройкой Secure. Непубличные фотографии доступны только владельцу.

`FrontendController` раздаёт `DIST_PATH` (по умолчанию `dist/`) и поддерживает маршруты React. Отсутствующий API возвращает JSON 404, а не HTML страницы приложения. Выход из каталога и переход через символические ссылки блокируются. Некорректный URL с выходом выше корня Tomcat отклоняет кодом 400 ещё до MVC.

Сохранены ключи `.env`: `PORT`, `DB_PATH`, `DATA_PATH`, `DIST_PATH`, `UPLOADS_PATH`, `ACCOUNT_MODE`, `LAB_MODE`, `FRONTEND_ORIGIN`, `SESSION_COOKIE_SECURE`, настройки источников и ИИ. `BIND_ADDRESS` по умолчанию равен `127.0.0.1`. `.env` подключается как источник Spring-настроек с низким приоритетом; аргументы CLI, JVM, окружение и Spring-конфигурация имеют приоритет. Файл можно отключить свойством `--app.dotenv.enabled=false`.

## Запуск и проверка

Из корня репозитория:

```powershell
npm run backend:build
npm run build
java -jar backend/target/o-podoydet-backend.jar
```

Сохраняются `npm run dev`, `npm start`, лабораторный и демонстрационный запуск. Для прямой Maven-сборки: `mvn -f backend/pom.xml clean package`; для запуска: `mvn -f backend/pom.xml spring-boot:run`. Maven Plugin использует корень репозитория как рабочую папку, чтобы пути к данным и `.env` совпадали с обычным запуском. Проверка Java: `npm run backend:test`.

HTTP-тесты авторизации, кабинетов, загрузок, поиска и чата запускают настоящий Spring Boot / Tomcat на случайном локальном порту и отдельной временной базе. Класс `Api` в `src/test` — только тестовая обёртка для запуска контекста. `SpringRuntimeTest` дополнительно проверяет MVC-регистрацию, закрытие контекста, SPA/статику, ошибки запросов и Origin. Тесты доменных правил выполняются без веб-сервера.

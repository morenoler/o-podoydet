# Бэкенд Spring Boot

Единственный Java API находится в `server/`: Java 21, Spring Boot 3.5.6,
Spring MVC, Tomcat, Jackson 2 и PostgreSQL 16. Подробности ядра знаний,
миграций и API: [server/README.md](../server/README.md).

`OPodoydetApplication` запускает приложение, `DomainConfig` передаёт зависимости
сервисам поиска, кабинетов и помощника. Доменный расчёт не зависит от HTTP.
Данные сохраняются через JdbcClient/JPA и транзакции, схема управляется Flyway.
SQLite используется только как источник явного импорта `LEGACY_DB_PATH`;
исходный файл не изменяется.

## Поиск и чат

`POST /api/search/conversation` последовательно изменяет пожелания пользователя.
Явные `preferenceOverrides` имеют приоритет над прежним свободным текстом.
Сброс в интерфейсе удаляет историю и изменения фильтров из чата, сохраняя ручные
условия, даты и гостей. [Контракт чата](ADVISOR.md).

Поиск возвращает конкретные категории: `roomRecommendations` для совпадения всех
выбранных условий и `roomAlternatives` для допущенных вариантов с оговорками.
Свойства разных категорий не объединяются. Режим explore допускает неизвестные
обязательные условия только как предварительные, verified требует подтверждений.
Идентификатор категории сохраняется в ссылках, сравнении и избранном.

Помощник Python получает снимок окончательного расчёта, включая проекции знаний
и обезличенные уточнения. История хранится в PostgreSQL; снимки поиска и запуски
помощника принадлежат аккаунту или браузерной сессии. Python не обслуживает Java API.
Отдельный сервис `services/window-view` выполняет геометрическую оценку вида.

## Запуск и проверки

```powershell
npm run db:up
npm run build:all
npm start
```

Настройки PostgreSQL: `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`,
`DB_SCHEMA`. Основной сайт, лаборатория и демоверсия используют отдельные схемы.
JAR: `server/target/o-podoydet-server.jar`. Npm-скрипты читают `.env`;
при прямом запуске JAR настройки подключения передаются окружением или Spring.

`npm run backend:test` проверяет запуск и Java API на PostgreSQL 16.
Testcontainers запускает отдельную базу; альтернативно задаются
`TEST_DATABASE_URL`, `TEST_DATABASE_USER`, `TEST_DATABASE_PASSWORD`.
Каждый тест создаёт собственную схему и каталог загрузок. Отсутствие Docker
или PostgreSQL является ошибкой проверки, а не основанием пропустить тест.

Origin проверяется по декодированному маршруту. JSON-запросы и фотографии имеют
ограничения размера, непубличные фото доступны владельцу. Проверки авторизации,
изолированных снимков, импорта, конкурентных операций и диалога выполняются вместе
с доменными тестами. [Результаты проверки миграции](SPRING_MIGRATION_QUALITY.md).

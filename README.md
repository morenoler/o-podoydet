# О!Подойдёт — Пусан

Прототип подбора отелей по проверяемым пожеланиям. Сначала пользователь выбирает **регион, даты и гостей**, затем варианты отдыха, обязательные условия и необязательный текст. Демонстрационная территория — Пусан, район пляжа Хэундэ в Южной Корее.

Отдельный [микросервис вида из окна](services/window-view/README.md) принимает этаж и возвращает JSON с оценкой моря, соседних зданий, достопримечательностей, восхода и заката. Для Хэундэ включён снимок открытых данных; расчёт работает без сети. Python-сервис запускается из `services/window-view` командой `python -m window_view serve`, Java API передаёт запросы через `POST /api/views/estimate`.

![Стартовый экран](docs/preview.png)

Интерфейс: React + TypeScript + Vite. **Бэкенд: Java 21**, JDK HttpServer, Jackson. **База: SQLite 3** через JDBC, отдельный файл `.local/busan.sqlite3`. Node.js используется для интерфейса и скриптов подготовки данных, сервер API работает на Java.

В базе 24 реальных объекта размещения из OpenStreetMap. Категории номеров, вместимость и ответы отельеров демонстрационные. **Цены, свободные номера и бронирование не подключены.** Безопасность района не считается подтверждённой при отсутствии официальных сведений.

## Запуск

Нужны JDK **21**, Maven **3.9+**, Node.js **24+** и npm. Укажите `JAVA_HOME` на JDK 21; Maven должен быть в `PATH` или `MAVEN_HOME`. На этой рабочей машине также настроен локальный поиск распакованных инструментов в `.local/tools/jdk-21*` и `.local/tools/apache-maven-*`; эти инструменты не входят в репозиторий.

```powershell
npm ci
npm run dev
```

Команда собирает и запускает Java API на `http://127.0.0.1:8080`, затем Vite на **http://127.0.0.1:3000**. Изменения интерфейса обновляются автоматически; после изменений Java перезапустите команду. `Ctrl+C` останавливает оба процесса.

Для собранного приложения:

```powershell
npm run build:all
npm start
```

Откройте **http://127.0.0.1:8080**. В этом режиме Java раздаёт API и файлы `dist/`. Maven создаёт исполняемый `backend/target/o-podoydet-backend.jar`. Его можно запустить из корня проекта командой `java -jar backend/target/o-podoydet-backend.jar` без Node.js. Сервер читает `.env`; переменные окружения имеют приоритет.

## SQLite 3 и настройки

При необходимости скопируйте `.env.example` в `.env`. Секреты, локальные базы, сборки и зависимости исключены из Git.

- `PORT` — порт Java API, по умолчанию `8080`.
- `DB_PATH` — SQLite 3, по умолчанию `.local/busan.sqlite3`.
- `DATA_PATH` — исходный снимок `data/demo.json` для импорта.
- `AREA_DATA_PATH` — отчёт района `data/area-assessments.json`.
- `WINDOW_VIEW_URL` — отдельный Python-сервис оценки вида, по умолчанию `http://127.0.0.1:8011`.
- `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL` — необязательный провайдер Responses API. Без ключа и модели работает ограниченный разбор правилами.

DDL находится в [schema.sql](backend/src/main/resources/schema.sql). В SQLite сохраняются отели, категории, факты, вопросы, предварительные ответы и метаданные. JSON-снимок служит исходными данными, после импорта API читает каталог из базы. Подтверждение ответа выполняется транзакционно, прежние свидетельства остаются в истории. Для независимой демосессии задайте новый путь `DB_PATH`.

Старая `.local/app.sqlite` с Адлером сохраняется на диске и не используется Пусаном. Параметры поиска в браузере также хранятся отдельно от прежней версии.

Это локальный прототип с кабинетом одного оператора. Публикация исходного кода на GitHub не делает кабинет общедоступным веб-сервисом. Для размещения приложения в интернете нужны авторизация и права доступа.

## Подбор и уточнения

1. Разбор объединяет выбранные пожелания и необязательный текст; сценарий сам не добавляет скрытых требований.
2. Подбор проверяет условия в одной категории номера, вместимость и обязательность.
3. Неизвестные, устаревшие и конфликтующие сведения остаются видимыми; подтверждённое нарушение обязательного условия исключает вариант.
4. Условия номера уточняются через демонстрационный кабинет. Географический маршрут берётся из сохранённой карты.
5. Ответ сначала становится черновиком с цитатой. Оператор подтверждает его или явно разрешает конфликт. Повторное подтверждение запрещено.

Планирование проверок детерминированное; реальной отправки сообщений отелям и автономного обхода сайтов нет. Правила поддерживают ограниченные формулировки. Адаптер LLM требует отдельной проверки с реальным провайдером; при сбое используется режим правил с предупреждением.

## Оценка района

```powershell
npm run area:assess
npm run area:assess -- --lat 35.16 --lon 129.16 --output .local/one-area.json
```

Первая команда оценивает координаты всех отелей из `data/demo.json`. Отчёт отображается в карточках через `GET /api/areas/:hotelId`.

- **Воздух:** PM2.5, PM10, NO₂ и US AQI из Open-Meteo / CAMS Global. Модельная сетка около 45 км; это не измерение конкретной улицы и не прогноз на произвольные даты отдыха. Снимок старше 6 часов помечается устаревшим.
- **Безопасность:** без достоверных районных сведений выводится «Не оценена». Поддерживается импорт проверенной официальной статистики с полигоном, периодом, источником и методикой. Количество камер, полицейских участков и демографические признаки не используются как заменители преступности.
- В поставке есть официальные сведения полиции о кражах и разбойных нападениях за 2025 год по всему Хэундэ-гу. Граница района отдельно получена из OSM; её историческое соответствие 2025 году не подтверждено. Это исходные районные показатели, а не вероятность происшествия у отеля.
- Ошибка источника или пропуск не превращаются в нулевое загрязнение либо положительную оценку безопасности. Общий балл района не вычисляется.

Форматы импорта, кеш, offline-режим, происхождение данных и ограничения описаны в [AREA_ASSESSMENT.md](docs/AREA_ASSESSMENT.md).

## Геоданные

Подготовленный снимок Пусана включён в репозиторий, поэтому запуск не требует запросов к картографическим серверам.

```powershell
npm run data:fetch
npm run data:prepare
npm run area:assess
```

Скрипт загрузки ограничен районом Хэундэ и использует кеш с именем региона. Подготовка строит связный пешеходный граф и маршруты до приближённого подхода к пляжу. После изменения исходного каталога используйте новую SQLite-базу для отдельной демонстрации.

Входы в отели и подходы к пляжу не обследованы. Соединительные участки до сети не включены в длину маршрута. Отсутствие лестниц на карте не доказывает доступность для коляски. Окружение показывает возможные источники шума, а не акустические измерения. Названия и расположение объектов реальны, их действующая работа не проверена.

## Проверки и структура

```powershell
npm run check
npm test
npm run backend:test
npm run build:all
```

`backend/` — Java API, SQLite и JUnit; `src/` — интерфейс; `shared/` — типы и вычисления интерфейса/скриптов; `scripts/` — данные, оценка района и запуск; `tests/` — TypeScript-проверки; `data/` — воспроизводимые снимки.

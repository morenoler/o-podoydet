# О!Подойдёт

Поиск жилья по условиям, которые можно проверить: окна во двор, семейное размещение, доступ без ступеней и окружение. Система сохраняет источники, показывает неизвестность и противоречия, а после уточнения пересчитывает результат. Это исследовательский прототип, без оплаты и внешней системы бронирования.

## Запустить для жюри

Нужен только **Docker с Compose v2 или новее**. При первой сборке Docker скачает базовые образы и зависимости; данные уже лежат в репозитории. API-ключи, Ollama, локальные Java, Node.js и Python не нужны.

```sh
docker compose --profile jury up --build --wait
```

- **[Основной сайт](http://127.0.0.1:8080)** — сохранённые данные района Хэундэ в Пусане, поиск, объяснения и кабинеты.
- **[Диалог для жюри](http://127.0.0.1:8081/jury-demo.html)** — три кнопки: поиск с обязательными окнами во двор, ответ вымышленного отельера, повторный поиск. На новой демосхеме результат меняется с 0 на 1. Сценарий полностью синтетический и отделён от реальных объектов.

Для запуска только основного сайта: `docker compose up --build --wait`.
Остановка с сохранением данных: `docker compose --profile jury down`.

[Подробный запуск и проверки](docs/RUNNING.md) · [Сценарий показа](docs/JURY_DEMO.md) · [Устройство бэкенда](server/README.md)

## Что покрыто данными

Основной подробный район — **Хэундэ, Пусан**: 96 объектов в исходной выборке, 46 официально описанных категорий у 6 отелей, приближённые пешеходные маршруты для 95 объектов. Для основного показа Compose выбран этот один район. При обычном локальном запуске доступны также расширенный каталог Пусана из 876 записей OSM и 61 именованная запись Сочи. Запись OSM не доказывает действующее уникальное предприятие. У большинства объектов категории и удобства неизвестны.

Поиск `verified` требует подтверждений; `explore` допускает неизвестное только с явным предупреждением. Описание категории не подтверждает свойства каждого физического номера. Геометрическая оценка вида из окна, шумовые признаки и маршруты не проверены на месте. Цены и наличие реальных номеров на даты не подключены.

## Разработка

React / TypeScript / Node.js 24, Java 21 / Spring Boot 3.5.6, PostgreSQL 16 / PostGIS, Python 3.11+. Для локальной сборки также нужен Maven 3.9+.

```sh
npm ci
npm run build:all
npm start
```

По умолчанию используется разбор по правилам. Контейнерный запуск явно задаёт `AI_PROVIDER=rules`; ключи в образ не попадают. Подключение моделей необязательно: [настройка провайдера](docs/DEEPSEEK_MODULE.md), [.env.example](.env.example). Local и DeepSeek используют `POST /chat/completions`. Совместимый режим `LLM_*` сохраняет `/responses` для поиска и `/chat/completions` для разбора ответа отельера.

Основные проверки: `npm test`, `npm run backend:test`, `npm run agents:test`, `npm run demo:test`. Полный список, PostgreSQL для тестов и расширенная проверка 288 оценок вида из окна — в [RUNNING.md](docs/RUNNING.md).

Презентация и видео: **публичные ссылки ещё не добавлены**. Интерактивный сценарий выше доступен из этой копии проекта; наличие опубликованных материалов не предполагается.

Подробности модулей и прежние отчёты сохранены в [PROJECT_GUIDE.md](docs/PROJECT_GUIDE.md). Результаты исправлений текущего ревью и оставшиеся ограничения собраны в [отчёте качества](docs/QUALITY_REVIEW_2026-10-29.md).

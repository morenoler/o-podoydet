# О!Подойдёт — Пусан

Прототип подбора конкретных категорий номеров по проверяемым пожеланиям. Пользователь выбирает **регион, даты и гостей** и добавляет условия через фильтры или чат. Демонстрационная территория — Пусан, район пляжа Хэундэ в Южной Корее.

![Стартовый экран](docs/preview.png)

Интерфейс: React + TypeScript + Vite. **Бэкенд: Spring Boot 4.1.2 / Java 21**, Spring MVC, встроенный Tomcat и Jackson 3. **База: SQLite 3** через JDBC, отдельный файл `.local/busan.sqlite3`. Spring управляет сервисами, настройками и закрытием ресурсов. Node.js используется для интерфейса и скриптов подготовки данных. [Устройство бэкенда](docs/BACKEND.md).

В каталоге 96 именованных объектов OpenStreetMap: 42 отеля, 42 мотеля, 6 хостелов, 4 гостевых дома и 2 объекта апартаментов. Для 95 рассчитан приближённый маршрут до пляжа; у одного маршрут неизвестен. По официальным источникам подтверждены 38 категорий у 6 отелей, для 17 категорий подтверждено семейное назначение. У остальных 90 объектов категория и вместимость неизвестны. По умолчанию используется `data/verified-hotels.json` с политикой `verified-only`: вымышленные категории и ответы демонстрационного кабинета не влияют на подбор. [Покрытие и ограничения проверенных данных](docs/VERIFIED_DATA.md). **Внешние цены и наличие номеров не подключены.** У объявлений отельеров есть собственная цена и заявки без оплаты; они отделены от исследовательского каталога. Безопасность района не считается подтверждённой при отсутствии сопоставимых официальных сведений.

## Кабинеты и фотографии

Обновлённый интерфейс FigCraft v2 доступен в основной сборке. Путешественник видит поездки, вопросы, избранное и профиль; отельер управляет объявлениями, заявками и ответами. Этаж и стороны света сохраняются в БД, свободные заметки для подбора доступны только владельцу. Фото можно загрузить с компьютера или добавить по ссылке, просмотреть, переставить и удалить. [Контракт и устройство кабинетов](docs/ACCOUNTS.md).

Для проверки опубликована отдельная вымышленная SQLite-база: **[демонстрационный запуск и пароли](docs/DEMO.md)**. Команды npm run demo:setup и npm run demo:start используют основную сборку на порту 8082 и отдельное хранилище. Рабочая БД и её сессии в Git не включаются.

## Запуск

### Помощник подбора

На главной странице открыт чат в боковой панели «Карта / ИИ-ассистент». Пожелания можно добавлять по одному: «рядом с морем», «ещё тихо», «тишина обязательна», «убери условие про пляж». Условия накапливаются и автоматически обновляют основную выдачу; их можно убрать и кнопками над списком. До выбора дат чат сохраняет пожелания, а подбор запускается после заполнения поездки. История и незавершённый черновик сохраняются в текущей сессии браузера.

Чат использует существующий разбор `LLM_*`, если он настроен, иначе явно показывает ограниченный режим правил. Поддерживаются восемь проверяемых критериев каталога. Неизвестные пожелания (например, бассейн, тропический душ или бюджет) не выдаются за применённые фильтры. Обязательность меняется только по явной просьбе пользователя. Подробнее: [диалоговый подбор](docs/ADVISOR.md#диалоговый-подбор).

На странице результатов появился помощник: агент потребностей → агент подбора → агент-критик. Он объясняет отсутствие совпадений, составляет короткий список и показывает предварительные результаты изменения одного условия. Обязательные условия, даты и состав гостей автоматически не меняются. Агентная часть написана на Python, API и расчёты — на Java 21, история — в SQLite. [Запуск, бесплатный режим и устройство](docs/ADVISOR.md).

Для помощника нужен Python 3.11+; путь при необходимости задаётся в `.env` через `ADVISOR_PYTHON`. Он работает без платного API: по умолчанию использует детерминированные роли, опционально — локальную модель Ollama, максимум два вызова за запуск. Обычный подбор работает без Python.

### Тестовая копия с визуализацией ИИ

Лаборатория на **http://127.0.0.1:8081/lab** повторяет страницы основного сайта и позволяет проверить работу каждого агента. Она собирается из той же кодовой базы, но использует отдельные сборку `dist-lab/`, базу `.local/lab.sqlite3` и историю браузера. Основной сайт остаётся на порту 8080. [Установка Ollama, запуск обеих копий и инструкция проверки](docs/LOCAL_AI_LAB.md).

Для экспериментов добавлены шесть вымышленных объявлений: подходящее, с несовпадением условия, неполными данными, устаревшими сведениями, противоречивыми источниками и недостаточной вместимостью. Две кнопки запускают опыты только на этих объявлениях: строгий фильтр оставляет один вариант, а перевод требования к окнам во двор в желательное условие даёт модели выбор между несколькими.

Визуализация разделяет **правила Java → выбор локальной модели → проверку моделью-критиком → программную защиту результата**. Для каждого объявления видны допуск, передача модели и итог. Для каждого условия можно сопоставить необходимое предупреждение с фактическим ответом критика: пропуски и лишние замечания не скрываются. Кнопка «Сравнить с правилами» повторяет запуск на том же снимке данных без ИИ. У каждого этапа есть объяснение задачи, способ проверки и реальные входы/выходы.

Ollama и Qwen 2.5 1.5B работают локально, без платы за API. При ошибке модели явно показывается результат по правилам. Веса, рабочие локальные базы, история запусков и `.env` не входят в репозиторий; скрипты установки и настройки включены.

### Приложение

Нужны JDK **21**, Maven **3.9+**, Node.js **24+** и npm. Укажите `JAVA_HOME` на JDK 21; Maven должен быть в `PATH` или `MAVEN_HOME`. На этой рабочей машине также настроен локальный поиск распакованных инструментов в `.local/tools/jdk-21*` и `.local/tools/apache-maven-*`; эти инструменты не входят в репозиторий.

```powershell
npm ci
npm run dev
```

Команда собирает и запускает Java API на `http://127.0.0.1:8080`, затем Vite на **http://127.0.0.1:3000**. Изменения интерфейса обновляются автоматически; после изменений Java перезапустите команду. `Ctrl+C` останавливает оба процесса.

Для собранного приложения:

```powershell
npm run build:all
npm start
```

Откройте **http://127.0.0.1:8080**. В этом режиме Spring Boot раздаёт API и файлы `dist/`. Maven создаёт исполняемый `backend/target/o-podoydet-backend.jar` через Spring Boot Maven Plugin. Его можно запустить из корня проекта командой `java -jar backend/target/o-podoydet-backend.jar` без Node.js. Сервер читает `.env`; аргументы командной строки, системные свойства и переменные окружения имеют приоритет. Например, `--server.port=8090` меняет порт при прямом запуске.

## SQLite 3 и настройки

При необходимости скопируйте `.env.example` в `.env`. Секреты, локальные базы, сборки и зависимости исключены из Git.

- `PORT` — порт Java API, по умолчанию `8080`.
- `BIND_ADDRESS` — адрес сервера, по умолчанию `127.0.0.1`.
- `DB_PATH` — SQLite 3, по умолчанию `.local/busan.sqlite3`.
- `DATA_PATH` — исходный каталог для импорта, по умолчанию `data/verified-hotels.json`. Если в старой `.env` указан `data/demo.json`, замените путь и перезапустите сервер.
- `AREA_DATA_PATH` — отчёт района `data/area-assessments.json`.
- `NOISE_DATA_PATH` — дороги, наблюдения движения и календарь событий `data/noise-context.json`.
- `TRAFFIC_DATA_PATH` — исторические будничные профили движения KTDB, по умолчанию `data/traffic-ktdb-2024.json`.
- `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL` — необязательный провайдер Responses API. Без ключа и модели работает ограниченный разбор правилами.

DDL находится в [schema.sql](backend/src/main/resources/schema.sql). В SQLite сохраняются объекты размещения, категории, факты, вопросы, предварительные ответы и метаданные. При запуске сервер синхронизирует каталог с JSON-снимком: добавляет новые объекты и обновляет исходные данные, сохраняя вопросы, черновики и подтверждённые ответы. После импорта API читает каталог из базы. Политика `verified-only` допускает в подбор только географические и официальные свидетельства с источником и датой. Сохранённые demo/host-факты остаются историей, не подтверждая реальные условия. Подтверждение ответа выполняется транзакционно, прежние свидетельства остаются в истории. Для независимой демосессии задайте новый путь `DB_PATH`; для обновления каталога достаточно перезапуска сервера.

Старая `.local/app.sqlite` с Адлером сохраняется на диске и не используется Пусаном. Параметры поиска в браузере также хранятся отдельно от прежней версии.

Основная версия включает авторизацию и отдельные кабинеты путешественника и отельера, объявления, вопросы и заявки. Публикация исходного кода на GitHub не запускает веб-сервис. Сервер по умолчанию слушает только 127.0.0.1; размещение в интернете не выполняется.

## Подбор и уточнения

1. Разбор объединяет выбранные пожелания и необязательный текст; сценарий сам не добавляет скрытых требований.
2. Основная выдача и помощник рекомендуют конкретные категории номеров, в которых подтверждены все выбранные условия и вместимость. Проверяются все категории отеля; свойства разных номеров не объединяются. Карточка, сравнение, избранное и ссылка сохраняют выбранную категорию.
3. Исходные неизвестные, устаревшие и конфликтующие сведения остаются видимыми. Отдельная политика даёт каждому условию match/mismatch, а варианту — только «Подходит» или «Не подходит». Предположения отмечены как оценки.
4. Географический маршрут берётся из сохранённой карты, условия номера — из официального исследования конкретной категории.
5. В объявлениях владельцев путешественник задаёт вопрос или отправляет заявку. Отельер отвечает и меняет статус в собственном кабинете. Данные владельца отмечены как его сведения, а не независимо подтверждённые факты.

Доступны восемь пожеланий, включая **безопасность района, чистый воздух и меньше внешнего шума**. В основной подборке должны совпасть и обязательные, и желательные условия. Конкретные категории с несовпадениями по желательным условиям или неполными данными доступны в отдельном свёрнутом разделе. Невыполнение обязательного условия исключает вариант из обоих списков. Объекты без подтверждённой категории не становятся рекомендациями. Оценка района выполняется сервером на даты поездки и не может подтверждаться ответом отельера. Каталог содержит категории (например, Deluxe Twin), а не физические комнаты с номером двери; наличие на даты не проверяется.

![Сравнение воздуха, безопасности и внешнего шума](docs/environment-comparison.png)

Планирование проверок детерминированное; реальной отправки сообщений отелям и автономного обхода сайтов нет. Правила поддерживают ограниченные формулировки. Адаптер LLM требует отдельной проверки с реальным провайдером; при сбое используется режим правил с предупреждением.

Диагностика также использует тип размещения для семейного отдыха, предполагаемую вместимость 2 гостя (4 для апартаментов) и отсутствие отмеченных лестниц либо обход на карте. Такие оценки не подтверждают совпадение в основной подборке. Существующие пригодные доказательства имеют приоритет. Детальные правила и поля объяснений: [VERIFIED_DATA.md](docs/VERIFIED_DATA.md).

## Оценка района

```powershell
npm run area:assess
npm run area:assess -- --lat 35.16 --lon 129.16 --output .local/one-area.json
```

Первая команда оценивает координаты всех отелей из `data/demo.json`. Отчёт отображается в карточках через `GET /api/areas/:hotelId`.

- **Воздух:** PM2.5, PM10, NO₂ и US AQI из Open-Meteo / CAMS Global. Для пожелания нужен свежий почасовой прогноз на всю поездку: от полуночи заезда до полуночи выезда по Пусану. Условие выполнено, если US AQI не превышает 50 во все часы. За горизонтом прогноза исходная оценка неизвестна. Тогда допускается грубая оценка по проверенному текущему снимку не старше 24 часов: US AQI ≤ 50 проходит фильтр. Она явно помечена как предположение и не называется прогнозом на поездку. Сетка около 45 км не различает соседние улицы; обычный срок свежести прогноза — 6 часов.
- **Безопасность:** без достоверных районных сведений выводится «Не оценена». Поддерживается импорт проверенной официальной статистики с полигоном, периодом, источником и методикой. Количество камер, полицейских участков и демографические признаки не используются как заменители преступности.
- В поставке есть официальные сведения полиции о кражах и разбойных нападениях за 2025 год по всему Хэундэ-гу. Граница района отдельно получена из OSM; её историческое соответствие 2025 году не подтверждено. Это исходные районные показатели, а не вероятность происшествия у отеля.
- Ошибка источника или пропуск не превращаются в нулевое загрязнение либо положительную оценку безопасности. Общий балл района не вычисляется.

Для пожелания безопасности требуется официальный показатель на 100 тысяч жителей и сопоставимый региональный ориентир с одинаковыми периодом, категорией и методикой. В поставке есть только абсолютные числа: исходная сравнительная оценка неизвестна, а итог фильтра — mismatch по правилу недостаточности данных. Это не утверждение, что район опасен.

**Внешний шум** зависит от расстояния до дорог, датированных наблюдений движения и местных событий, пересекающихся с поездкой. Класс дороги не заменяет измерение загруженности; частичный календарь не доказывает отсутствие праздников. Расчёт показывает риск, а не децибелы в номере. Подготовка: `npm run noise:assess`. Формат источников и ограничения: [NOISE.md](docs/NOISE.md).

В поставку также входят реальные **исторические будничные подсчёты KTDB за 2024 год**, полученные без ключа: 10 из 86 дорожных участков имеют данные, всего 184 часовых значения. В текущем каталоге 72 объекта находятся в пределах 300 м от этих линий; это пространственное покрытие историей, а не подтверждение тишины. Это не текущая загруженность и не прогноз. На поездках с будними днями такой фон может менять порядок вариантов при желательном условии тишины. Исходное свидетельство сохраняет неизвестность по датам поездки, но итог фильтра получается по эвристике: низкий исторический риск проходит, умеренный и высокий — нет. Если истории нет, запасное правило принимает расстояние до ближайшей известной дороги больше 150 м. Эти предположения действуют и для обязательного условия; фактический шум они не подтверждают. [Источник, покрытие и ограничения](docs/TRAFFIC.md).

```powershell
npm run traffic:fetch
npm run traffic:fetch -- --refresh
```

Первая команда использует сохранённый проверенный кеш; вторая запрашивает официальный публичный слой заново. Для обычного запуска обновлять снимки не требуется.

Форматы импорта, кеш, offline-режим, происхождение данных и ограничения описаны в [AREA_ASSESSMENT.md](docs/AREA_ASSESSMENT.md).

## Геоданные

Подготовленный снимок Пусана включён в репозиторий, поэтому запуск не требует запросов к картографическим серверам.

```powershell
npm run data:fetch
npm run data:prepare
npm run area:assess
npm run noise:assess
npm run traffic:fetch
```

`npm run data:prepare` пересобирает географическую основу `data/demo.json`, затем рабочий `data/verified-hotels.json`. Для пересборки рабочего каталога из сохранённой географии и двух файлов исследования достаточно `npm run data:verify`; эта команда не обходит сайты и не продлевает даты проверки.

Скрипт загрузки ограничен районом Хэундэ и использует кеш с именем региона. Подготовка сохраняет пять типов размещения и строит маршруты до приближённого подхода к пляжу по связному пешеходному графу. Объект без допустимого маршрута остаётся в каталоге с `route: null` и без подтверждённого расстояния. Для применения изменений каталога перезапустите Java-сервер; отдельная SQLite-база нужна только для чистой демонстрации без истории ответов.

Входы в отели и подходы к пляжу не обследованы. Соединительные участки до сети не включены в длину маршрута. Отсутствие лестниц на карте не доказывает доступность для коляски. Окружение показывает возможные источники шума, а не акустические измерения. Названия и расположение объектов реальны, их действующая работа не проверена.

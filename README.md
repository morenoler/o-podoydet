# О!Подойдёт

**Некоммерческий исследовательский проект для хакатона.** Мы показываем, как подбирать жильё по условиям поездки, объяснять результат источниками и пересчитывать его после уточнения неизвестного условия.

Путешественнику бывает недостаточно общего описания «семейный отель рядом с морем». Важно, подходит ли **один конкретный вариант размещения**: хватит ли мест, куда выходят окна, есть ли ступени, как пройти до пляжа и какие сведения об окружении вообще доступны. «О!Подойдёт» сохраняет разницу между известным фактом, заявлением владельца, неизвестностью и противоречием.

Это прототип, а не сервис продажи поездок. В нём нет оплаты, подключения к реальному наличию номеров и подтверждения бронирования у гостиниц. Заявки в кабинетах демонстрируют внутренний сценарий приложения.

## Быстрый запуск одной командой

### Что нужно

Достаточно **работающего Docker с Compose v2 или новее**, Git либо распакованного архива репозитория и браузера. Для этого способа не нужны установленные на компьютере Java, Maven, Node.js, Python, Ollama или ключи модельных API.

На Windows используйте Linux containers в Docker Desktop; обычный вариант — backend WSL 2. Проверьте:

~~~sh
docker version
docker compose version
~~~

В `docker version` должна быть доступна часть **Server**. Только установленный CLI без запущенного Docker Engine не сможет поднять проект. Требования к Windows и WSL: [официальная инструкция Docker](https://docs.docker.com/desktop/setup/install/windows-install/).

### Получить код и запустить

Если копия проекта уже есть, откройте терминал в её корне, рядом с `docker-compose.yml`. Для новой копии:

~~~sh
git clone https://github.com/morenoler/o-podoydet.git
cd o-podoydet
~~~

Запуск основного сайта вместе с демонстрацией диалога:

~~~sh
docker compose --profile jury up --build --wait
~~~

Первая сборка скачивает базовые образы, npm/Maven-зависимости и системные пакеты. Её продолжительность зависит от сети и кеша. Команда ждёт готовности сервисов, а не только создания контейнеров.

| Адрес | Назначение |
| --- | --- |
| [http://127.0.0.1:8080](http://127.0.0.1:8080) | Основной сайт: реальный исследовательский каталог Хэундэ, поиск и кабинеты. |
| [http://127.0.0.1:8081/jury-demo.html](http://127.0.0.1:8081/jury-demo.html) | Отдельная страница трёх шагов с вымышленным отельером. Регистрация не нужна. |
| [http://127.0.0.1:8080/api/health](http://127.0.0.1:8080/api/health) | Состояние основного API, количество объектов, режим и регион. |
| [http://127.0.0.1:8080/v3/api-docs](http://127.0.0.1:8080/v3/api-docs) | OpenAPI в JSON. Старые динамические маршруты описаны в ней не полностью. |

Compose поднимает четыре сервиса: `db`, `window-view`, `app`, `host-demo`. Основное приложение использует схему PostgreSQL `public`, учебный диалог — отдельную `host_dialog_demo`. Python-сервис доступен Java по внутренней сети; его порт 8011 по умолчанию наружу не опубликован. PostgreSQL опубликован на `127.0.0.1:5432`; интерфейсы также доступны только локально.

Только основной сайт, без отдельного диалога:

~~~sh
docker compose up --build --wait
~~~

### Проверить готовность и остановить

~~~sh
docker compose --profile jury ps
docker compose logs --tail=100 app host-demo window-view db
docker compose --profile jury down
~~~

Обычный `down` сохраняет именованные тома базы и загруженных фотографий. Не добавляйте `-v`, если хотите сохранить данные и историю показа. Docker-образы тоже остаются для следующего запуска.

## Сценарий показа на 7–10 минут

| Время | Действие | Что важно показать |
| --- | --- | --- |
| 1 минута | Открыть основной сайт и задать поездку в Пусан | Подбор начинается с условий поездки и пожеланий. |
| 2 минуты | Выбрать пожелания, открыть результат и карточку | По каким условиям вариант подходит, чего не хватает, где источник и область действия. |
| 1–2 минуты | Посмотреть карту, маршрут и оценку вида | Рассчитанное по данным отделено от подтверждённого на месте. |
| 2 минуты | Перейти на отдельную страницу диалога и выполнить три шага | Неизвестное условие → синтетический ответ → новый результат поиска 0→1. |
| 1–2 минуты | Показать ответы API, ограничения и, при подготовке, кабинеты | Изменение результата объясняется сохранённым доказательством; происхождение не скрывается. |

Для самого короткого показа достаточно страницы `/jury-demo.html`. Для развёрнутого — сначала основной каталог, затем учебный диалог. Два режима открываются на разных портах именно для разделения реальных источников и синтетических сведений.

## Три шага диалога отельера

Откройте [демонстрацию на 8081](http://127.0.0.1:8081/jury-demo.html).

1. **«Найти номер во двор».** Запрос использует поездку на три ночи через неделю, двух взрослых и обязательные окна во двор. На новой демосхеме подходящих вариантов нет: свойство неизвестно у обеих вымышленных категорий.
2. **«Ответить за учебного отельера».** Планировщик создаёт вопросы, симулятор отвечает по сохранённому сценарию. Из текста извлекается утверждение об учебной категории, сохраняются цитата, время и метки `demo=true`, `simulated=true`.
3. **«Проверить результат».** Повторяется тот же поиск. Теперь подходит одна учебная категория. Раздел **«Посмотреть ответы API и происхождение сведений»** показывает реальные ответы сервера.

Это запросы к настоящему Spring API и записи в PostgreSQL. Интерфейс не подставляет заранее заготовленный результат поиска. При этом **сам отельер и его ответы вымышлены**, а извлечение в стандартном показе выполняется правилами без платной модели.

На повторном запуске уже сохранённые ответы дают **1→1**. Это нормальное сохранение состояния; страница сообщает о повторном показе. Приложение не стирает историю ради повторения эффекта.

Автоматическая проверка того же сценария из контейнера:

~~~sh
docker compose --profile jury --profile checks run --rm jury-check
~~~

На новой схеме ожидаются `before: 0`, `after: 1`; на повторной — `before: 1`, `after: 1`, `repeatRun: true`. Проверка сохраняет cookie между запросами и проверяет обе метки синтетического происхождения.

На основном сайте симулятор не отвечает за реальные гостиницы. Защита требует учебного режима, каталога с политикой `demo` и явно вымышленного объекта. Попытка симулировать ответ реального отеля возвращает HTTP 403.

### Свежая репетиция без удаления прежних данных

Используйте **новое имя Compose-проекта** и свободные порты. Каждое новое имя создаёт свои тома. Повтор того же имени снова откроет уже сохранённое состояние.

PowerShell:

~~~powershell
$env:APP_PORT = '8090'
$env:JURY_PORT = '8091'
$env:POSTGRES_PORT = '55433'
docker compose -p opodoydet-rehearsal-2 --profile jury up --build --wait
~~~

Bash:

~~~sh
APP_PORT=8090 JURY_PORT=8091 POSTGRES_PORT=55433 docker compose -p opodoydet-rehearsal-2 --profile jury up --build --wait
~~~

Основной сайт будет на 8090, учебный диалог — на 8091. Для проверки и остановки используйте то же имя:

~~~sh
docker compose -p opodoydet-rehearsal-2 --profile jury --profile checks run --rm jury-check
docker compose -p opodoydet-rehearsal-2 --profile jury down
~~~

В PowerShell переменные сохраняются в текущем терминале. Когда они больше не нужны:

~~~powershell
Remove-Item Env:APP_PORT, Env:JURY_PORT, Env:POSTGRES_PORT -ErrorAction SilentlyContinue
~~~

## Основной сайт и объяснение подбора

1. Задайте регион, будущие даты поездки и количество гостей.
2. Выберите сценарии отдыха и уточните отдельные пожелания. Обязательное условие влияет на допуск варианта; необязательное — на объяснение и предпочтительность.
3. Откройте результаты. Смотрите не только итоговый порядок, но и статусы отдельных условий, причины исключения и недостающие сведения.
4. В карточке проверьте категорию, вместимость, область действия доказательств, маршрут и окружение. Несколько видов из описания категории не означают, что они одновременно есть в каждом номере.
5. Если включён помощник, откройте объяснение результата. Предложение изменить пожелание требует решения пользователя и не превращает исходно неподходящий вариант в подходящий.

Число результатов зависит от дат, гостей, пожеланий и срока актуальности источников. Пустая строгая выдача — допустимый результат, если подтверждений недостаточно.

### Как читать статусы

| Состояние | Значение |
| --- | --- |
| Подтверждение в рамках источника | Сохранённое свидетельство поддерживает условие в указанной области действия и сроке. Это не автоматически независимая проверка помещения. |
| Заявлено владельцем / `reported` | Условие сообщил владелец объявления; происхождение заявления сохраняется. |
| Неизвестно / `unknown` | Сведений нет, они неприменимы, устарели либо недостаточны. Это не «нет» и не «да». |
| Известное несоответствие | Есть применимое свидетельство, что условие не выполняется. |
| Конфликт / `conflict` | Применимые версии противоречат друг другу; их нельзя скрыть выбором более удобной. |

**`verified`** требует подтверждений обязательных условий. **`explore`** допускает неизвестность только как явно предварительный вариант; известное несоответствие и конфликт не обходятся. Политика каталога **`verified-only`** означает исключение демонстрационных фактов из реального набора, а не обследование всех объектов на месте.

Свойства проверяются совместно внутри одной категории либо одного варианта объявления. Нельзя взять вместимость из одной комнаты и окна во двор из другой и объявить их одним подходящим номером.

## Что реально покрыто данными

Стандартный Docker-показ сосредоточен на **районе Хэундэ в Пусане**. Более широкие каталоги доступны в репозитории и при обычном локальном запуске без явного `DATA_PATH`.

| Набор | Записи объектов | Объекты с официальными категориями | Категории | Рассчитанные маршруты |
| --- | ---: | ---: | ---: | ---: |
| Подробный Хэундэ | 96 | 6/96 | 46 | 95/96 |
| Расширенный Пусан | 876 | 6/876 | 46 | 95/876 |
| Сохранённый участок Сочи | 61 | 0/61 | 0 | 0/61 |

Хэундэ входит в расширенный Пусан: строки таблицы нельзя складывать. Число объектов — число записей набора, а не независимо проверенных действующих предприятий. Технические заглушки и пустые массивы комнат не считаются собранными категориями.

Из 46 категорий вместимость известна для **41**, для **5** неизвестна. Семейное размещение опубликовано для **25/46**, остальные **21** значения неизвестны. Для всех **46** категорий окна во двор и полный путь без ступеней остаются неизвестными. Поэтому обязательное пожелание «номер во двор» не должно давать подтверждённый реальный результат только на этих сведениях.

Официальные описания категорий получены 24–25 октября 2026 года. Дата загрузки не подставляется вместо неизвестной даты публикации и не считается датой проверки на месте. Проверок на месте выполнено **0**.

### Что нельзя заключать из этих данных

- Точка отеля или центр здания не являются проверенным входом. Первые и последние метры маршрута могут быть неизвестны.
- Конечная точка возле пляжа не подтверждает проход по гальке к воде с коляской.
- Наличие лифта или отсутствие тега лестницы не доказывает весь путь без ступеней.
- Окна во двор не гарантируют тишину. Шум оценивается по признакам окружения, без придуманных децибел.
- Статистика района не является гарантией безопасности конкретной улицы или человека.
- Сохранённый прогноз воздуха применим только к своим датам; неизвестные будущие даты не получают хорошую оценку автоматически.
- Геометрическая оценка вида не является фотографией, обещанием вида на море или подтверждением из конкретного физического номера.
- Описания категорий не сообщают реальное наличие и цену на выбранные даты.

## Карта, маршруты и вид из окна

Основной интерфейс показывает расположение, маршрут и доступные сведения об окружении. Расстояния и геометрические оценки вычисляются кодом по сохранённым входным данным. Версии расчётов и исходные идентификаторы сохраняются.

Отдельный Python-сервис `window-view` оценивает направления, препятствия и сценарии этажей. Неизвестные этаж, ориентация окна, высота препятствия и рельеф ограничивают результат. Для текущих реальных данных `actual_visibility_confirmed=false`; наличие оценки не превращает его в `true`.

Java обращается к этому сервису по `WINDOW_VIEW_URL`. В Docker это внутренний адрес `http://window-view:8011`. В локальной разработке сервис запускается отдельно. Подробнее: [README сервиса](services/window-view/README.md).

Картографические подложки в браузере требуют сети. Доступность спутниковых тайлов зависит от провайдера, домена и его правил; отсутствие тайла не добавляет и не удаляет факты в базе. Снимок подложки не является источником новых характеристик комнаты. Условия подробной спутниковой подложки описаны в [отчёте о карте](docs/SATELLITE_DETAIL_QUALITY.md).

## Архитектура и роль ИИ

~~~mermaid
flowchart LR
    UI["Браузер: React / TypeScript"] --> API["Spring Boot / Java 21"]
    API --> DB[("PostgreSQL 16 / Flyway")]
    DATA["Сохранённые каталоги и источники"] --> API
    API --> VIEW["Python window-view"]
    API --> ADVISOR["Python-помощник"]
    API -. "при явном включении" .-> MODEL["Локальная модель или внешний API"]
    ADVISOR -. "при явном включении" .-> MODEL
    DEMO["Отдельная учебная страница"] --> DEMOAPI["Учебный экземпляр Spring"]

~~~

| Слой | Технологии и ответственность |
| --- | --- |
| Интерфейс | React, TypeScript, Vite, React Router, Leaflet; формы, результаты, карты и кабинеты. |
| Основной API | Java 21, Spring Boot 3.5.6, Spring MVC; проверка запроса, подбор, объяснения, доступ к кабинетам. |
| Хранение | PostgreSQL 16, Spring Data JPA/JdbcClient, транзакции и миграции Flyway. Compose использует образ PostGIS. |
| Доказательства | Субъект, характеристика, значение, источник, область действия, даты, статус и срок перепроверки. |
| Геометрия | Python 3.11+ и стандартная библиотека, отдельный сервис и сохранённые сцены. |
| Помощник | Python worker, ограниченная работа с итоговым снимком поиска, правила либо выбранный модельный провайдер. |

Поиск использует один снимок критериев до подсчёта баллов и допуска варианта. Его результат переиспользуется в деталях, кандидатах и помощнике. Источники с известным общим происхождением не считаются независимыми подтверждениями только потому, что у них разные идентификаторы.

### Показ без ключей

Compose явно задаёт `AI_PROVIDER=rules`. Поиск, демонстрационный диалог и геометрические оценки работают без обращения к модельным API. Модель не нужна для воспроизведения перехода 0→1.

Разбор правил имеет ограниченный словарь. Нераспознанное пожелание не должно превращаться в придуманное подтверждение. География, совместимость условий, проверки доказательств и запрет смешивать разные комнаты остаются задачами кода.

### Необязательное подключение модели

Для локальной разработки доступны `AI_PROVIDER=local`, `deepseek` и `rules`. Настройки берутся из серверного окружения; при npm-запуске `.env` загружается запускающим скриптом. Не помещайте ключи в README, Git или переменные `VITE_*`.

| Настройка | Назначение |
| --- | --- |
| `AI_PROVIDER` | Режим по умолчанию. `rules` отключает модели даже при наличии настроенных ключей. |
| `ADVISOR_LOCAL_MODEL`, `ADVISOR_LOCAL_BASE_URL` | Имя и адрес уже подготовленной локальной модели. |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` | Серверные настройки необязательного внешнего провайдера. |
| `ADVISOR_PYTHON` | Исполняемый Python для помощника. |

Local и DeepSeek используют `/chat/completions`. Совместимый режим старых `LLM_*` при пустом `AI_PROVIDER` сохраняет `/responses` для поиска и `/chat/completions` для разбора ответа отельера. Общий автоматический replay записанных LLM-ответов не реализован.

В основном интерфейсе есть выбор «Модель ИИ» для следующих запросов этого браузера, если сервер допускает провайдер. Он не меняет настройки других посетителей. Стандартный Compose-показ намеренно оставлен в режиме правил; изменение только локального файла `.env` не отменяет явно заданные значения Compose.

Подробности: [настройка провайдеров](docs/DEEPSEEK_MODULE.md), [образец окружения](.env.example). Работа реального платного API не проверялась в офлайн-прогонах проекта.

## Кабинеты путешественника и владельца

Основной сайт содержит регистрацию, вход, кабинет путешественника, кабинет владельца, опубликованные объявления и внутренние заявки. Реальные гостиницы исследовательского каталога **не привязаны** к пользователям, выдающим себя за их владельцев.

Личное уточнение владельцу объявления отличается от учебного симулятора:

1. Путешественник открывает объявление, задаёт поездку и выбирает «Подготовить личный вопрос».
2. Владелец в «Вопросы гостей → Уточнения для подбора» указывает «Да», «Нет» или «Пока не знаю», область действия и известную дату наблюдения.
3. Ответ сохраняется как заявление владельца с историей версий.
4. Путешественник нажимает «Пересчитать подбор» и получает новый снимок. Старый снимок не переписывается.

В публичную выдачу передаётся обезличенное условие. Личная переписка, дополнение путешественника и идентификатор диалога не должны становиться публичными доказательствами. Противоречащие ответы сохраняются; неизвестный ответ не восстанавливает прежнее положительное утверждение. Подробные правила: [CLARIFICATIONS.md](docs/CLARIFICATIONS.md).

## Локальная разработка без сборки приложения в Docker

Нужны **Node.js 24+, JDK 21, Maven 3.9+, Python 3.11+ и PostgreSQL 16**. Docker можно использовать только для PostgreSQL либо подключить свою базу.

~~~sh
npm ci
npm run dev
~~~

Spring API запускается на 8080, Vite — на 3000. Для собранного интерфейса:

~~~sh
npm run build:all
npm start
~~~

Скопируйте `.env.example` в `.env` только если у вас ещё нет своего файла. Существующие настройки базы и ключи не заменяйте примером. Для прямого `java -jar` переменные нужно передать процессу явно.

| Переменная | Назначение |
| --- | --- |
| `PORT`, `BIND_ADDRESS` | Порт и адрес Java API. |
| `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD` | Явное подключение PostgreSQL. |
| `DB_SCHEMA` | Схема экземпляра; основная, лабораторная и учебная должны быть разделены. |
| `DATA_PATH` | Явный каталог. В основном Compose это `data/verified-hotels.json`; при обычном локальном запуске пустое значение загружает Пусан и Сочи. |
| `UPLOADS_PATH` | Постоянные фотографии объявлений; резервируются вместе с БД. |
| `WINDOW_VIEW_URL` | Адрес отдельного сервиса вида из окна. |
| `BUILD_OUT_DIR` | Отдельная папка сборки интерфейса, полезная при работающей демоверсии. |

Python-сервис в отдельном терминале:

~~~sh
cd services/window-view
python -X utf8 -m window_view serve
~~~

На Windows `-X utf8` обеспечивает корректную работу русских строк. В Linux/macOS используйте свой исполняемый Python 3.11+, например `python3`.

Лаборатория `npm run lab:build` / `npm run lab:start` — ещё один режим, обычно на 8081. Не запускайте её одновременно с учебным диалогом на том же порту. SQLite оставлен только для явно включённого переноса старой базы через `LEGACY_DB_PATH` и сборку `-Plegacy-import`; обычный runtime не содержит SQLite JDBC.

## Проверки и воспроизводимость

После установки зависимостей, из корня:

~~~sh
npm test
npm run backend:test
npm run agents:test
npm run demo:test
npm run build:all
npm run lab:build
python -X utf8 -m unittest discover -s scripts/tests
~~~

Java- и интеграционные Python-проверки используют настоящий PostgreSQL: через Docker/Testcontainers либо `TEST_DATABASE_URL`, `TEST_DATABASE_USER`, `TEST_DATABASE_PASSWORD`. Они создают свои временные схемы. Отсутствие Docker не считается успешным тестом и не заменяется молчаливым пропуском.

Из `services/window-view`:

~~~sh
python -X utf8 -m unittest discover -s tests -v
python -X utf8 verify_busan.py --workers 4
~~~

Расширенный прогон выполняет **288 запросов для 96 объектов**: по три сценария на объект. Он проверяет согласованность расчётов, а не точность реального вида из окна.

### HTTP-контракт

~~~sh
npm run contract:verify
~~~

Эталон содержит 85 HTTP-сценариев и получен с отдельной неизменённой сборки исходного main `0fc7c56`. Профиль проверки фиксирует время по `contract/baseline.json`; обычный сервер использует реальное время. Крупные JSON сжаты без потери содержимого, манифесты проверяют контрольные суммы. Прежние 85 ответов сохранены отдельно. Метод сравнения и допустимые нормализации: [contract/README.md](contract/README.md).

`contract:verify` сам собирает сервер, создаёт отдельную схему и запускает его на **8089**. Этот порт должен быть свободен; проверка не подключается к случайно работающему на нём экземпляру. После сравнения свой сервер останавливается.

Результаты прогонов, обнаруженные ошибки и оставшиеся ограничения ведутся в [отчёте качества](docs/QUALITY_REVIEW_2026-10-29.md). Там отдельно указаны тесты логики, сверка сохранённых источников, контейнерные проверки и невыполненные обследования на месте. Успешные тесты не означают «100% достоверность данных».

## Что работает без сети

| Операция | Сеть |
| --- | --- |
| Первая сборка образов и установка зависимостей | Нужна для Docker registry, npm, Maven и системных пакетов. |
| Поиск по сохранённым данным и режим правил | Не требует внешних API после подготовки окружения. |
| Синтетический диалог для жюри | Не требует ключей или связи с отельерами. |
| Геометрические расчёты на сохранённых сценах | Не требуют сетевого сбора. |
| Картографические тайлы браузера | Требуют доступа к провайдеру подложки. |
| Локальная модель | Модель должна быть заранее загружена и запущена. |
| Внешняя модель, новый сбор открытых источников | Нужны сеть и соответствующие настройки; запускаются явно. |

Ни обычная сборка приложения, ни показ не обновляют незаметно исходные снимки данных. Сетевой сбор — отдельные команды, с источниками, временем получения, ограничениями и кешем.

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `Cannot connect to the Docker daemon` | Запущен ли Docker Desktop/Engine; есть ли секция Server в `docker version`; выбран ли режим Linux containers. |
| Порт уже занят | Не останавливайте чужой экземпляр. Задайте свободные `APP_PORT`, `JURY_PORT`, `POSTGRES_PORT` и отдельное имя `-p`. |
| Ошибка скачивания POM, npm-пакета или образа | Проверьте сеть, DNS и доступ к указанному registry. После восстановления повторите команду: успешные слои кешируются. Ошибка загрузки не доказывает ошибку исходного кода. |
| Сервис unhealthy | Посмотрите `docker compose --profile jury ps` и журнал конкретного сервиса. `config --quiet` проверяет только YAML, не работоспособность приложения. |
| Страница диалога на 8081 не открывается | Нужен профиль `jury`; проверьте, не изменён ли `JURY_PORT` и не занят ли порт лабораторией. |
| Первый шаг сразу показывает один вариант | В этой схеме уже сохранены учебные ответы. Это повторный показ 1→1; для 0→1 используйте новое имя проекта. |
| Строгий поиск ничего не нашёл | Проверьте обязательность условий, даты, вместимость и доступные подтверждения. Неизвестность не следует исправлять подстановкой `true`. |
| Карта пуста, но API отвечает | Проверьте внешние тайлы, сеть и ограничения провайдера. Расчёты и наличие подложки — разные проверки. |
| Модель недоступна | Стандартный Compose отключает её через `rules`. Для необязательного модельного режима проверьте серверные настройки и доступность провайдера. |
| `demo:setup` сообщает, что файл существует | Он защищает уже подготовленный seed. Повторно запускайте `demo:start` либо создайте новый файл и отдельную схему по [DEMO.md](docs/DEMO.md). |

Перед показом желательно один раз собрать проект и пройти сценарий. Для восстановления запуска не нужен сброс Docker к заводским настройкам или удаление рабочих томов.

# О!Подойдёт

## Работа с проектом

- Основное приложение — React/TypeScript + Java 21 и SQLite 3. Сохранять его существующий стек.
- `services/window-view/` — отдельный Python 3.11+ сервис; стандартная библиотека,
  запуск и проверки без обязательных внешних зависимостей.
- Пользователь разрешил субагентов. Разделять владение файлами; интеграцию проверяет основной агент.
- Проверять каждый значительный этап; исправлять найденные ошибки до зависимых изменений.
- Перед сдачей запускать существующие тесты/сборку и расширенную проверку нового сервиса.

## Достоверность

- Расчёт видимости — геометрическая оценка по ограниченным данным, не фотография и не подтверждение на месте.
- Неизвестные окно, этаж, направление, высота препятствия и рельеф не превращать в подтверждённый вид.
- Категория номера и оценка отеля не подтверждают вид из конкретного физического номера.
- Хранить источник, дату получения, известную дату исходных данных, метод и допущения.
- Реальные открытые данные и синтетические тестовые сцены разделять. Не выдумывать номера реальных гостиниц.
- Кэшировать открытые источники; сохранять запрос, SHA-256 и атрибуцию. Обычные тесты работают без сети.
- Запросы к публичным источникам ограничивать по времени, объёму и частоте. Не обходить ограничения доступа.
- Не отправлять сообщения отельерам, не публиковать ключи и персональные переписки.

## Проверки

- Приложение: `npm test`, `npm run backend:test`, `npm run agents:test`, `npm run build:all`, `npm run lab:build`.
- Микросервис: из `services/window-view` — `python -m unittest discover -s tests -v`.
- Расширенная проверка: из `services/window-view` — `python verify_busan.py --workers 4`; 288 запросов по 96 объектам.
- Парсер шумового отчёта: `python -m unittest discover -s scripts/tests`.
- Качество алгоритма, полнота источников и проверка на месте — разные показатели.

## Интеграция

- Java разделён на application, domain, persistence, shared, web, advisor. Клиент вида находится в application.
- Основной сайт использует verified-only; синтетическая лаборатория работает отдельно на 8081 со своей SQLite.
- Неизвестность не даёт положительного допуска. API сохраняет evidenceStatus; UI отделяет неизвестность от установленного несоответствия.
- Публиковать целый проект в отдельную ветку. Пользователь запретил прямой push в main.
